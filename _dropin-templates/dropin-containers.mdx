## Slots

The `ContainerName` container supports customization slots for adding or modifying content within specific sections. Each slot receives a context object (`ctx`) that provides:

- **`ctx.data`**: Current component data and state
- **`ctx.appendChild(element)`**: Method to add elements to the slot
- **`ctx.replaceWith(element)`**: Method to replace slot content
- **`ctx.onChange(callback)`**: Method to listen for data changes

### Available slots

| Slot | Purpose | Required |
|------|---------|----------|
| Header | Custom header content | No |
| Footer | Custom footer content | No |
| SlotName | Custom slot functionality | No |

### Basic slot usage

```javascript
slots: {
  Header: (ctx) => {
    const header = document.createElement('div');
    header.innerHTML = `
      <h2>Container Header</h2>
      <p>Custom content</p>
    `;
    ctx.appendChild(header);
  },
  
  Footer: (ctx) => {
    const footer = document.createElement('div');
    footer.className = 'custom-footer';
    footer.textContent = 'Custom footer content';
    ctx.appendChild(footer);
  }
}
```

### Dynamic content updates

Slots can respond to data changes using the `ctx.onChange` method:

```javascript
slots: {
  Header: (ctx) => {
    const header = document.createElement('div');
    header.innerHTML = `<h2>Items: ${ctx.data?.items?.length || 0}</h2>`;
    ctx.appendChild(header);
    
    // Update when data changes
    ctx.onChange((next) => {
      header.innerHTML = `<h2>Items: ${next.data?.items?.length || 0}</h2>`;
    });
  }
}
```

## Features

### Automatic loading states

- **Skeleton Loading**: Configurable skeleton items while fetching data
- **Loading Indicators**: Automatic loading state management
- **Error Handling**: Graceful error display with user-friendly messages
- **Empty States**: Appropriate messaging when no data is available

### Real-time updates

The container automatically updates when events are received:

1. **Data Start**: Shows loading state
2. **Data Received**: Updates with new data
3. **Data Complete**: Removes loading state
4. **Error Handling**: Displays error state if applicable

## Best practices

1. **Scope management**: Use unique scope identifiers for multiple instances
2. **Slot customization**: Use slots for merchant-specific customization
3. **Element Creation**: Always create DOM elements and append them using `ctx.appendChild()`
4. **CSS classes**: Use BEM naming convention for custom slot styles
5. **Design tokens**: Use design tokens in CSS overrides for maintainability
6. **Performance**: Use lazy loading for off-screen containers
7. **Error handling**: Let the container handle errors automatically
8. **Real-time updates**: Let the container handle updates automatically

## Troubleshooting

### Common issues

1. **Container not updating**: Check scope configuration and event handling
2. **Slots not rendering**: Ensure the element is added to the slot using `ctx.appendChild()`, `ctx.replaceWith()`, etc.
3. **Styling not applied**: Check CSS class names and specificity
4. **Event handlers not working**: Verify event listeners are added to the correct elements
5. **Dynamic updates failing**: Make sure you're using `ctx.onChange()` for data-dependent content
6. **Styling conflicts**: Use specific CSS classes to avoid conflicts

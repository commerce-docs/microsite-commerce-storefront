Use this tool to check your `config.json` against common Adobe Commerce Optimizer (ACO) and Adobe Commerce as a Cloud Service (ACCS) misconfiguration patterns before deploying. See the [Storefront Configuration](/setup/configuration/commerce-configuration/) page for the full field and header reference this tool validates against.

Paste your `config.json` below and select **Validate**. Nothing is sent anywhere — validation runs entirely in your browser.

## What this checks

- **Unresolved placeholders** — Any `{{PLACEHOLDER}}` value left in the file. Requests are sent with the literal placeholder string instead of a real header or URL value, so the backend rejects or silently misroutes them.
- **Missing analytics fields** — Required `analytics` fields for your backend type (for example `locale`, `store-view-currency-code`, and `view-id` for ACO). Product Recommendations and Live Search need these to resolve locale, currency, and catalog view correctly; when they're missing, the pipeline silently falls back to defaults.
- **Mixed header families** — Both `Magento-*` and `AC-*` headers present in the same `cs` section, usually left over from a PaaS/ACCS-to-ACO migration. Mixing header families is a common source of inconsistent behavior between endpoints.
- **Header casing** — Header names that don't match the expected casing (for example `Magento-store-code` instead of `Magento-Store-Code`). Header matching for store and website context is case-sensitive on the backend, so a casing mismatch causes broken faceting or caching even though the header "looks" correct.

The AEM Assets integration allows your storefront to display product images that are managed in AEM Assets instead of traditional Commerce-hosted images. This integration provides enhanced image management capabilities, including advanced optimization, cropping, and delivery through Adobe's Content Delivery Network (CDN).

## How it works in the boilerplate

The Commerce drop-ins automatically detect the `commerce-assets-enabled` configuration and adjust image handling accordingly. Here's how you can access this configuration in your custom code:

<Tasks>

<Task>

### Import the AEM Assets utility

Import the `tryRenderAemAssetsImage` helper from the drop-ins tools package.

```javascript showLineNumbers=false 
import { tryRenderAemAssetsImage } from '@dropins/tools/lib/aem/assets.js';
```

</Task>

<Task>

### Render images via drop-in slots

Use the `tryRenderAemAssetsImage` function inside your drop-in image slots as shown in the example below.

```javascript showLineNumbers=false {"Container:":4-5} {"Container Image Slot:":6-8} {"AEM Assets integration:":10-17}
import { tryRenderAemAssetsImage } from '@dropins/tools/lib/aem/assets.js';

export default async function decorate(block) {
  
  await dropinRenderer.render(DropinComponent, {

    slots: {
      DropinImageSlot: (ctx) => {
        const { data, defaultImageProps } = ctx;

        tryRenderAemAssetsImage(ctx, {
          imageProps: defaultImageProps,
          params: {
            width: defaultImageProps.width,
            height: defaultImageProps.height,
          },
        });
      },
    },
  })(block);
}
```

</Task>

<Task>

### Real-world examples from the boilerplate

Based on the actual boilerplate implementation, AEM Assets integration uses the `tryRenderAemAssetsImage` function from `@dropins/tools/lib/aem/assets.js`. Here are real examples:

#### Product List SearchResults container

```javascript showLineNumbers=false {"Container:":2-3} {"Container Image Slot:":4-6} {"AEM Assets integration:":11-20}
import { tryRenderAemAssetsImage } from '@dropins/tools/lib/aem/assets.js';

provider.render(SearchResults, {

  slots: {
    ProductImage: (ctx) => {
      const { product, defaultImageProps } = ctx;
      const anchorWrapper = document.createElement('a');
      anchorWrapper.href = rootLink(`/products/${product.urlKey}/${product.sku}`);


      tryRenderAemAssetsImage(ctx, {
        alias: product.sku,
        imageProps: defaultImageProps,
        wrapper: anchorWrapper,
        params: {
          width: defaultImageProps.width,
          height: defaultImageProps.height,
        },
      });
    },
  },
});
```

### Key considerations

- **Recommended setup:** Set `commerce-assets-enabled: true` when using AEM Assets integration to ensure proper image handling.

- **Backward compatibility:** The integration is designed to work with mixed image sources, so Commerce-hosted images will continue to work even when AEM Assets is enabled.

- **Drop-ins vs. custom code:** The automatic image handling described above applies to Commerce drop-ins. If you're using custom image handling code, you'll need to implement the AEM Assets compatibility yourself.

## Using drop-ins outside the boilerplate (optional)

If you use the boilerplate, AEM Assets works out of the box. Without the boilerplate, implement the minimal config and slot usage below.

<Aside type="caution" title="Important limitation">
If you're using Commerce drop-ins as standalone NPM packages without the boilerplate, the `commerce-assets-enabled` configuration system described in this document may not be available to you. The boilerplate provides the configuration infrastructure (`config.json`, `getConfigValue` function, etc.) that drop-ins rely on to detect AEM Assets settings.
</Aside>

To enable AEM Assets with standalone drop-ins, you'll need to implement the configuration system that drop-ins expect:

### Minimal configuration

Set `commerce-assets-enabled: true` in a `public.default` config (JSON or config service). Align endpoints/headers to your environment as needed.

### Minimal integration steps

1. Install `@dropins/tools`.
2. Import `tryRenderAemAssetsImage`.
3. In each image slot, call `tryRenderAemAssetsImage(ctx, { alias: <sku>, imageProps, params: { width, height } })`.

Result: uses AEM Assets when available; falls back to Commerce; applies correct CDN params automatically.

### Reference implementation

See the [Commerce Boilerplate](https://github.com/hlxsites/aem-boilerplate-commerce) for complete examples.

## Troubleshooting

### Images not displaying

If product images are not displaying correctly:

1. **Check your configuration:** Ensure `commerce-assets-enabled` is set to `true` if you're using AEM Assets.
2. **Verify image URLs:** AEM Assets images typically include specific URL patterns that indicate they're served from AEM.
3. **Check browser console:** Look for 400 errors that might indicate incompatible optimization parameters.
4. **Test with mixed sources:** Try with both AEM Assets and Commerce-hosted images to isolate the issue.

### Configuration not taking effect

1. **Clear cache:** Ensure your configuration changes are not cached.
2. **Check config location:** Verify your `config.json` is in the root directory of your project (same level as `package.json`) and properly formatted. Alternatively, you can use the [config service](https://www.aem.live/docs/config-service-setup) where your config lives at `https://admin.hlx.page/config/{{ORG}}/sites/{{SITE}}/public.json`.
3. **Validate JSON:** Use a JSON validator to ensure your configuration file is valid.

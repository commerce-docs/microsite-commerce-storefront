In this section, you'll learn how Commerce blocks in your storefront connect to an AEM Assets integration using values from either your site's [public config](https://www.aem.live/docs/admin.html#schema/PublicConfig) or a [config.json](https://github.com/hlxsites/aem-boilerplate-commerce/blob/main/demo-config.json) file in your code repo.

The AEM Assets integration allows your storefront to display product images that are managed in AEM Assets instead of traditional Commerce-hosted images. This integration provides enhanced image management capabilities, including advanced optimization, cropping, and delivery through Adobe's Content Delivery Network (CDN).

## Overview

To enable AEM Assets integration in your storefront, you need to add the `commerce-assets-enabled` property to your configuration. This tells the Commerce drop-ins to handle images from AEM Assets appropriately, applying the correct optimization parameters and CDN paths.

## How it works in the boilerplate

The Commerce drop-ins automatically detect the `commerce-assets-enabled` configuration and adjust image handling accordingly. Here's how you can access this configuration in your custom code:

<Tasks>

<Task>

### Import the AEM Assets utility

Import the `tryRenderAemAssetsImage` helper from the drop-ins tools package.

```javascript showLineNumbers=false 
import { tryRenderAemAssetsImage } from '@dropins/tools/lib/aem/assets.js';
```

</Task>

<Task>

### Render images via drop-in slots

Use the`tryRenderAemAssetsImage` function inside your drop-in image slots as shown in the example below.

```javascript showLineNumbers=false {"Container:":4-5} {"Container Image Slot:":6-8} {"AEM Assets integration:":10-17}
import { tryRenderAemAssetsImage } from '@dropins/tools/lib/aem/assets.js';

export default async function decorate(block) {
  
  await dropinRenderer.render(DropinComponent, {

    slots: {
      DropinImageSlot: (ctx) => {
        const { data, defaultImageProps } = ctx;

        tryRenderAemAssetsImage(ctx, {
          imageProps: defaultImageProps,
          params: {
            width: defaultImageProps.width,
            height: defaultImageProps.height,
          },
        });
      },
    },
  })(block);
}
```

</Task>

### Key considerations

- **Recommended setup:** Set `commerce-assets-enabled: true` when using AEM Assets integration to ensure proper image handling.

- **Backward compatibility:** The integration is designed to work with mixed image sources, so Commerce-hosted images will continue to work even when AEM Assets is enabled.

- **Drop-ins vs. custom code:** The automatic image handling described above applies to Commerce drop-ins. If you're using custom image handling code, you'll need to implement the AEM Assets compatibility yourself.

## Implementation details

If you [set up your storefront](/get-started/create-storefront/) using the boilerplate code, AEM Assets is supported out-of-the-box through the Commerce drop-ins.

If you set up your storefront without the boilerplate code, you can still enable AEM Assets compatibility, but you'll need to implement the configuration system that drop-ins expect.

### Configuring drop-ins outside the boilerplate

<Aside type="caution" title="Important limitation">
If you're using Commerce drop-ins as standalone NPM packages without the boilerplate, the `commerce-assets-enabled` configuration system described in this document may not be available to you. The boilerplate provides the configuration infrastructure (`config.json`, `getConfigValue` function, etc.) that drop-ins rely on to detect AEM Assets settings.
</Aside>

To enable AEM Assets with standalone drop-ins, you'll need to implement the configuration system that drop-ins expect:

#### Configuration requirements

Your configuration should follow the structure from [`demo-config.json`](https://github.com/hlxsites/aem-boilerplate-commerce/blob/main/demo-config.json):
```json
{

    "default": {
      "commerce-assets-enabled": true,
      "commerce-core-endpoint": "https://your-commerce-endpoint.com/graphql",
      "commerce-endpoint": "https://your-commerce-services-endpoint.com/graphql",
      "headers": {
        "all": {
          "Store": "your-store-view-code"
        },
        "cs": {
          "Magento-Customer-Group": "b6589fc6ab0dc82cf12099d1c2d40ab994e8410c",
          "Magento-Store-Code": "your-store-code",
          "Magento-Store-View-Code": "your-storeview-code",
          "Magento-Website-Code": "your-website-code",
          "x-api-key": "your-api-key",
          "Magento-Environment-Id": "your-environment-id"
        }
      }
    }
  }
}
```

#### Integration Requirements

1. **Install the @dropins/tools package** - This provides the `tryRenderAemAssetsImage` function
2. **Import the AEM Assets utility** - `import { tryRenderAemAssetsImage } from '@dropins/tools/lib/aem/assets.js'`
3. **Use in image slots** - Call `tryRenderAemAssetsImage` in your drop-in image slots with proper configuration
4. **Provide SKU alias** - AEM Assets uses the product SKU as an alias to match images
5. **Configure image parameters** - Set width, height, and other image optimization parameters

#### Technical Implementation Details

The `tryRenderAemAssetsImage` function is used in the [boilerplate](https://github.com/hlxsites/aem-boilerplate-commerce/blob/main/scripts/__dropins__/tools/types/elsie/src/lib/aem/assets.d.ts)and handles:

- **Automatic fallback** - If AEM Assets images are not available, it falls back to Commerce-hosted images
- **Image optimization** - Applies the correct parameters for AEM Assets CDN delivery
- **SKU-based matching** - Uses the product SKU to locate the corresponding asset in AEM
- **Dynamic rendering** - Creates optimized image elements with proper attributes
- **Configuration detection** - Automatically detects if AEM Assets integration is enabled

## AEM Assets integration patterns in the boilerplate

To help developers understand exactly where and how AEM Assets are configured in the boilerplate, here's a breakdown of the key integration points:

### Configuration Flow Diagram

```
┌─────────────────────────────────────────────────────────────────┐
│                    AEM Assets Integration Flow                  │
└─────────────────────────────────────────────────────────────────┘

1. Configuration Source
   ├── demo-config.json (or config.json)
   │   └── { "commerce-assets-enabled": true }
   │
2. StorefrontSDK Integration
   ├── @dropins/tools/lib/aem/assets.js
   │   └── tryRenderAemAssetsImage() function
   │
3. Commerce Blocks (blocks/commerce-*)
   ├── blocks/product-details/
   │   └── Uses tryRenderAemAssetsImage() in gallery slots
   ├── blocks/product-list-page/
   │   └── Uses tryRenderAemAssetsImage() in ProductImage slot
   ├── blocks/commerce-wishlist/
   │   └── Uses tryRenderAemAssetsImage() in image slot
   └── blocks/commerce-cart/
       └── Uses tryRenderAemAssetsImage() for cart item images
   │
4. Drop-in Image Slots
   └── Image slots call tryRenderAemAssetsImage() with:
       ├── SKU alias for asset matching
       ├── Image dimensions and optimization params
       └── Automatic fallback to Commerce images
```

### Key Integration Points

Based on the [boilerplate structure](https://github.com/hlxsites/aem-boilerplate-commerce), AEM Assets integration happens at these specific locations:

#### 1. Configuration Layer
- **File**: [`demo-config.json`](https://github.com/hlxsites/aem-boilerplate-commerce/blob/main/demo-config.json)
- **Purpose**: Central configuration including `commerce-assets-enabled`
- **Pattern**: Nested JSON structure under `public.default`

#### 2. Configuration Access Layer  
- **Directory**: [`scripts/`](https://github.com/hlxsites/aem-boilerplate-commerce/tree/main/scripts)
- **Purpose**: Provides `getConfigValue()` function for blocks to access config
- **Pattern**: Async function supporting dot-notation keys

#### 3. Commerce Block Layer
- **Directory**: [`blocks/`](https://github.com/hlxsites/aem-boilerplate-commerce/tree/main/blocks) (commerce-* folders)
- **Purpose**: Each Commerce block checks `commerce-assets-enabled` and handles images accordingly
- **Pattern**: Import `getConfigValue`, check config, apply appropriate image handling

#### 4. Drop-in Integration Layer
- **Location**: Within Commerce blocks
- **Purpose**: Drop-ins receive configuration through the blocks that initialize them
- **Pattern**: Configuration passed to drop-ins during initialization

### Actual Implementation Pattern

Based on the boilerplate implementation, Commerce blocks use this pattern for AEM Assets integration:

```javascript
// 1. Import AEM Assets utility
import { tryRenderAemAssetsImage } from '@dropins/tools/lib/aem/assets.js';

// 2. Use in drop-in image slots

  // Initialize drop-in with AEM Assets-aware image slots
  dropinRenderer.render(DropinComponent, {
    slots: {
      ImageSlot: (ctx) => {
        const { product, defaultImageProps } = ctx;
        
        // 3. Render with AEM Assets support
        tryRenderAemAssetsImage(ctx, {
          alias: product.sku,
          imageProps: defaultImageProps,
          params: {
            width: defaultImageProps.width,
            height: defaultImageProps.height,
          },
        });
      },
    },
  })(block);
}
```

## Troubleshooting

### Images not displaying

If product images are not displaying correctly:

1. **Check your configuration:** Ensure `commerce-assets-enabled` is set to `true` if you're using AEM Assets.
2. **Verify image URLs:** AEM Assets images typically include specific URL patterns that indicate they're served from AEM.
3. **Check browser console:** Look for 400 errors that might indicate incompatible optimization parameters.
4. **Test with mixed sources:** Try with both AEM Assets and Commerce-hosted images to isolate the issue.

### Configuration not taking effect

1. **Clear cache:** Ensure your configuration changes are not cached.
2. **Check config location:** Verify your `config.json` is in the root directory of your project (same level as `package.json`) and properly formatted. Alternatively, you can use the [config service](https://www.aem.live/docs/config-service-setup) where your config lives at `https://admin.hlx.page/config/{{ORG}}/sites/{{SITE}}/public.json`.
3. **Validate JSON:** Use a JSON validator to ensure your configuration file is valid.

In this section, you'll learn how Commerce blocks in your storefront connect to an AEM Assets integration using values from either your site's [public config](https://www.aem.live/docs/admin.html#schema/PublicConfig) or a [config.json](https://github.com/hlxsites/aem-boilerplate-commerce/blob/main/demo-config.json) file in your code repo.

You'll need to add the property `commerce-assets-enabled` to your `config.json` file to enable compatibility with the AEM Assets integration.

```json title="config.json" showLineNumbers ins={'+':4}
{
  "public": {
    "default": {
      "commerce-assets-enabled": true,
      "commerce-core-endpoint": "https://www.aemshop.net/graphql",
      "commerce-endpoint": "https://www.aemshop.net/cs-graphql",
    }
  }
}
```

<Callouts>

1. **commerce-assets-enabled:** (read/write) Enables the use of AEM Assets integration in your storefront. See [AEM Assets Integration](https://experienceleague.adobe.com/en/docs/commerce/aem-assets-integration/overview) documentation for details.

</Callouts>

If you [set up your storefront](/get-started/) using the boilerplate code, AEM Assets is supported out-of-the-box. 

If you set up your storefront without the boilerplate code, you can still enable compatibility with the AEM Assets integration by configuring each image slot individually.

## Expected behaviors

Find below what is expected to happen in each different configuration combination:

Commerce	
true
check mark button  Only hosted images will be returned from the APIs, but config is indicating that images will come from AEM Assets, the code should not fail as the integration code should passthrough. This only applies for drop-in slots, not widgets compatibility workarounds.
Commerce	
false
check mark button Hosted images will be returned from the APIs, and config is indicating that AEM Assets is not enabled, images should display correctly.
AEM Assets	
true
check mark button AEM Assets images will be returned from the APIs, and config is indicating that AEM Assets is enabled, images should display correctly.
AEM Assets	
false
warning  AEM Assets images will be returned from the APIs, but config is indicating that images will not come from the AEM Assets CDN. Images will not display correctly, and they will appear as broken if the applied optimization parameters conflict with the AEM Assets expected ones (it will return a 400). If they don't conflict, images should display correctly.

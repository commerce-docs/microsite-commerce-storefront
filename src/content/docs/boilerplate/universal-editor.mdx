The Commerce boilerplate ships with Universal Editor instrumentation already in place for all standard blocks. This page covers what developers need to do to activate it and how to instrument custom blocks you add to your project.

## Enable Universal Editor for your DA.live site

<Aside type="note">
Universal Editor on DA.live is part of Adobe's Early Access Technology program and requires AEM Sites credits on your IMS Org. Only Chrome and Safari browsers are supported.
</Aside>

Enabling Universal Editor requires a one-time config entry in your DA organization settings.

<Steps>

1. Open your DA org config at `https://da.live/config#/{your-org}/` (the org name is visible in the breadcrumb while browsing your site in DA.live).

2. Add the following key-value row to the config table:

   | Key | Value |
   |-----|-------|
   | `editor.path` | `/your-org/your-site/path=https://experience.adobe.com/#/@{dx-handle}/aem/editor/canvas/main--{site}--{org}.ue.da.live` |

   Replace the placeholders:
   - `{your-org}` — your DA org name
   - `{dx-handle}` — your Adobe DX Handle (found in the URL on `experience.adobe.com`, e.g. `@mycompany`)
   - `{site}` and `{org}` — your AEM Edge Delivery site and org names (matching the subdomain pattern `main--{site}--{org}.aem.live`)

3. Save the config. Any page path that is a descendant of the config path will automatically open in Universal Editor. For pages in the same org, DA.live presents an **Open in-context editing** option in the toolbar.

</Steps>

## Built-in block instrumentation

All standard blocks in the Commerce boilerplate include the three JSON files that Universal Editor requires:

| File | Purpose |
|------|---------|
| `component-definition.json` | Registers blocks and their table structure |
| `component-models.json` | Defines the fields shown in the UE properties panel |
| `component-filters.json` | Controls which child components a container block accepts |

No additional setup is needed for these blocks — they are ready to edit in context out of the box.

## Instrument custom blocks

When you add a new block to your project, you need to create a corresponding JSON definition so Universal Editor can recognize and edit it.

The recommended approach (used in the [`da-block-collection`](https://github.com/aemsites/da-block-collection)) is to maintain per-block files in a `ue/models/blocks/` folder and then bundle them into the root-level JSON files.

<Steps>

1. Create `ue/models/blocks/your-block.json` with `definitions`, `models`, and `filters` objects. Use the [accordion.json](https://github.com/aemsites/da-block-collection/blob/main/ue/models/blocks/accordion.json) as a reference for a container block, or [hero.json](https://github.com/aemsites/da-block-collection/blob/main/ue/models/blocks/hero.json) for a simple block.

2. Add your block to the `filters` list in `ue/models/blocks/section.json` so it can be inserted into page sections from the UE toolbar.

3. Run the bundler to regenerate the three root-level JSON files:

   ```bash
   npm run build:json
   ```

4. Commit the updated JSON files. The pre-commit hook (if you copied it from `da-block-collection`) runs the bundler automatically.

</Steps>

<Aside type="tip">
Open a page in Universal Editor while developing. Blocks without instrumentation appear as **(no definition)** in the content tree — a quick visual signal that a definition file is needed.
</Aside>

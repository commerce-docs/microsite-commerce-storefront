The Commerce boilerplate ships with Universal Editor (UE) instrumentation for all standard blocks. This page covers how to activate it and how to instrument custom blocks you add. UE setup and block instrumentation are identical for PaaS, Adobe Commerce as a Cloud Service, and Adobe Commerce Optimizer—no backend-specific configuration. Site configuration (backend connection via `config.json`) is covered in [Create a storefront](/get-started/create-storefront/) and [Architecture](/get-started/architecture/).

## Enable Universal Editor for your DA.live site

<Aside type="note">
Universal Editor (UE) on DA.live is part of Adobe's Early Access Technology program and requires AEM Sites credits on your IMS Org. Only Chrome and Safari browsers are supported.
</Aside>

Add the `editor.path` key-value to your **Document Authoring (DA)** org config at <Link href="https://da.live/config#/{your-org}/" text="https://da.live/config#/{your-org}/" />. See the <Link href="https://docs.da.live/developers/guides/setup-universal-editor" text="Setup Universal Editor" /> guide on DA.live for the exact format, placeholders, and behavior.

## Built-in block instrumentation

All standard blocks in the Commerce boilerplate include the three JSON files that Universal Editor (UE) requires:

**Table:** JSON files for UE block instrumentation.

<TableWrapper nowrap={[0]}>
| File | Purpose |
|------|---------|
| `component-definition.json` | Registers blocks and their table structure |
| `component-models.json` | Defines the fields shown in the UE properties panel |
| `component-filters.json` | Controls which child components a container block accepts |
</TableWrapper>

No additional setup is needed for these blocks — they are ready to edit in context out of the box.

## Instrument custom blocks

When you add a new block to your project, create a JSON file in that block's folder so the Universal Editor can recognize and edit it. The Commerce boilerplate uses `blocks/{block-name}/_{block-name}.json` (for example, `blocks/product-recommendations/_product-recommendations.json`) with `definitions`, `models`, and `filters` objects.

<Steps>

1. Create `blocks/{your-block}/_{your-block}.json` with `definitions`, `models`, and `filters`. Reference <Link href="https://github.com/hlxsites/aem-boilerplate-commerce/blob/main/blocks/product-recommendations/_product-recommendations.json" text="product-recommendations" /> for key-value blocks or <Link href="https://github.com/aemsites/da-block-collection/blob/main/ue/models/blocks/accordion.json" text="accordion" /> for container blocks.

2. **Commerce blocks** (for example, `commerce-myblock`) are picked up automatically by the `models/_component-definition.json` glob `../blocks/commerce-*/_*.json#/definitions`. For **other blocks**, add an entry to the Blocks group in `models/_component-definition.json`:
   ```json
   { "...": "../blocks/your-block/_*.json#/definitions" }
   ```

3. Run the bundler to regenerate the root-level JSON files:

   ```bash
   npm run build:json
   ```

</Steps>

<Aside type="tip">
Open a page in Universal Editor while developing. Blocks without instrumentation appear as **(no definition)** in the content tree — a quick visual signal that a definition file is needed.
</Aside>

For detailed syntax, see the <Link href="https://docs.da.live/developers/reference/universal-editor" text="Universal Editor developer reference" /> on DA.live.

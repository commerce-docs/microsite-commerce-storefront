The Ratings and Reviews drop-in exports API functions from `@dropins/storefront-ratings-reviews/api.js`. Use them to load review pages, read review settings, submit reviews, and configure requests to Adobe Commerce GraphQL.

Complete [initialization](/dropins/ratings-reviews/initialization/) before calling functions that load or submit review data. The examples import the initializer from the [quick start](/dropins/ratings-reviews/quick-start/) to configure the endpoint and store headers.

| [`getStoreConfig`](#getstoreconfig) | Loads the store's review settings. |
| [`getRatingsMetadata`](#getratingsmetadata) | Loads the rating categories and the values shoppers can choose. |

## getProductReviews

Loads one page of approved reviews for a product and publishes request, loading, result, and error [events](/dropins/ratings-reviews/events/).

Call this function to load the first page for the `Review` and `Pagination` containers. Both containers update in response to its events. `Pagination` requests later pages when a shopper uses the page controls. `Review` retries a failed request when a shopper selects **Try again**.

```typescript
getProductReviews(
  sku: string,
  options?: { pageSize?: number; currentPage?: number; scope?: string },
): Promise<ProductReviewsModel | null>
```

<TableWrapper nowrap={[0,1]}>

| Parameter | Type | Req? | Description |
| --- | --- | --- | --- |
| `sku` | `string` | Yes | SKU of the product whose reviews to load. The drop-in sends it to Commerce unchanged. |
| `options.pageSize` | `number` | No | Number of reviews per page. Defaults to `20`. |
| `options.currentPage` | `number` | No | Page to load, starting at `1`. Defaults to `1`. |
| `options.scope` | `string` | No | Name that connects the request to its containers through events. Pass the same value to the containers that display this list. |

</TableWrapper>

### Returns

A promise that resolves to a [`ProductReviewsModel`](#productreviewsmodel), or `null` when the `reviews` query returns `null`. The `Review` container shows *Reviews are unavailable.* for a `null` result and *No reviews on this page.* for a page with no items.

### Example

Use this call in a storefront block that renders `Review` and `Pagination`:

```js title="blocks/product-reviews/product-reviews.js"
import { getProductReviews } from '@dropins/storefront-ratings-reviews/api.js';
import '../../scripts/initializers/ratings-reviews.js';

const yourSku = 'YOUR-PRODUCT-SKU';

getProductReviews(yourSku, { pageSize: 20, currentPage: 1, scope: 'product-reviews' })
  // The containers show failures, so the block only logs the rejection.
  .catch((error) => console.error(error));
```

Replace `YOUR-PRODUCT-SKU` with the product's SKU.

- The call loads the first page with up to 20 reviews.
- Pass `'product-reviews'` as the `scope` for both containers so they receive this request's events.
- The `.catch()` logs errors in the browser console. The containers display the error state.

### Behavior

- *Input checks*: A blank SKU, or a `pageSize` or `currentPage` that is not a positive integer, rejects the promise before any network request. No events are published in that case.
- *Newest request wins*: Only the newest request in a scope publishes its result, so a slower, older response cannot replace a newer page. An older request's promise still resolves with its own data.
- *Errors*: GraphQL and network errors reject the promise. They also publish a `reviews/error` event if the request is still the newest in its scope. Handle errors with `.catch()` or `try...catch`.
- *Invalid data*: Invalid page information rejects the promise. The drop-in skips individual invalid reviews and logs a warning, so the remaining reviews still render.
- *Ratings*: The drop-in divides each review's `average_rating`, from `0` to `100`, by 20 to produce `rating` on a scale from `0` to `5`. A review with an average of `0` and no rating votes gets `rating: null`, which the list shows as *Not rated*.
- *Caching*: Each call sends a new request. Responses are not cached.

## getStoreConfig

Loads the store's review settings from the `storeConfig` query. The initializer calls this function and saves the result in the drop-in configuration. To read those saved settings without another request, use `config.getConfig()` instead.

```typescript
getStoreConfig(): Promise<StoreConfigModel>
```

### Returns

A promise that resolves to a [`StoreConfigModel`](#storeconfigmodel). It rejects if the request returns GraphQL errors or no `storeConfig` data. It also rejects if a setting value is not `true`, `false`, `1`, or `0`.

### Example

To request the settings directly from a storefront block:

```js title="blocks/product-reviews/product-reviews.js"
import { getStoreConfig } from '@dropins/storefront-ratings-reviews/api.js';
import '../../scripts/initializers/ratings-reviews.js';

try {
  const { isProductReviewsEnabled, allowGuestsToWriteProductReviews } = await getStoreConfig();
  console.log({ isProductReviewsEnabled, allowGuestsToWriteProductReviews });
} catch (error) {
  console.error('Could not load review settings:', error);
}
```

- `isProductReviewsEnabled` indicates whether the store has product reviews turned on.
- `allowGuestsToWriteProductReviews` indicates whether signed-out shoppers can submit reviews.

## getRatingsMetadata

Loads the active rating categories, such as *Quality* or *Price*, and the values a shopper can choose for each one. The data comes from the `productReviewRatingsMetadata` query.

The `WriteReview` container calls this function for you. Call it directly when building a custom review form.

```typescript
getRatingsMetadata(): Promise<RatingMetadataModel[]>
```

### Returns

A promise that resolves to an array of [`RatingMetadataModel`](#ratingmetadatamodel) objects, one for each category. The promise rejects when the request returns GraphQL errors or no data.

### Behavior

- *Values*: Each category's `values` are sorted from lowest to highest. Each `value` is a whole number of stars, such as `1` through `5`.
- *Unusable categories*: The drop-in leaves out categories without an ID, a name, or at least one valid value.
- *Caching*: The request can use the browser's HTTP cache.

## createProductReview

Submits a product review with the `createProductReview` mutation. The `WriteReview` container calls this function for you. Call it directly when building a custom review form.

```typescript
createProductReview(input: CreateProductReviewInput): Promise<CreatedProductReviewModel>
```

<TableWrapper nowrap={[0,1]}>

| Parameter | Type | Req? | Description |
| --- | --- | --- | --- |
| `input.sku` | `string` | Yes | SKU of the product to review. |
| `input.nickname` | `string` | Yes | Name the reviewer enters. |
| `input.summary` | `string` | Yes | Review title. |
| `input.text` | `string` | Yes | Review body. |
| `input.ratings` | `Array<{ id: string; valueId: string }>` | Yes | One entry for each rating category. Use the `id` of the category and the `valueId` of the chosen value from `getRatingsMetadata`. |

</TableWrapper>

### Returns

A promise that resolves to the created review as a [`CreatedProductReviewModel`](#createdproductreviewmodel).

### Example

This example submits a review with four stars in each rating category:

```js title="blocks/product-reviews/product-reviews.js"
import { createProductReview, getRatingsMetadata } from '@dropins/storefront-ratings-reviews/api.js';
import '../../scripts/initializers/ratings-reviews.js';

const yourSku = 'YOUR-PRODUCT-SKU';

try {
  const categories = await getRatingsMetadata();
  const ratings = categories.map(({ id, values }) => ({
    id,
    // A category without a four-star value makes the request reject.
    valueId: values.find(({ value }) => value === 4)?.valueId,
  }));

  const review = await createProductReview({
    sku: yourSku,
    nickname: 'Alex',
    summary: 'Comfortable fit',
    text: 'I wear it every day.',
    ratings,
  });
  console.log(review);
} catch (error) {
  console.error('Could not submit the review:', error);
}
```

Replace `YOUR-PRODUCT-SKU` with the product's SKU.

- `getRatingsMetadata` supplies the category IDs and value IDs. Send those IDs unchanged in `ratings`.
- The example selects the four-star value in each category. If a category has no four-star value, `createProductReview` rejects the input before sending a submission request.
- A successful call logs the created review in the browser console. A failed call logs an error.

### Behavior

- *Input checks*: The function trims `sku`, `nickname`, `summary`, and `text`. The promise rejects before any network request if one of these fields is empty, `ratings` is empty, or a rating has no `id` or `valueId`.
- *reCAPTCHA*: For valid input, the function requests a fresh reCAPTCHA token. If a token is returned, the request includes it in the `X-ReCaptcha` header. The function removes the header after the request finishes, whether it succeeds or fails.
- *Errors*: The promise rejects with the GraphQL error message, for example, when reviews are turned off or Commerce rejects the reCAPTCHA token.
- *Moderation*: New reviews usually wait for approval in the Admin, so they do not appear in the review list right away.
- *Events*: This function publishes no events. The `WriteReview` container publishes [`reviews/review-submitted`](/dropins/ratings-reviews/events/#reviewsreview-submitted) after a successful submission.

## GraphQL client functions

The drop-in has its own GraphQL client. These functions configure it.

<TableWrapper nowrap={[0]}>

| Function | Description |
| --- | --- |
| `setEndpoint(endpoint)` | Sets the GraphQL endpoint. Storefront initializers pass `CORE_FETCH_GRAPHQL` so that requests use your Commerce GraphQL endpoint and store headers. |
| `setFetchGraphQlHeader(name, value)` | Adds or replaces one header on every request. |
| `setFetchGraphQlHeaders(headers)` | Adds or replaces several headers on every request. |
| `removeFetchGraphQlHeader(name)` | Removes one header. |
| `fetchGraphQl(query, options)` | Sends a GraphQL request through the configured client. |
| `getConfig()` | Returns the current client configuration. |

</TableWrapper>

<Aside type="note">
Headers are shared by every request the drop-in sends. Set store headers once in the initializer rather than before individual calls.
</Aside>

## Data models

These models describe review pages, store settings, rating choices, and submissions.

### ProductReviewsModel

One page of reviews.

```typescript
type ProductReviewsModel = {
  items: ProductReviewModel[];
  pageInfo: {
    currentPage: number;
    pageSize: number;
    totalPages: number;
  };
};
```

### ProductReviewModel

One approved review. All text fields are plain text exactly as the shopper entered them. Render them as text, not HTML.

```typescript
type ProductReviewModel = {
  // Name the reviewer entered.
  nickname: string;
  // Review title.
  summary: string;
  // Review body.
  text: string;
  // Average of the review's rating votes on a 0–5 scale, or null when the review has no votes.
  rating: number | null;
  // Server date string without a time zone, for example "2026-09-17 12:12:00".
  createdAt: string;
};
```

### StoreConfigModel

The store's review settings.

```typescript
type StoreConfigModel = {
  // True when product reviews are enabled for the store.
  isProductReviewsEnabled: boolean;
  // True when guests may submit reviews.
  allowGuestsToWriteProductReviews: boolean;
};
```

### RatingMetadataModel

One rating category and the values a shopper can choose.

```typescript
type RatingMetadataModel = {
  // Category ID. Send it back unchanged.
  id: string;
  // Category name, for example "Quality".
  name: string;
  // Choices sorted from lowest to highest.
  values: Array<{
    // Value ID. Send it back unchanged.
    valueId: string;
    // Number of stars, for example 4.
    value: number;
  }>;
};
```

### CreateProductReviewInput

The review to submit.

```typescript
type CreateProductReviewInput = {
  sku: string;
  nickname: string;
  summary: string;
  text: string;
  ratings: Array<{ id: string; valueId: string }>;
};
```

### CreatedProductReviewModel

The review that Adobe Commerce created.

```typescript
type CreatedProductReviewModel = {
  nickname: string;
  summary: string;
  text: string;
  // Average of the review's ratings on a 0–5 scale, or null when it has none.
  rating: number | null;
  // Score for each rating category.
  ratingsBreakdown: Array<{ name: string; value: number }>;
};
```

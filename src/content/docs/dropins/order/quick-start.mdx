The Order drop-in provides a complete order management experience for customers. It includes containers for viewing order details, tracking shipments, managing returns, and searching order history.

## Quick example

The Order drop-in is included in the <Link href="https://github.com/hlxsites/aem-boilerplate-commerce" text="Commerce boilerplate" />. This example shows the basic pattern:

```js
// 1. Import initializer (handles all setup)
import '../../scripts/initializers/order.js';

// 2. Import the container you need
import CreateReturn from '@dropins/storefront-order/containers/CreateReturn.js';

// 3. Import the provider
import { render as provider } from '@dropins/storefront-order/render.js';

// 4. Render in your block
export default async function decorate(block) {
  await provider.render(CreateReturn, {
    // Configuration options - see Containers page
  })(block);
}
```

**New to drop-ins?** See the [Connect a drop-in](/dropins/all/quick-start/) guide for complete step-by-step instructions.

## Invoice Management

For an authenticated customer's order invoices, use [OrderInvoices](/dropins/order/containers/order-invoices/) and [InvoiceDetails](/dropins/order/containers/invoice-details/). These containers use the existing Order initializer; no separate Invoice drop-in initialization is required.

<Aside type="caution" title="Prerelease integration">
  The consolidated Invoice Management feature is available in
  `@dropins/storefront-order@5.0.0-alpha-20261110114801`. An alpha is a prerelease, not a stable
  release. The package version installed in your storefront must include both invoice containers and
  the PDF options documented here.
</Aside>

Before deploying the feature:

- Pin the approved Order package version in the storefront manifest and lockfile, and regenerate the browser assets through the storefront's package installation workflow. A manually copied build can be overwritten by the next installation.
- Deploy Storefront Compatibility **4.7.22**, **4.8.34**, or **4.9.9**, or a later compatible patch on the corresponding release line. [Verify the invoice schema](/dropins/order/functions/#verify-invoice-schema-compatibility) on the endpoint used by each environment.
- Confirm that the host provides the invoice-list and invoice-details pages. In the AEM storefront integration, these use the `commerce-order-invoices` and `commerce-invoice-details` blocks.
- Preserve both `orderRef` and `invoiceRef` in invoice-details URLs, and preserve the destination through sign-in. An invoice reference does not authorize access to an invoice.
- Verify multiple and partial invoices, zero and unavailable amounts, and PDF downloads. Use an invoice whose stored subtotal differs from unit price multiplied by quantity to verify backend rounding is preserved.

The package, host integration, and backend schema must all be compatible. Updating only the package does not create authored pages or deploy backend fields. Invoice retrieval is scoped to one authenticated customer's order; guest invoice lookup and cross-order invoice search are not provided.

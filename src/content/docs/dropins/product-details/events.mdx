## Event details

The following sections provide detailed information about each event, including its direction, event payload, and usage examples.


### `pdp/data` (emits and listens)

Triggered when data is available or changes.

#### Event payload

```typescript
ProductModel | null
```

See [`ProductModel`](#productmodel) for full type definition.





#### Example

```js
import { events } from '@dropins/tools/event-bus.js';

events.on('pdp/data', (payload) => {
  console.log('pdp/data event received:', payload);
  // Add your custom logic here
});
```

## Data Models

The following data models are used in event payloads for this drop-in.

### ProductModel

Used in: [`pdp/data`](#pdpdata-emits-and-listens).

```ts
interface ProductModel {
  name: string;
  sku: string;
  isBundle: boolean;
  addToCartAllowed: boolean;
  inStock: boolean | null;
  shortDescription?: string;
  metaDescription?: string;
  metaKeyword?: string;
  metaTitle?: string;
  description?: string;
  images?: Image[];
  prices: Prices;
  attributes?: Attribute[];
  options?: Option[];
  optionUIDs?: string[];
  url?: string;
  urlKey?: string;
  externalId?: string;
  externalParentId?: string;
  variantSku?: string;
  productType?: ProductType | undefined;
}
```

### Attribute

Used in: [`ProductModel.attributes`](#productmodel).

```ts
interface Attribute {
  id: string;
  label: string;
  value: string;
  roles?: string[];
}
```

`value` is delivered as a JSON string (or, for some attributes, an already-parsed object) whose shape depends on the attribute's `id`. Attributes with an `id` starting with `ac_` carry a JSON payload specific to that attribute — for example `ac_giftcard`, `ac_downloadable`, and `ac_customizable_options`.

#### `ac_customizable_options`

Carries Magento **Customizable Options** — priced selectable choices (dropdown, radio, checkbox, multi-select) and shopper-input fields (text, textarea, date, date/time, time) attached to a product:

```json
{
  "schemaVersion": 1,
  "selectable": [
    {
      "id": "1",
      "label": "Add Pressure Gauges?",
      "renderType": "drop_down",
      "type": "custom_option",
      "required": "1",
      "sortOrder": "1",
      "values": [
        {
          "id": "Y3VzdG9tLW9wdGlvbi8xLzE=",
          "label": "No Thanks",
          "price": "0.000000",
          "priceType": "fixed",
          "sku": "PG-NO",
          "sortOrder": "1",
          "isDefault": false
        },
        {
          "id": "Y3VzdG9tLW9wdGlvbi8xLzI=",
          "label": "Yes - 3 x GT16-3S",
          "price": "108.000000",
          "priceType": "fixed",
          "sku": "PG-YES",
          "sortOrder": "2",
          "isDefault": false
        }
      ]
    }
  ],
  "shopperInput": [
    {
      "id": "Y3VzdG9tLW9wdGlvbi8y",
      "label": "Engraving text",
      "renderType": "field",
      "required": "0",
      "price": "15.000000",
      "sku": "ENGRAVE",
      "sortOrder": "2",
      "range": { "to": "30" },
      "productSku": "TEST-CUSTOPT-SIMPLE"
    }
  ]
}
```

- This example is the parsed Catalog Service payload, before price normalization. The typed PDP accessor converts `price` fields from numeric strings (for example, `"108.000000"`) to numbers for rendering. If you read the raw attribute yourself, parse its JSON and convert prices before arithmetic or formatting.
- `schemaVersion` identifies the attribute payload format. `selectable` contains predefined choices; `shopperInput` contains fields for shopper-entered values. `required` is a string flag (`"1"` or `"true"` marks a required option), not a boolean. `sortOrder` defines the display order.
- `selectable[].values[].id` and `shopperInput[].id` are base64-encoded `custom-option/<optionId>[/<valueId>]` tokens. These are the same tokens the cart drop-in's [`addProductsToCart`](/dropins/cart/functions/#addproductstocart) expects in `optionsUIDs` (for selectable choices) and `enteredOptions` (for shopper-input values) — no mapping step is required between reading this attribute and adding the product to the cart.
- A product with no customizable options simply has no `ac_customizable_options` entry in `attributes`.

<Aside type="note">
  The
  [`ProductCustomizableOptions`](/dropins/product-details/containers/product-customizable-options/)
  container renders selectable choices and `field`, `area`, `date`, `date_time`, and `time`
  shopper-input fields. Shopper inputs update `enteredOptions` with the encoded option UID and
  string value; clearing a field removes its entry. File options appear disabled. Required-option
  enforcement and live updates to the displayed product total are not implemented. See the
  [how-to](/dropins/product-details/tutorials/render-customizable-options/) for customization steps.
</Aside>

### ValuesModel

Used in: [`pdp/values`](#pdpvalues-emits-and-listens).

```ts
interface ValuesModel {
  sku: string;
  quantity: number;
  optionsUIDs?: string[];
  enteredOptions?: Array<{ uid: string; value: string }>;
}
```

For customizable options, `optionsUIDs` contains encoded selectable-value UIDs, and `enteredOptions` contains encoded shopper-input option UIDs with string values. Text is preserved, including whitespace and line breaks. Date and time inputs use the [cart-compatible formats](/dropins/product-details/containers/product-customizable-options/#shopper-input-controls) produced by the container.

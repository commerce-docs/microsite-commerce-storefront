Magento **Customizable Options** let merchants attach priced selectable choices (dropdown, radio, checkbox, multi-select) and shopper-input fields (text, textarea, date, date/time, time) to a product — for example, "Add Pressure Gauges?" as a priced dropdown, or "Engraving text" as a priced text field. Catalog Service exposes this data to the storefront as a JSON product attribute named `ac_customizable_options`, delivered through the same generic `attributes` field the Product Details drop-in already fetches for every product — no separate query is required.

<Aside type="note" title="Data foundation only">
This page documents the `ac_customizable_options` attribute shape and how to read it from product data. Dedicated containers for rendering these options, enforcing required selections, and showing a live price preview ship in later releases of this drop-in. Until then, `file`-type shopper-input options aren't included in the documented shape below — file uploads to Commerce aren't supported by any drop-in yet.
</Aside>

## Prerequisites

Before reading this page, you should understand:

- [Events](/dropins/product-details/events/) — `pdp/data` and the [`ProductModel`](/dropins/product-details/events/#productmodel) data model, in particular its `attributes` field
- The existing `ac_giftcard` and `ac_downloadable` attributes, which use the same generic `attributes` delivery mechanism documented here

## Attribute shape

Each entry in `ProductModel.attributes` with `id: 'ac_customizable_options'` carries a `value` shaped like this (a JSON string or an already-parsed object, depending on how the data reached your code):

```json
{
  "schemaVersion": 1,
  "selectable": [
    {
      "id": "1",
      "label": "Add Pressure Gauges?",
      "renderType": "drop_down",
      "type": "custom_option",
      "required": "1",
      "sortOrder": "1",
      "values": [
        { "id": "Y3VzdG9tLW9wdGlvbi8xLzE=", "label": "No Thanks", "price": "0.000000", "priceType": "fixed", "sku": "PG-NO", "sortOrder": "1", "isDefault": false },
        { "id": "Y3VzdG9tLW9wdGlvbi8xLzI=", "label": "Yes - 3 x GT16-3S", "price": "108.000000", "priceType": "fixed", "sku": "PG-YES", "sortOrder": "2", "isDefault": false }
      ]
    }
  ],
  "shopperInput": [
    {
      "id": "Y3VzdG9tLW9wdGlvbi8y",
      "label": "Engraving text",
      "renderType": "field",
      "required": "0",
      "price": "15.000000",
      "sku": "ENGRAVE",
      "sortOrder": "2",
      "range": { "to": "30" },
      "productSku": "TEST-CUSTOPT-SIMPLE"
    }
  ]
}
```

- **`selectable`** holds priced choice-based options. Supported `renderType` values: `drop_down`, `radio`, `checkbox`, `multiple`. Each value carries its own `price` and `priceType` (`fixed` or `percent`), since the choice — not the option — determines the price delta.
- **`shopperInput`** holds free-form options. Supported `renderType` values: `field`, `area`, `date`, `date_time`, `time`. `range` describes input constraints (for example, a maximum text length), and `price` is optional — some shopper-input options carry no charge.
- **`price` fields arrive as numeric strings** (for example, `"108.000000"`), matching the raw Commerce representation. Convert them to numbers before doing arithmetic or formatting.
- **UIDs** (`selectable[].values[].id` and `shopperInput[].id`) are base64-encoded `custom-option/<optionId>[/<valueId>]` tokens — the same tokens `addProductsToCart` expects in `selected_options` (for selectable choices) and `entered_options` (for shopper-input values). No mapping step is needed between reading this attribute and adding the product to the cart.

## Reading the attribute

`ac_customizable_options` is delivered on `ProductModel.attributes` exactly like `ac_giftcard` and `ac_downloadable` — subscribe to [`pdp/data`](/dropins/product-details/events/#pdpdata-emits-and-listens), find the entry by `id`, and parse its `value` if it arrives as a string:

```js
import { events } from '@dropins/tools/event-bus.js';

events.on('pdp/data', (data) => {
  const attribute = data?.attributes?.find(
    (attr) => attr.id === 'ac_customizable_options'
  );

  if (!attribute) return;

  const customizableOptions =
    typeof attribute.value === 'string'
      ? JSON.parse(attribute.value)
      : attribute.value;

  // customizableOptions.selectable / customizableOptions.shopperInput
}, { eager: true });
```

A product with no customizable options simply has no `ac_customizable_options` entry in `attributes` — there's no placeholder object to guard against.

<Aside>
Remember to coerce each `price` string to a number (for example, `Number(value.price)`) before using it — the drop-in does not do this coercion for you at the `pdp/data` event level.
</Aside>

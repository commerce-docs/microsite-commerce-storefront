Shoppers get pages from Edge Delivery Services. The browser runs drop-ins and calls the configured catalog and shopping APIs. Those APIs can belong to different platforms.

Confirm the services required by your project in [Backend options](/get-started/backends/). Use [Storefront configuration](/setup/configuration/commerce-configuration/) when you are ready to connect them.

## How the pieces connect

Commerce blocks use drop-ins and storefront API clients to connect page features to catalog services and shopping operations.

The Adobe Commerce storefront integration uses <Term>GraphQL</Term>. Catalog APIs supply product details and discovery. Core Commerce GraphQL handles carts, checkout, customer accounts, and orders on Adobe Commerce backends.

Adobe Commerce as a Cloud Service supports both kinds of requests. With Adobe Commerce Optimizer, shopping operations stay with an existing commerce platform. Connecting catalog services does not automatically adapt cart and checkout to a third-party platform. To compare backend configurations and their requirements, see [Backend options](/get-started/backends/).

## Commerce Services and integrations

The required services depend on the selected backend and shopping features. Catalog Service, Live Search, and Product Recommendations describe the Commerce Services path. Adobe Commerce Optimizer exposes its own Merchandising API for catalog and discovery requests.

Do not treat this service list as a universal installation checklist. Use [Prerequisites by backend](/get-started/backends/#prerequisites-by-backend) and, for an existing Adobe Commerce deployment, [PaaS: required packages and services](/get-started/backends/#paas-required-packages-and-services).

### Services Connector

For Adobe Commerce on Cloud or on-premises using hosted Commerce Services, the Commerce Services Connector links the deployment to Catalog Service, Live Search, and Product Recommendations. Configure that connection in the Commerce Admin using the API keys and data space for the intended environment.

For Adobe Commerce as a Cloud Service, follow the managed environment's setup rather than the extension-installation steps for an existing Commerce deployment.

### Adobe Commerce Optimizer

Adobe Commerce Optimizer provides catalog and product discovery through the <Link href="https://developer.adobe.com/commerce/services/optimizer/merchandising-services/" text="Merchandising API" />. Use that API rather than assuming that the Catalog Service API applies to every project.

The <Link href="https://experienceleague.adobe.com/en/docs/commerce/aco-optimizer-connector/overview" text="Adobe Commerce Optimizer Connector" /> synchronizes catalog and pricing data from Adobe Commerce on Cloud or on-premises into Adobe Commerce Optimizer. Other data sources use the supported <Link href="https://experienceleague.adobe.com/en/docs/commerce/optimizer/setup/data-sync" text="Data Sync" /> integration. Neither route replaces the existing platform's cart, checkout, accounts, or orders.

### Catalog Service

The <Term>Catalog Service</Term> gives storefronts on the Commerce Services path read-only access to product data through a dedicated GraphQL API. It serves catalog reads separately from core Commerce operations.

For projects using Adobe Commerce Optimizer or its connector, the <Link href="https://experienceleague.adobe.com/en/docs/commerce/catalog-service/guide-overview" text="Catalog Service documentation" /> directs developers to the Merchandising API instead. Product-page and discovery requirements therefore depend on the selected backend.

### Live Search

<Term>Live Search</Term> provides AI-powered search, filtering, and result ranking for Commerce environments using that service. It is a search path for product discovery, not a separate installation requirement for every backend.

When using Live Search outside the classic PHP theme, configure storefront event collection so the service receives shopper activity. See [Analytics](/setup/analytics/instrumentation/). Adobe Commerce Optimizer projects use the discovery capabilities exposed through the Merchandising API.

### Product Recommendations

On the Commerce Services path, Product Recommendations uses Adobe Sensei to show suggested products. Examples include units such as "Customers who bought this also bought" and "Most viewed." Configure recommendation units in the Commerce Admin and render them where the storefront needs them.

This service is optional. Its Commerce Admin setup is not the configuration process for every backend's recommendation capabilities.

Without the classic PHP theme, Product Recommendations needs the same storefront event collection as Live Search before models have signal. See [Analytics](/setup/analytics/instrumentation/).

### Core GraphQL

Core Commerce GraphQL is the API on an Adobe Commerce backend for carts, checkout, customer accounts, orders, and other reads and writes. Hosted catalog services do not replace these operations. When Adobe Commerce Optimizer supplies the catalog experience, the existing commerce platform still handles transactions. A third-party platform uses its own APIs and requires project-specific integration.

The storefront starter code uses separate core and catalog API clients. They can share an endpoint address, but their API responsibilities remain different. See [Storefront configuration](/setup/configuration/commerce-configuration/) for connection settings and the <Link href="https://developer.adobe.com/commerce/webapi/graphql/" text="GraphQL overview" /> for Adobe Commerce operations.

### Storefront Compatibility package

The Storefront Compatibility package extends the default Commerce GraphQL schema with additional support that drop-ins require. Without it on the Commerce deployment that serves those flows, the drop-ins cannot talk to your backend as they expect. See [Compatibility Package](/setup/configuration/storefront-compatibility/) for who installs it on each backend.

Adobe manages the Storefront Compatibility package on Adobe Commerce as a Cloud Service. For Adobe Commerce on Cloud or on-premises with Adobe Commerce Optimizer, install it on the Adobe Commerce deployment.

## Optional integrations

These integrations serve additional data and API requirements. They are separate from the catalog and shopping connections in the main diagram.

### Data Connection

The <Term>Data Connection</Term> sends shopper behavior and order data to Adobe Experience Platform, where other Adobe tools can use it for personalization and segmentation. For example, Adobe Journey Optimizer, a cross-channel marketing automation tool, can use that data to trigger an abandoned-cart email. Use this optional integration when the project needs Experience Platform capabilities.

This example covers the Data Connection extension on Adobe Commerce on Cloud or on-premises. Its <Link href="https://experienceleague.adobe.com/en/docs/commerce/data-connection/overview" text="Data Connection documentation" /> distinguishes browser behavior data from Commerce server data. The configured SDKs, APIs, and connectors collect those sources for Experience Platform.

### API Mesh

<Link href="https://developer.adobe.com/graphql-mesh-gateway/" text="API Mesh for Adobe Developer App Builder" /> is an advanced option when a project needs to combine multiple backend sources behind a single GraphQL endpoint. Add it for that requirement, not as a default storefront prerequisite.

## Coming from Luma or a classic Commerce theme?

This migration path applies when an existing Commerce theme remains in use. In the classic model, Commerce builds storefront pages with PHP. With Edge Delivery Services, the browser renders drop-ins that call the configured APIs. Moving the storefront does not replace the Commerce Admin, catalog, or order tools.

If Luma pages and Edge Delivery pages must share a cart and sign-in session during the move, use [Luma Bridge](/setup/discovery/luma-bridge/). For the relationships between the existing platform, the bridge, and the Adobe Commerce Optimizer Connector, see [Backend topology](/get-started/backends/#backend-topology). A new storefront without Luma pages does not need this session bridge.

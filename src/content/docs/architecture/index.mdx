## The runtime model

A storefront page brings together content, code, and Commerce data:

<Diagram adaptColors type="mermaid" code={`
flowchart LR
  content["Page content"] --> delivery["Edge Delivery Services"]
  code["Storefront code"] --> delivery
  delivery --> browser["Shopper's browser"]
  browser <--> data["Commerce data"]
`} caption="Edge Delivery Services delivers page content and storefront code to the shopper's browser. The storefront code then requests Commerce data." />

- Page content: Authors manage text, images, and page settings in an authoring tool such as <Term>DA.live</Term>. This content is separate from the storefront code.
- Storefront code: The project's JavaScript and styles control how pages look and behave. <Term>Edge Delivery Services</Term>, Adobe's delivery system, sends this code and the page content to the shopper's browser. Commerce blocks render the included drop-ins in that browser.
- Commerce data: Connected Commerce services supply product information and shopping data, such as prices and cart contents. These services form the [backend](/get-started/backends/). A project can use one commerce platform or combine services from more than one.

For example, a product page can show an authored promotion next to a price supplied by Commerce. Storefront code controls how they appear together.

The event bus lets shopping features coordinate within that browser. Configuration determines which services receive their API requests.

## Catalog requests and shopping operations

Storefront requests serve two different purposes:

- Catalog requests retrieve product details, prices, search results, and recommendations.
- Shopping operations read or update carts, complete checkout, and manage customer accounts and orders.

Adobe Commerce as a Cloud Service supports both parts of the shopping experience. With Adobe Commerce Optimizer, the storefront uses its catalog and product-discovery services while an existing commerce platform handles shopping operations.

The storefront starter code has separate API clients for catalog requests and core Commerce operations. These are different responsibilities even when the clients use the same endpoint address.

See [Commerce services at a glance](/get-started/architecture/commerce-services-and-backends/) for the service relationships and [Storefront configuration](/setup/configuration/commerce-configuration/) for connection settings.

The Adobe Commerce boilerplate supports the Universal Editor (UE) for content and commerce blocks. For first-time setup, start with <Link href="https://docs.da.live/developers/guides/setup-universal-editor" text="Setup Universal Editor" /> — instrumentation syntax and the custom block workflow are covered in the rest of the DA.live documentation below.

<Aside type="note" title="Document Authoring content source">
This page covers Universal Editor setup for the **Commerce boilerplate**, which uses **Document Authoring (DA.live)** as the content source. If your project uses **AEM Sites** as the content source, the instrumentation approach differs — follow the <Link href="https://www.aem.live/developer/universal-editor-blocks" text="Universal Editor blocks guide" /> on aem.live instead.
</Aside>

## Commerce boilerplate structure

The standard DA.live approach centralizes block instrumentation in one folder, `ue/models/blocks/`, as shown in the <Link href="https://github.com/aemsites/da-block-collection" text="da-block-collection" /> reference implementation. The Commerce boilerplate takes a different approach: each block keeps its own instrumentation file next to its code, at `blocks/{block-name}/_{block-name}.json`. When you commit, a pre-commit hook combines these per-block files into the root-level `component-*.json` files that the UE reads.

Here's how those files are organized in the repository:

```text
aem-boilerplate-commerce/
├── component-definition.json    ← generated (UE reads this)
├── component-filters.json       ← generated (UE reads this)
├── component-models.json        ← generated (UE reads this)
├── models/
│   └── _section.json           ← add new blocks to the component list
└── blocks/
    ├── accordion/
    │   └── _accordion.json      ← UE instrumentation
    ├── hero/
    │   └── _hero.json
    ├── product-recommendations/
    │   └── _product-recommendations.json
    ├── commerce-cart/
    │   └── _commerce-cart.json
    └── ...                      ← and other blocks with _*.json
```

Not every block in the boilerplate has instrumentation yet. `header` and `footer` are managed as global content outside the block picker, so they don't need a `_*.json` file; a few other blocks don't have one either.

Each generated file has a distinct role:

- `component-models.json` — the fields that appear in the Universal Editor's properties panel for each block.
- `component-definition.json` — how each block appears in the Universal Editor's block picker, including its name, group, and how its content maps to the table structure in the document.
- `component-filters.json` — which blocks or items you can insert inside another block, such as the entries you can add to an accordion.

You don't edit the generated files directly. This applies whether you're building a new custom block or adding instrumentation to an existing commerce block that doesn't have it yet: create the block's `_{block-name}.json` file next to its code, then add the block's name to the `components` list in `models/_section.json`. The pre-commit hook regenerates the three files above the next time you commit, and the block appears in the Universal Editor's block picker.

<Aside type="tip">
While you're developing, open a page in the Universal Editor. Blocks without instrumentation appear as **(no definition)** in the content tree, which is a quick visual signal that a definition file is needed. See <Link href="https://docs.da.live/developers/reference/universal-editor#step-by-step-guide" text="step 3 of the instrumentation guide" /> for details.
</Aside>

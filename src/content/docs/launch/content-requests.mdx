Your storefront delivers pages through Edge Delivery Services, part of Adobe Experience Manager (AEM). AEM measures usage in content requests, which count toward the allowance in your license.

One page view can use more than one content request because the browser loads the page and its data through separate requests. Not every request counts: AEM includes eligible HTML and JSON responses but excludes traffic such as images, style sheets, and JavaScript files.

Understanding what counts helps you estimate usage before launch. The example below shows how one product page view adds up to about 2.4 content requests after exclusions:

## How content requests are calculated

Unless an [exclusion](#which-requests-are-excluded) applies, the <Link href="https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/implementing/using-cloud-manager/license-dashboard#what-is-a-content-request" text="AEM counting definition" /> counts responses by type:

- **HTML:** Each HTML response, such as the page itself, counts as one content request.
- **JSON:** Every five JSON responses, such as storefront data files, count as one content request.

<Aside type="tip" title="Forecasting usage">

To forecast usage, [estimate the content requests for representative pages](#estimate-content-requests-for-a-page), multiply each estimate by that page's expected views, and then add content requests that occur without a shopper page view. Prefetched content and bots that AEM does not recognize can add these content requests.

</Aside>

## Which requests count

AEM counts eligible HTML and JSON page content with HTTP status codes `100-299`, including partial content (`206`), unless an [exclusion](#which-requests-are-excluded) applies. The status code describes the result of a request.

These situations still count:

<TableWrapper>

| Situation | Counting rule |
| --------- | ------------- |
| A content delivery network (CDN) serves a cached response | Counted once, at the first caching system that receives the request. |
| A page is prefetched (loaded in advance) | Counted when fetched, even if the shopper never opens the page. |
| A script, bot, or monitoring tool fetches content | Counted unless AEM excludes the bot or monitoring check. |
| Analytics does not record the visit | Consent settings and tracking blockers do not remove eligible requests from the count. |

</TableWrapper>

## Which requests are excluded

These requests don't consume your content request allowance.

<TableWrapper>

| Request type | What to look for |
| ------------ | ---------------- |
| Static assets | Images, style sheets, and JavaScript files. |
| HTML fragments | Navigation, footer, or other fragments requested from URLs ending in `.plain.html`. |
| Redirects and errors | Responses with status codes `300-399`, `400-499`, or `500` and above. A successful follow-up request can still count. |
| Recognized bots | Search, social, or artificial intelligence (AI) crawlers that AEM identifies as excluded bots. Unrecognized bots can still count. |
| Detected attacks | Traffic AEM detects and blocks as a distributed denial-of-service attack. |
| Specified health checks | Only the monitoring checks listed in the <Link href="https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/implementing/using-cloud-manager/content-requests" text="AEM exclusion rules" />. For Edge Delivery availability checks, use `HEAD` instead of `GET`. |
| Requests to other services | Requests routed directly to Commerce or another service without reaching AEM. |
| Commerce Integration Framework calls | Requests forwarded by AEM through URLs starting with `/api/graphql`. |

</TableWrapper>

For all exclusions, see <Link href="https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/implementing/using-cloud-manager/content-requests" text="AEM content request rules" />.

## Estimate content requests for a page

Using an Adobe demo product page, we'll show how to estimate content requests for any storefront page with your browser's developer tools.

<Diagram caption="Adobe demo product page used to estimate content requests.">
  ![Demo storefront product page for the Pride at Adobe t-shirt, with product images, price, quantity selector, and Add to Cart button, followed by content cards, a team photo, product recommendations, and the footer.](./images/product-page.webp)
</Diagram>

<Steps>

1. Open a page on your production site in your browser.

   Only production traffic counts toward your allowance.

1. Open your browser's <b>developer tools</b>, and then select the **Network** tab.

1. Select <b>Disable cache</b>, and then reload the page.

   Disabling the cache shows the requests a first-time visitor makes.

1. In the <b>Filter</b> box, enter the following filter. Replace `www.example.com` with your storefront's domain.

   ```text showLineNumbers=false
   domain:www.example.com mime-type:text/html
   ```

    At the bottom of the panel, record the first number (matching requests) as your listed HTML count.

   <Diagram caption="The HTML filter lists the page document and four fragments.">
     ![Chrome DevTools Network panel with Disable cache selected and the request list filtered to HTML responses from www.aemshop.net. Five responses with status 200 are listed: the page document and four .plain.html fragments.](./images/html-requests.png)
   </Diagram>

1. Replace the filter with the following one, and record your listed JSON count the same way.

   ```text showLineNumbers=false
   domain:www.example.com mime-type:application/json
   ```

   <Diagram caption="The JSON filter lists seven storefront data files and six Commerce API calls.">
     ![Chrome DevTools Network panel with the request list filtered to JSON responses from www.aemshop.net. Thirteen responses with status 200 are listed: 7 storefront data files, such as global.json and cart.json, and 6 graphql and cs-graphql requests.](./images/json-requests.png)
   </Diagram>

1. <b>Subtract</b> the excluded requests (shown above):

   - Redirects and errors: any request whose Status column shows a value outside **200** to **299**, such as **301** or **404**.
   - HTML fragments: any request whose name ends in `.plain.html`, such as `nav.plain.html` or `footer.plain.html`.
   - Commerce API calls: any request whose name starts with `graphql` or `cs-graphql`.

1. <b>Add</b> your remaining HTML count to your remaining JSON count divided by five.

</Steps>

## Product page calculation example

For the product page in the screenshots, exclude the `.plain.html` fragments and the `graphql` and `cs-graphql` calls that its CDN routes to Commerce.

<TableWrapper highlightLast totalRow>

| Files | Browser requests | Content requests |
| ----- | ---------------- | ---------------: |
| Product page | 1 HTML | **1** |
| Fragments, such as the footer | 4 HTML | excluded = **0** |
| Storefront data files, such as cart.json | 7 JSON | 7 ÷ 5 = **1.4** |
| graphql and cs-graphql calls | 6 JSON | excluded = **0** |
| Total | 5 HTML, 13 JSON | **2.4** |

</TableWrapper>

<Aside type="note" title="Estimated versus measured usage">

This estimate covers one visit. Browser caching can reduce requests on repeat visits. Shopper interactions, bots, and monitoring tools can add requests unless an exclusion applies.

To include shopper interactions in your estimate, use the page with DevTools open before recording your counts.

For a breakdown of measured usage, ask your Adobe team for a top usage report.

</Aside>

A content request is a page or data file that your storefront delivers through Adobe Experience Manager (AEM). Adobe measures your storefront's usage in content requests, not page views. Your license sets a monthly content request allowance, and Adobe compares your usage with the total for each 12-month period, so busy months can balance quieter ones.

## Page views compared to content requests

When a shopper views a page, the browser makes many requests, but only the page and some data files count. The <Link href="https://experienceleague.adobe.com/en/docs/experience-manager-cloud-service/content/implementing/using-cloud-manager/license-dashboard#what-is-a-content-request" text="AEM counting definition" /> uses two rules:

- *Pages:* Each page's HTML counts as 1 content request.
- *Data files:* Only some JSON data files count, such as the index file that lists banners and other content for product and category pages. Every JSON file that counts toward content requests is counted in groups of 5, so each one adds 1 ÷ 5 = 0.2. Commerce API calls are different. They go straight to Adobe Commerce, not AEM, so they don't count. Placeholder files don't count either.

For example, a product page on the <Link href="https://www.aemshop.net/" text="aemshop.net" /> demo storefront loads 1 page and 1 JSON file that counts, so one view uses 1 + 0.2 = 1.2 content requests:

## Which requests count

Your storefront delivers pages through Edge Delivery Services, part of AEM, so AEM's counting rules apply. These rules cover traffic through the Adobe-managed content delivery network (CDN).

<Diagram
  adaptColors
  caption="AEM checks each storefront visit. Only the visits in the Counts column use your content request allowance."
>
  ![Storefront visits arrive through the Adobe-managed CDN, and AEM checks each one. Six kinds of visits count. Shoppers count 1 per page, even with analytics blocked. Prerendered pages count 1 per page, once, whether or not the shopper opens them. Spreadsheets and indexes, such as banners, store lists, and blogs, count 0.2 per file. Unrecognized bots, such as AI agents and scripts, count 1 per page. Uptime monitors that send GET requests count 1 per check. Apps and feeds that read your data files count 0.2 per file. Four kinds don't count and use 0 of your allowance. Images, styles, and scripts, plus the navigation and footer. Well-known search, social, and AI crawlers. Health checks from monitors that send HEAD requests. Redirects and errors, such as 301 or 404.](./images/what-counts.png)
</Diagram>

<Aside type="tip" title="Automated traffic">

Unrecognized bots and uptime monitors that send `GET` requests count the same as shopper page views. To keep your own monitoring and automated traffic from using your allowance, see [Keep automated traffic from counting](/setup/launch/measure-content-requests/#keep-automated-traffic-from-counting).

</Aside>

## Shopping actions and Commerce API calls

Shopping actions that only send Commerce API calls don't count. Examples include filtering products on a search or category page, adding to the cart on a product page, and placing an order on the checkout page. They send calls to Adobe Commerce, not AEM, and don't load a new page. Any action that opens a new page counts, such as going from the cart to checkout. Hovering over a link can count too, if it [prerenders](#prerendered-pages) the linked page.

## Prerendered pages

A prerendered page is one that is loaded in advance, before the shopper actually opens it. This technique improves perceived performance when navigating between pages, because the content is ready the moment it's requested. To make that possible, the storefront asks browsers to load linked pages ahead of time, for example, when the pointer rests on a product link.

<Aside type="tip" title="You control prerendering">

Home, category, and search pages have many links that can trigger prerendering. Your storefront team can adjust which links qualify and when prerendering starts, or remove the storefront's prerender rule in `head.html`. Compare navigation speed and content request usage when changing these settings. See the <Link href="https://developer.chrome.com/docs/web-platform/prerender-pages#the-speculation-rules-api" text="Chrome speculation rules documentation" />.

</Aside>

### Calculating prerendered content requests

A shopper opens a category page, hovers over products A and B, and then opens B. Both prerenders finish, and each uses 1.2 content requests. Opening B uses its prerendered copy, so only A adds content requests.

<Diagram
  adaptColors
  caption="Prerendering product B costs the same as a normal page view of B. Product A's unopened prerender is the extra cost."
>
  ![A four-step shopper journey. Step 1, the shopper opens a category page, a regular page view. Step 2, the shopper hovers over product A, which is prerendered, never opened, and uses 1.2 content requests. Step 3, the shopper hovers over product B, which is prerendered and uses 1.2. Step 4, the shopper opens product B, and the browser uses the prerendered copy, which adds 0. Product B totals 1.2 plus 0, which equals 1.2, the same as a normal page view. Product A's prerender adds 1.2 extra content requests.](./images/prerender-journey.png)
</Diagram>

- *Counted once:* Product B was prerendered and then opened, so it costs the same as a normal page view.
- *Extra cost:* Product A was never seen, but its prerender adds 1.2 content requests.
- *Not a forecast:* This short example shows the counting rule. To estimate your storefront's average, [measure unopened prerendered pages](/setup/launch/measure-content-requests/#unopened-prerendered-pages).

## Key takeaways

<TableWrapper>

| Activity | Content requests |
| --- | --- |
| Opening a page, including the cart and checkout pages | 1 |
| Loading a JSON data file that counts, such as the index file | 0.2 |
| Prerendering a page, whether or not the shopper opens it | 1, plus 0.2 for each JSON file that counts. Not counted again if opened. |
| Pages loaded by unrecognized bots and uptime checks | 1, plus 0.2 for each JSON file that counts |
| Filtering products, adding to the cart, updating the cart, or placing an order | 0 |
| Images, styles, scripts, navigation, and footer | 0 |
| Well-known search, social, and AI crawlers | 0 |
| Redirects and errors | 0 |

</TableWrapper>

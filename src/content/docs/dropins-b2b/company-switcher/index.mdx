## What does this drop-in do?

The Company Switcher drop-in enables B2B users with access to multiple companies to seamlessly switch between different company contexts within the Adobe Commerce storefront. It provides a single UI container for selecting the active company, which then ensures that all subsequent B2B operations (such as viewing company data, managing requisitions, requesting quotes) are performed within the correct company's scope.

The drop-in integrates with Adobe Commerce's multi-company and company hierarchy features, ensuring that user permissions and data are correctly isolated and applied based on the active company context. It is essential for B2B buyers and administrators who operate across multiple company accounts and need to maintain distinct operational environments.

## Section topics

The topics in this section will help you understand how to customize and use the Company Switcher effectively within your storefront.

### Quick Start

Provides quick reference information and getting started guide for the Company Switcher drop-in. This topic covers package details, import paths, and basic usage examples to help you integrate Company Switcher functionality into your site.

### Initialization

Explains how to initialize the Company Switcher drop-in with configuration options including language definitions for internationalization and custom data models for type transformations. The initializer provides runtime configuration for company context management and automatic GraphQL header synchronization.

### Containers

Describes the single UI container CompanySwitcher which provides a dropdown interface for selecting the active company from available company accounts. The container handles authentication requirements, displays the current company context, and triggers company context changes when users select a different company.

### Functions

Documents the 3 API functions for managing company context including retrieving customer company context (`customerCompanyContext`), setting company-specific GraphQL headers (`setCompanyHeaders`), and setting customer group headers (`setGroupHeaders`). These functions work together to ensure all API requests are scoped to the correct company and customer group.

### Events

Explains the `companyContext/changed` event which is emitted whenever the active company context switches. This critical event triggers data refreshes across all B2B containers (purchase orders, quotes, requisition lists, company management) and ensures proper data isolation. Other drop-ins listen to this event to reload their data within the new company scope.

### Slots

Describes the customization slots available in the CompanySwitcher container for customizing the company selection dropdown appearance, company name display, and switcher trigger element. Slots enable custom rendering of company information and integration with custom UI frameworks.

### Dictionary

Documents the internationalization (i18n) keys used in the Company Switcher container for labels, messages, and prompts. Includes translations for the switcher dropdown, company selection interface, current company indicator, and empty states for users without multiple companies.

### Styles

Explains how to customize the visual appearance of the Company Switcher container using CSS classes and design tokens. Covers styling for the switcher dropdown, company list items, selected company indicator, dropdown trigger, and responsive behavior.

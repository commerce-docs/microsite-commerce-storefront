## Event details

### companyContext/changed

Emitted when the user switches to a different company or when the company context is initially established. This event signals that all company-specific data should be refreshed.

#### Event payload

```typescript
string | null | undefined
```

The event payload is the company ID (as a string) when a company is selected, or `null`/`undefined` when the company context is removed.

#### When triggered

- After user selects a different company from the switcher
- On initial page load when company context is established
- After successful company context update
- When company headers are set via `setCompanyHeaders()`
- When company headers are removed by passing `null` to `setCompanyHeaders()`

#### Example

```js
import { events } from '@dropins/tools/event-bus.js';

events.on('companyContext/changed', (companyId) => {
  if (companyId) {
    console.log(`Company context changed to: ${companyId}`);
    
    // Refresh all company-specific data
    refreshCompanyData(companyId);
    
    // Update permissions for new company
    refreshUserPermissions();
    
    // Reload company-specific UI components
    reloadCompanyDependentData();
    
    // Track analytics
    trackCompanySwitch(companyId);
  } else {
    console.log('Company context removed');
    
    // Clear company-specific caches
    clearCompanyCache();
  }
});
```

#### Usage scenarios

- Refresh company-specific data across the application
- Update user permissions for the new company context
- Reload company-dependent drop-ins (Purchase Order, Quote Management, etc.)
- Clear cached data from previous company
- Update navigation and menu items based on new company
- Track company switching behavior in analytics
- Update session storage or cookies
- Refresh company structure and hierarchy displays
- Update approval rules and workflows
- Reload requisition lists for new company

## Listening to events

The Company Switcher event is emitted through the centralized event bus:

```js
import { events } from '@dropins/tools/event-bus.js';

// Listen for company context changes
const handleCompanyChange = async (payload) => {
  const { companyId, companyName } = payload.data;
  
  // Show loading state
  showLoadingIndicator('Switching to ' + companyName);
  
  // Refresh all company-dependent data
  await Promise.all([
    refreshUserPermissions(),
    refreshCompanyData(companyId),
    refreshPurchaseOrders(),
    refreshQuotes(),
    refreshRequisitionLists()
  ]);
  
  // Hide loading state
  hideLoadingIndicator();
  
  // Show success message
  showSuccess(`Switched to ${companyName}`);
};

events.on('companyContext/changed', handleCompanyChange);

// Clean up when component unmounts
events.off('companyContext/changed', handleCompanyChange);
```

<Aside type="caution" title="Critical Integration Point">
The `companyContext/changed` event must be handled by all company-specific features in your storefront. Failing to refresh data after this event can lead to displaying data from the wrong company, which is a serious security and data integrity issue.
</Aside>

<Aside type="tip">
Consider implementing a global loading state when the company context changes, as multiple data refreshes may be triggered. This provides better user experience during the transition.
</Aside>

## Boilerplate Integration Patterns

The Adobe Commerce boilerplate uses a simple, decentralized approach where each component independently handles company context changes. Here are the actual patterns from the `b2b-integration` branch:

### Pattern 1: Quote Management Page

When switching companies, clear the current quote and reload:

```js
import { events } from '@dropins/tools/event-bus.js';

// Listen for company context changes
events.on('companyContext/changed', () => {
  // Clear quoteid from URL
  const url = new URL(window.location.href);
  url.searchParams.delete('quoteid');
  
  // Update URL and reload page
  window.history.replaceState({}, '', url.toString());
  window.location.href = url.toString();
});
```

**Source**: `blocks/commerce-b2b-negotiable-quote/commerce-b2b-negotiable-quote.js`

**Why this works**: Quotes are company-specific. A full page reload with cleared state ensures the quote list renders correctly for the new company.

### Pattern 2: Account Navigation

Reset authentication cache and refresh permissions:

```js
import { events } from '@dropins/tools/event-bus.js';

// Force a refresh of the permissions when company changes
events.on('companyContext/changed', () => {
  import('@dropins/storefront-auth/api.js').then((module) => {
    module._resetCache();
    module.getCustomerRolePermissions();
  });
});
```

**Source**: `blocks/commerce-account-nav/commerce-account-nav.js`

**Why this works**: Permissions are company-specific. Clearing the auth cache ensures fresh permission data is fetched for the new company context.

### Pattern 3: Product Search/List Pages

Re-run search with current filters:

```js
import { events } from '@dropins/tools/event-bus.js';

// Listen for company context changes and reload search data
events.on('companyContext/changed', async () => {
  await performInitialSearch(config, {
    q,
    page,
    sort,
    filter
  });
});
```

**Source**: `blocks/product-list-page/product-list-page.js`

**Why this works**: Product availability and pricing may differ by company. Re-running the search ensures correct company-specific results.

### Pattern 4: Company Roles & Permissions Page

Automatically refresh data and manage form states:

```js
import { events } from '@dropins/tools/event-bus.js';

// Listen via useCompanyContextListener hook
events.on('companyContext/changed', async () => {
  // Reset to first page
  setCurrentPage(1);
  
  // Refresh roles data for new company
  await refreshRolesData();
  
  // Handle form states intelligently:
  // - Keep create/duplicate forms open (preserved data)
  // - Close edit forms (role doesn't exist in new company)
  // - Close delete modals (for safety)
  manageFormStates();
});
```

**Source**: `blocks/commerce-company-roles-permissions/` (via hooks)

**Why this works**: Company roles are company-specific. Smart form management prevents confusion when switching contexts while editing.

### Complete Example: Company Switcher Dropdown

Here's how to implement a company switcher using the boilerplate pattern:

```js
import { events } from '@dropins/tools/event-bus.js';
import { setCompanyHeaders } from '@dropins/storefront-company-switcher/api.js';

// Initialize company switcher dropdown
function initCompanySwitcher() {
  const dropdown = document.querySelector('#company-selector');
  
  dropdown.addEventListener('change', (e) => {
    const companyId = e.target.value;
    const companyName = e.target.selectedOptions[0].text;
    
    // Set company headers - this emits companyContext/changed event
    setCompanyHeaders(companyId);
    
    // Optional: Show loading indicator
    document.body.classList.add('switching-company');
  });
}

// Initialize on page load
initCompanySwitcher();
```

Each page/component that needs to react will handle `companyContext/changed` independently using one of the patterns above.

## Best practices

### 1. Keep it simple and focused

Each component should handle only its own refresh logic. The boilerplate demonstrates that simple, decentralized event handling is easier to maintain than complex orchestration.

```js
// Good: Component handles its own specific needs
events.on('companyContext/changed', async () => {
  await refreshMyComponentData();
});

// Avoid: Over-engineering with complex coordinators
// (unless you have specific requirements for it)
```

### 2. Use page reloads for complex state

For pages with complex state (like quote details), a full page reload is simpler and more reliable:

```js
events.on('companyContext/changed', () => {
  // Clear page-specific parameters
  const url = new URL(window.location.href);
  url.searchParams.delete('id');
  
  // Reload with clean state
  window.location.href = url.toString();
});
```

### 3. Reset caches appropriately

Different modules may cache company-specific data. Reset only what you need:

```js
events.on('companyContext/changed', () => {
  // Import and reset only the module you need
  import('@dropins/storefront-auth/api.js').then((module) => {
    module._resetCache();
  });
});
```

### 4. Handle errors gracefully

Always handle potential errors during refresh:

```js
events.on('companyContext/changed', async () => {
  try {
    await refreshMyData();
  } catch (error) {
    console.error('Failed to refresh:', error);
    // Optionally show user-friendly message
    showErrorToast('Please refresh the page');
  }
});
```

### 5. Provide visual feedback

Show users that something is happening during company switches:

```js
const dropdown = document.querySelector('#company-selector');

dropdown.addEventListener('change', (e) => {
  // Show loading state immediately
  document.body.classList.add('switching-company');
  dropdown.disabled = true;
  
  // Set company headers (triggers the event)
  setCompanyHeaders(e.target.value);
  
  // Optional: Remove loading after a delay or on next event
  setTimeout(() => {
    document.body.classList.remove('switching-company');
    dropdown.disabled = false;
  }, 1000);
});
```

Shoppers can now pick their own free gift in the cart, instead of getting one added automatically. They can also pay with Google Pay or PayPal Buttons, along with credit cards and Apple Pay. Apple Pay now supports coupon codes. Shoppers can also save items across more than one wishlist. B2B buyers can use a shared company address book across account management, checkout, and quotes. See the [changelog](/releases/changelog/) for the full list of changes.

<Aside type="caution" title="Breaking changes">
There are no breaking changes in this release suite.
</Aside>

## Highlights

These highlights describe changes for shoppers and merchants. For the matching APIs, props, and versions, see [Updated Drop-in SDK](#updated-drop-in-sdk) and the [B2C](#updated-b2c-drop-in-components) and [B2B](#updated-b2b-drop-in-components) component tables.

### Free gift selection in cart and checkout

Shoppers can now pick their own free gift in the cart, instead of getting one added automatically. This happens whenever their cart qualifies for a "Free Gift" cart price rule, a discount that adds a free item to qualifying orders. They choose the gift in the cart and complete the order at checkout. Order history and returns show the gift at zero price with a "Free Gift" label, so it doesn't look like a pricing error.

### New payment options: Google Pay and PayPal Buttons

Shoppers can now pay with Google Pay or PayPal Buttons, along with credit cards and Apple Pay. Apple Pay also supports coupon codes. The Payment Services drop-in moves to a new major version, 4.2.1 (up from 3.1.2). Existing credit card and Apple Pay integrations don't need any changes.

### Multiple named wishlists per shopper

Shoppers can now create more than one wishlist, instead of only the default one. They can add products to a specific list. For example, keeping a gift list separate from a save-for-later list. Guest wishlists can now stay saved for a set time, so a shopper who isn't signed in still finds their saved items on a later visit.

### Accessibility improvements across drop-ins

Screen readers and keyboards now work better in cart, account, and search. This helps you meet accessibility rules and helps more shoppers finish checkout.

### B2B Company Address Book

B2B buyers can now manage a shared [company address book](/dropins-b2b/company-management/company-address-book/). They can use those saved addresses across account management, checkout, and quotes, instead of only their own personal addresses. Company Administrators turn the feature on or off from the Company Profile page and choose whether custom shipping addresses are still allowed. Permissions based on each buyer's role control who can view, add, edit, or delete company addresses.

### B2B reCAPTCHA protection for company registration

reCAPTCHA verification on the company registration form (the "create company" form) now needs an explicit opt-in, instead of running by default. This fixes a bug where the always-on check failed on backends without B2B enabled.

<Aside type="note" title="Action required (B2B)">
After upgrading, B2B storefronts must pass `{ b2bEnabled: true }` to the reCAPTCHA `setConfig()` call to keep verifying company registration submissions.
</Aside>

## Updated boilerplate

### Infrastructure

- **Drop-in SDK**: `@dropins/tools` upgraded to 2.1.0. See [Updated Drop-in SDK](#updated-drop-in-sdk) for sub-package versions.

### Fixes and improvements

- **Mini cart**: Defers loading the mini cart's fragment until a shopper opens the cart panel, reducing unnecessary requests and rate-limit errors ([#1387](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1387), B2C) ([#1389](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1389), B2B).
- **Product recommendations**: Fixed a bug where adding a recommended item to the cart overwrote the "current SKU" anchor used to generate recommendations. Suggestions now stay accurate after a shopper updates the cart ([#1403](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1403)).

## Updated Drop-in SDK

<Aside type="note" title="Internal links">
Many links on this page point to private Adobe Commerce repositories, such as `adobe-commerce/storefront-cart` and `adobe-commerce/StorefrontSDK`. Those links resolve only if you have access to the repository.
</Aside>

The Drop-in SDK (`@dropins/tools`) was upgraded to 2.1.0 in this release. The following sub-packages were also updated:

| Package | Version |
|---------|---------|
| `@adobe-commerce/elsie` | 2.1.0 |
| `@adobe-commerce/recaptcha` | 1.3.0 |

- **New features**: The Incrementer component now accepts an optional `label` prop that renders a visible `<label>` element connected to the input ([#260](https://github.com/adobe-commerce/StorefrontSDK/pull/260), [#295](https://github.com/adobe-commerce/StorefrontSDK/pull/295)). A new `LiveRegion` component lets you announce status changes to screen readers. New `loading` and `loadingLabel` props on `Button` announce loading state the same way ([#260](https://github.com/adobe-commerce/StorefrontSDK/pull/260)). New `sanitizeHtml` and `createSanitizedHtml` helpers use DOMPurify to remove unsafe code from untrusted HTML before you render it ([#300](https://github.com/adobe-commerce/StorefrontSDK/pull/300)).
- **Improvements and fixes**: You can now configure reCAPTCHA form types with a `b2bEnabled` flag ([#287](https://github.com/adobe-commerce/StorefrontSDK/pull/287)). See [B2B reCAPTCHA protection for company registration](#b2b-recaptcha-protection-for-company-registration) above. Accessibility fixes:
  - `Incrementer` no longer flickers when a server value arrives while a shopper is typing ([#217](https://github.com/adobe-commerce/StorefrontSDK/pull/217)). It also no longer triggers an unwanted update when keyboard focus moves to its buttons, and now exposes `aria-valuetext` for VoiceOver ([#288](https://github.com/adobe-commerce/StorefrontSDK/pull/288)).
  - `Modal` now hides the rest of the page from assistive technology while open, so screen reader users can't navigate outside the dialog ([#254](https://github.com/adobe-commerce/StorefrontSDK/pull/254)).
  - Active pagination buttons announce their state correctly and have higher-contrast focus indicators ([#259](https://github.com/adobe-commerce/StorefrontSDK/pull/259)).
  - `PasswordStatusIndicator` now announces requirement changes as they happen ([#261](https://github.com/adobe-commerce/StorefrontSDK/pull/261)).
  - `InputPassword` and `Field` now have clearer accessible names and correctly associate error messages with their inputs ([#291](https://github.com/adobe-commerce/StorefrontSDK/pull/291)).
  - Disabled buttons and progress spinners now have higher-contrast states ([#294](https://github.com/adobe-commerce/StorefrontSDK/pull/294)).
  - `RadioButton`'s focusable input stays anchored to its visible label when the page scrolls ([#298](https://github.com/adobe-commerce/StorefrontSDK/pull/298)).

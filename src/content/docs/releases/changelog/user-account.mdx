## User Account v4.2.0

The User Account drop-in has been updated with the following changes:

**New features**
- **B2B company address book**: `Addresses` and `AddressForm` containers gain full CRUD support for a shared company address book, with role-based permission gating (6 capabilities), B2B shipping/billing semantics, and a new `contextMode` prop (`addressBook`/`checkout`). Address nicknames are now also supported for B2C addresses. All new container props are optional; containers behave exactly as before when B2B is not enabled ([#131](https://github.com/adobe-commerce/storefront-account/pull/131)).
- **Order history search**: Shoppers can search order history by order number, product name, or SKU, with a new accessible clear button ([#128](https://github.com/adobe-commerce/storefront-account/pull/128), [#133](https://github.com/adobe-commerce/storefront-account/pull/133)).

**Fixes**
- **Hot-fix**: Restored independent default-shipping/default-billing checkboxes, save-checkbox placement, and correct address preselection for personal (B2C) addresses — regressions introduced by the company address book work ([#138](https://github.com/adobe-commerce/storefront-account/pull/138)).
- **Accessibility**: Descriptive `aria-label`s on Edit/Change-password buttons and scroll-margin fixes for keyboard focus, WCAG 2.4.11 ([#132](https://github.com/adobe-commerce/storefront-account/pull/132)). Customer Orders list date-picker label fix, WCAG 2.5.3, order-list semantic `<ul>/<li>` markup, WCAG 1.3.1, and a persistent live region for loading states, WCAG 4.1.3 ([#134](https://github.com/adobe-commerce/storefront-account/pull/134), [#129](https://github.com/adobe-commerce/storefront-account/pull/129)).

## User Account v4.0.0

**New features**
- **Seller Assisted Buying containers**: Two new containers support the seller-assisted buying capability: [`SellerAssistedBuyingActivity`](/dropins/user-account/containers/seller-assisted-buying-activity/) renders a log of assisted-buying sessions for the customer, and [`SellerAssistedBuyingSettings`](/dropins/user-account/containers/seller-assisted-buying-settings/) lets customers enable or revoke administrator assistance. Orders placed by a store administrator on behalf of a customer are marked with an "Order placed by an administrator" label on the order details page. Backed by the new `getAdminAssistanceActions` GraphQL API. See [Seller-assisted buying](/dropins/user-account/containers/seller-assisted-buying/) for setup details ([#1283](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1283)).

**Infrastructure**
- **Node.js 22 LTS**: The package now builds and distributes using Node.js 22 LTS. The `engines.node` constraint has been removed as this drop-in targets browser environments exclusively.

## User Account v3.3.0

The User Account drop-in has been updated with the following changes:

**Stored payment methods**
- **PaymentMethods container**: Shoppers can view all saved payment methods from their account page. The new `PaymentMethods` container displays stored cards with brand, masked number, and expiry status. Cards can be filtered by payment method code and shown in full or minified layout ([#57](https://github.com/adobe-commerce/storefront-account/pull/57)).
- **Delete stored card with confirmation**: Removing a stored payment method now shows a confirmation modal with a card preview before deleting. The modal prevents accidental deletion and disables row actions during an active removal operation ([#58](https://github.com/adobe-commerce/storefront-account/pull/58)).
- **PaymentCard component**: New `PaymentCard` component renders a single payment method with card type, masked number, and an optional EXPIRED tag ([#51](https://github.com/adobe-commerce/storefront-account/pull/51)).

**Address and customer attributes**
- **fieldIdPrefix on Addresses container**: The `fieldIdPrefix` prop is now correctly forwarded to the internal address form. This prevents duplicate field IDs when shipping and billing address forms are rendered on the same page ([#55](https://github.com/adobe-commerce/storefront-account/pull/55)).
- **Customer dropdown attribute prefill**: Customer custom attributes implemented as select/dropdown fields now correctly prefill their saved values from the API. Date-only fields are formatted without timezone shift ([#56](https://github.com/adobe-commerce/storefront-account/pull/56)).

## User Account v3.0.0

**Major version upgrade** with B2B company context support and translation improvements. The User Account drop-in has been updated to include the following changes:

**New features**

- **Company context switching** - Order history now automatically refreshes when B2B users switch companies via the `companyContext/changed` event. This ensures users only see orders relevant to their current company context without manual page refresh ([#25](https://github.com/adobe-commerce/storefront-account/pull/25)).
- **Translation override support** - The Provider component now supports merging custom language definitions with default translations. Developers can pass custom `langDefinitions` through the initialize configuration to override default UI text, enabling easier localization and brand-specific terminology ([#30](https://github.com/adobe-commerce/storefront-account/pull/30)).

**Improvements**

- **Fixed configurable product links** - Product URLs in order history now correctly link to configurable product detail pages. The GraphQL query now retrieves `product_sku` and `product_url_key` at the order item level instead of nested product fields, resolving 404 errors when clicking product links from order lists ([#34](https://github.com/adobe-commerce/storefront-account/pull/34)).
- **Elsie SDK upgrade** - Updated to Elsie SDK 1.6.0, bringing pagination SEO enhancements, improved price formatting utilities, table component mobile responsiveness improvements, enhanced field component rendering, and icon stroke width fixes.
- **GraphQL fetch upgrade** - Updated to @adobe-commerce/fetch-graphql 1.2.3 for improved GraphQL query handling and better header management.
- **reCAPTCHA upgrade** - Updated to @adobe-commerce/recaptcha 1.0.3 for improved security and compatibility.
- **Revised Adobe Commerce Drop-in License Agreement** - Updated license agreement to current terms. B2C drop-ins have been tested on Adobe Commerce as a Cloud Service (ACCS) and Adobe Commerce 2.4.7+ for Platform-as-a-Service (PaaS) deployments. However, the license agreement restricts use to Adobe Commerce as a Cloud Service (ACCS) and Adobe Commerce Optimizer (ACO) only. Use on Platform-as-a-Service (PaaS) or on-premise deployments is not permitted under the license agreement.

## User Account v1.0.9

The User Account drop-in has been updated to include the following changes:

- **Fixed empty order list**: Resolved an issue where the entire order list would appear empty when a customer had an order containing out-of-stock products, even if other valid orders existed.
- **Added grandTotalExclTax field support**: Added support for the `grandTotalExclTax` field and updated the Order confirmation to use it instead of computing `order?.grandTotal?.value - order?.totalTax?.value` in the frontend. When the order total is FREE, the "Total excluding taxes" line is now omitted, preventing negative excluding-tax totals on zero-total orders.

## User Account v1.0.7

**Fix for empty radio button**

{/* USF-2322 */}

We fixed an issue that was causing an empty radio button in the checkout shipping section when customers had no saved addresses. Now, the radio button only displays if the customer is logged in and has at least one saved address, ensuring a cleaner and more intuitive checkout experience.

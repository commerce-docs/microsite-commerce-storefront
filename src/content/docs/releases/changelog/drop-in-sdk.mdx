## Drop-in SDK (Elsie) v2.1.0

<Aside type="note" title="Internal Links">
  Links to the StorefrontSDK repository do not resolve unless you have access to that repository.
</Aside>

**New features**
- **Incrementer label**: The Incrementer component now accepts an optional `label` prop that renders a visible `<label>` element associated with the input field, addressing WCAG 3.3.2 ([#295](https://github.com/adobe-commerce/StorefrontSDK/pull/295)).
- **`LiveRegion` component and `Button` loading state**: A new `LiveRegion` component announces status changes to screen readers without moving focus. `Button` gains `loading` and `loadingLabel` props to announce in-progress actions (WCAG 4.1.3) ([#260](https://github.com/adobe-commerce/StorefrontSDK/pull/260)).
- **HTML sanitization helpers**: New `sanitizeHtml` and `createSanitizedHtml` helpers, backed by DOMPurify, make it safer to render untrusted HTML via `dangerouslySetInnerHTML` ([#300](https://github.com/adobe-commerce/StorefrontSDK/pull/300)).

**Improvements and fixes**
- **reCAPTCHA**: Form types are now configurable via a `b2bEnabled` flag. `COMPANY_CREATE` is no longer in the default form-type map; B2B storefronts must pass `{ b2bEnabled: true }` to `setConfig()` to include it and keep verifying company registration submissions ([#287](https://github.com/adobe-commerce/StorefrontSDK/pull/287)).
- **Accessibility**:
  - `Incrementer` no longer flickers when a server value arrives while a shopper is typing ([#217](https://github.com/adobe-commerce/StorefrontSDK/pull/217)), and no longer triggers a spurious update when keyboard focus moves to its buttons, now exposing `aria-valuetext` for VoiceOver ([#288](https://github.com/adobe-commerce/StorefrontSDK/pull/288)).
  - `Modal` hides sibling page content from assistive technology while open, so screen reader users can't navigate outside the dialog ([#254](https://github.com/adobe-commerce/StorefrontSDK/pull/254)).
  - Active pagination buttons announce their state correctly and use a higher-contrast focus indicator ([#259](https://github.com/adobe-commerce/StorefrontSDK/pull/259)).
  - `PasswordStatusIndicator` requirement changes are now announced as they happen ([#261](https://github.com/adobe-commerce/StorefrontSDK/pull/261)).
  - `InputPassword` and `Field` accessible names and error associations ([#291](https://github.com/adobe-commerce/StorefrontSDK/pull/291)).
  - Higher-contrast disabled button and progress spinner states ([#294](https://github.com/adobe-commerce/StorefrontSDK/pull/294)).
  - `RadioButton`'s focusable input stays anchored to its visible label when the page scrolls ([#298](https://github.com/adobe-commerce/StorefrontSDK/pull/298)).

## Drop-in SDK (Elsie) v2.0.0

<Aside type="note" title="Internal Links">
  Links to the StorefrontSDK repository do not resolve unless you have access to that repository.
</Aside>

**Breaking changes**
- **TypeScript 6.0 and ESLint 9**: The SDK's TypeScript toolchain moves from 4.7 to 6.0, and ESLint moves from 8 to 9 with flat config. If you extend the shared `@adobe-commerce/elsie/config/eslint` configuration, migrate your own `.eslintrc.js` to a flat-config `eslint.config.js`, add `"type": "module"` to `package.json`, and rename `.elsie.js` to `.elsie.cjs`. See the migration guide in the StorefrontSDK repository for the full list of steps ([#215](https://github.com/adobe-commerce/StorefrontSDK/pull/215)).

**New features**
- **Incrementer validation**: The Incrementer component now validates the field when its value is cleared ([#204](https://github.com/adobe-commerce/StorefrontSDK/pull/204)).
- **`DROPINS.showOverlays()`**: A new developer utility outlines every drop-in container and slot on the page with labeled overlays, making it easier to see how a storefront page is composed at runtime. `DROPINS.showSlots()` is deprecated in its favor ([#208](https://github.com/adobe-commerce/StorefrontSDK/pull/208)).
- **Cypress ESLint config**: A new optional `cypress` export from the shared ESLint config provides pre-configured flat-config rules for Cypress test files ([#238](https://github.com/adobe-commerce/StorefrontSDK/pull/238)).
- **`elsie changeset` CLI command**: Wraps `@changesets/cli` as a first-class `elsie` command, so you no longer need to install `@changesets/cli` separately ([#239](https://github.com/adobe-commerce/StorefrontSDK/pull/239)).

**Improvements and fixes**
- **Testing tools**: Jest upgraded to 30.4.2 and Storybook to 10.4.0 ([#205](https://github.com/adobe-commerce/StorefrontSDK/pull/205)).
- **`@adobe-commerce/event-bus`**: Added a TypeScript return type for `events.lastPayload` ([#216](https://github.com/adobe-commerce/StorefrontSDK/pull/216)).
- **Accessibility**:
  - `Picker` no longer leaves Add to Cart permanently disabled after single-option narrowing on configurable PDPs ([#219](https://github.com/adobe-commerce/StorefrontSDK/pull/219)).
  - Accessible labels on password validation icons ([#220](https://github.com/adobe-commerce/StorefrontSDK/pull/220)).
  - `Picker`'s accessible name and label association ([#233](https://github.com/adobe-commerce/StorefrontSDK/pull/233)).
  - Screen reader announcements for `Field` and `InLineAlert` status and error messages ([#253](https://github.com/adobe-commerce/StorefrontSDK/pull/253)).
  - Unique accessible names for `InLineAlert` action buttons ([#242](https://github.com/adobe-commerce/StorefrontSDK/pull/242)).
  - Focus management and dialog semantics in `Modal` ([#244](https://github.com/adobe-commerce/StorefrontSDK/pull/244)).
  - `ToggleButton`'s accessible name ([#246](https://github.com/adobe-commerce/StorefrontSDK/pull/246)) and invalid HTML ids when its value contains spaces ([#262](https://github.com/adobe-commerce/StorefrontSDK/pull/262)).
  - Higher-contrast keyboard focus indicators across Button, Checkbox, RadioButton, and other interactive components.
- **`InputDate`**: Fixed the input showing the wrong format after selecting a date from the calendar.

## Drop-in SDK (Elsie) v1.9.0

<Aside type="note" title="Internal Links">
  Links to the StorefrontSDK repository do not resolve unless you have access to that repository.
</Aside>

**Improvements and fixes**
- **Bundle optimizations**: Lazy icon loading and code consolidation significantly reduce the number of HTTP requests on page load across all drop-ins. The Preact runtime is now isolated into its own vendor chunk. API functions, icons, and internal components are consolidated into `chunks/api.js`, `chunks/icons.js`, and `chunks/components.js` respectively. Measured reductions: Drop-in tools −29% (34→24 requests), Auth drop-in −75% (24→6), Cart drop-in −85% (13→2). TTI improved 22% on average. Drop-ins must be rebuilt against this SDK release to benefit ([#200](https://github.com/adobe-commerce/StorefrontSDK/pull/200)).
- **Node.js 22 LTS**: The SDK and all drop-ins have been updated to require Node.js 22 LTS as the minimum build runtime ([#201](https://github.com/adobe-commerce/StorefrontSDK/pull/201)).
- **GraphQL fragment bundling fix**: GraphQL fragment files are no longer incorrectly swept into `chunks/api.js`, which would break the boilerplate's GraphQL override mechanism that depends on fragment strings being present in the standalone `fragments.js` output ([#210](https://github.com/adobe-commerce/StorefrontSDK/pull/210)).

## Drop-in SDK (Elsie) v1.6.0

<Aside type="note" title="Internal Links">
  Links to the StorefrontSDK repository do not resolve unless you have access to that repository.
</Aside>

The Drop-in SDK (Elsie) has been updated to include several new features and improvements:

**New features:**

- **Pagination SEO enhancements** - Pagination components now support a `routePage` prop that generates anchor tags instead of buttons, enabling proper SEO with crawlable page links, native browser link behavior (right-click, open in new tab), and improved accessibility while maintaining all existing functionality (<Link href={"https://github.com/adobe-commerce/StorefrontSDK/pull/143"} text={"#143"} />).
- **Price formatting utility** - The new `getPriceFormatter` utility function enables efficient bulk price formatting operations by creating reusable Intl.NumberFormat instances, reducing overhead when formatting multiple prices, and providing centralized locale resolution with proper fallback hierarchy (prop locale → global locale → environment locale → en-US default) (<Link href={"https://github.com/adobe-commerce/StorefrontSDK/pull/129"} text={"#129"} />).
- **New icons** - New icons are now available in the Icon component: Business (company/organization representation), List (list view toggle), Purchase (purchase/buy actions), Quote (quote request actions), Structure (organizational structure), and Team (team/group representation) (<Link href={"https://github.com/adobe-commerce/StorefrontSDK/pull/150"} text={"#150"} />).

**Improvements and fixes:**

- **Table component improvements** - Table components now include enhanced mobile responsiveness with automatic stacked layout via container queries, data labels automatically generated from column headers on mobile, improved styling for row details and expanded states, better typography hierarchy in mobile view, and enhanced visual structure with proper borders and spacing (<Link href={"https://github.com/adobe-commerce/StorefrontSDK/pull/149"} text={"#149"} />).
- **Field component enhancements** - Field components now provide more robust child component rendering, improving support for wrapped components and complex field structures with better prop propagation (<Link href={"https://github.com/adobe-commerce/StorefrontSDK/pull/139"} text={"#139"} />).
- **Icon stroke width fix** - Icon components now properly apply stroke width styles to all nested SVG elements, ensuring consistent visual appearance across all icon types instead of only applying to the root SVG element (<Link href={"https://github.com/adobe-commerce/StorefrontSDK/pull/151"} text={"#151"} />).
- **Multi-store detection fix** - Fixed incorrect multi-store detection in repoless EDS setups where configurations with additional non-store keys under the `public` namespace were incorrectly identified as multi-store configurations. This caused the Store Switcher to activate unnecessarily, resulting in rendering errors such as footer not loading due to missing store-switcher fragment. The detection logic now properly distinguishes actual store entries from other configuration keys (<Link href={"https://github.com/adobe-commerce/StorefrontSDK/pull/156"} text={"#156"} />).
- **FetchGraphQL instance linking** - FetchGraphQL instances can now link to or inherit configuration from other instances, enabling shared endpoint, header, and hook management across multiple instances. This reduces configuration duplication when creating multiple API clients with similar settings and provides better architecture for complex drop-in implementations. When an instance is linked to another, it delegates all configuration operations (setEndpoint, setFetchGraphQlHeader, addBeforeHook, addAfterHook) to the linked instance, ensuring consistent behavior across related API clients (<Link href={"https://github.com/adobe-commerce/StorefrontSDK/pull/145"} text={"#145"} />, <Link href={"https://github.com/adobe-commerce/StorefrontSDK/pull/147"} text={"#147"} />, <Link href={"https://github.com/adobe-commerce/StorefrontSDK/pull/148"} text={"#148"} />).

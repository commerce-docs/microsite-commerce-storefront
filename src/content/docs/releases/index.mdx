<Aside type="note" title="What is a suite release?">
A suite release marks a point in time when we have tested the storefront and its drop-in versions end-to-end. It serves as a quality starting point for new implementations. If you have already scaffolded or cloned the storefront, you do not need to "upgrade" to new suite releases — your codebase is your own. Suite releases are not packages and cannot be installed or updated as dependencies. The only dependencies to actively update are your drop-in packages (`@dropins/*`, `@adobe/*`), which follow semantic versioning. Minor and patch versions are non-breaking by contract. Use `npm outdated` to check for available updates.
</Aside>

## Release suites

The following sections provide high-level summaries of each release suite and details about the compatibility between storefront components. To see more details about each drop-in component by version, go to the [changelog](/releases/changelog/).

## June 2026 suite

The Product Recommendations drop-in now accepts a live `currentProduct` value from the Adobe Client Data Layer (ACDL). Recommendation units on a product detail page (PDP) update automatically when shoppers change variants — no page reload required. A new `confirmBeforeDelete` prop on `CartSummaryList` and `MiniCart` adds an inline confirmation step before an item is removed, preventing accidental cart deletions. Seller Assisted Buying lets store administrators place and manage orders on behalf of customers (works for both B2B and B2C). B2B storefronts also gain Company Hierarchy (nested team structure browsing) and Requisition List Sharing (share lists with colleagues by email or token), continuing the B2B expansion that began with Quick Order in earlier releases. This release also adds Adobe Commerce 2.4.9 compatibility. See the [changelog](/releases/changelog/) for the full list of changes.

If your implementation relies on specific cookie attributes or cross-domain authentication cookie behavior, review and test your auth flows after upgrading.
- **User Account v4.0.0 — major version bump**: `@dropins/storefront-account` was bumped to v4.0.0 for the [Seller Assisted Buying](/dropins/user-account/containers/seller-assisted-buying/) feature. The new containers ([`SellerAssistedBuyingActivity`](/dropins/user-account/containers/seller-assisted-buying-activity/), [`SellerAssistedBuyingSettings`](/dropins/user-account/containers/seller-assisted-buying-settings/)) and the `getAdminAssistanceActions` API are additive. No existing APIs were removed or changed.
- **Order v4.0.0 — major version bump**: `@dropins/storefront-order` was bumped to v4.0.0 for the Seller Assisted Buying feature. Orders placed by administrators now display a visible label on the order details page. No existing order APIs were removed or changed.
</Aside>

### Highlights

#### Reactive product context for recommendations on PDP

When a shopper selects a variant on a product detail page, recommendation units now update immediately to reflect that selection. The [`ProductList`](/dropins/recommendations/containers/product-list/) container accepts a new `currentProduct` prop (`{ sku, price }`) that the storefront reads from the ACDL `productContext.pricing` event. When this prop is present, the drop-in uses the `GetRecommendationsByUnitIdsWithCurrentProduct` query. Otherwise it falls back to the base query for backward compatibility. The standalone `currentSku` prop is deprecated — use `currentProduct.sku` instead ([#37](https://github.com/adobe-commerce/storefront-recommendations/pull/37), [#1244](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1244)).

#### Cart item deletion with confirmation

A new confirmation step can prevent accidental cart item deletions. Pass `confirmBeforeDelete={true}` to `CartSummaryList` or `MiniCart`: clicking the remove button replaces the item row with an inline confirmation banner with **Remove** and **Cancel** actions. A `ConfirmDeleteBanner` slot is available on both containers for full customization of the confirmation UI ([#138](https://github.com/adobe-commerce/storefront-cart/pull/138)).

#### Company Hierarchy (B2B)

B2B account administrators can now browse and manage their company's hierarchical structure from the storefront. The new `commerce-b2b-company-hierarchy` boilerplate block renders the nested team structure using the [`CompanyHierarchy`](/dropins-b2b/company-management/containers/company-hierarchy/) container from the Company Management drop-in. Users can navigate parent-child company relationships, view member assignments, and understand organizational reporting lines without leaving the storefront. The current implementation supports a single-level hierarchy (parent companies and their direct children). Nested hierarchies are not yet supported ([#1240](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1240), B2B).

#### Requisition List Sharing (B2B)

B2B users can now share requisition lists with colleagues directly from the storefront. The new `commerce-b2b-requisition-list-sharing` block lets users share a list by email or by copying a shareable link. The block uses the [`ShareRequisitionListContent`](/dropins-b2b/requisition-list/containers/share-requisition-list-content/) container. Recipients can view and import shared lists using the new [`SharedRequisitionList`](/dropins-b2b/requisition-list/containers/shared-requisition-list/) container. New APIs from the Requisition List drop-in — `shareRequisitionListByEmail`, `shareRequisitionListByToken`, `getSharedRequisitionList`, `getCompanyUsers`, and `importSharedRequisitionList` — handle the complete sharing workflow ([#1268](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1268), B2B).

#### Seller Assisted Buying

Store administrators can now place and manage orders on behalf of customers directly from the storefront. This feature works for both B2B and B2C stores — sales representatives can assist B2B buyers, and customer support agents can help B2C shoppers. The User Account drop-in v4.0.0 ships two new containers — [`SellerAssistedBuyingActivity`](/dropins/user-account/containers/seller-assisted-buying-activity/) (shows a log of assisted-buying sessions for the customer) and [`SellerAssistedBuyingSettings`](/dropins/user-account/containers/seller-assisted-buying-settings/) (lets customers enable or revoke administrator assistance) — backed by the new `getAdminAssistanceActions` GraphQL API. The boilerplate adds [`commerce-seller-assisted-buying-activity` and `commerce-seller-assisted-buying-settings`](/merchants/blocks/seller-assisted-buying/) blocks, and a banner in the header identifies when a representative is acting on a customer's behalf. See [Seller-assisted buying](/dropins/user-account/containers/seller-assisted-buying/) for the end-to-end flow and setup details ([#1283](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1283)).

Note: Seller-assisted buying is the storefront feature that uses the underlying Adobe Commerce Login as Customer capability, also called Remote Shopping Assistance in Admin settings.

## April 2026 suite

Shoppers can view and remove saved payment cards from their My Account page using the new `PaymentMethods` container in the User Account drop-in. Store administrators can add order comments in Commerce Admin marked as visible on the storefront, and shoppers now see those comments with timestamps in the order details view using the new `OrderComments` container. The Requisition List drop-in gains move and copy items between lists, and the Quick Order drop-in adds consistent configurable-product cart handling. See the [changelog](/releases/changelog/) for the full list of changes.

### Breaking changes

<Aside type="caution" title="Breaking changes">
- **Product Recommendations v4**: The drop-in switches to the `getRecommendationsUnitsByIds` GraphQL query. If you call the legacy `getRecommendations` function directly, update your integration to use the new API before upgrading to v4.
</Aside>

### Highlights

#### Stored payment methods in My Account

Shoppers can view saved payment cards and remove any card they no longer need, all from their My Account page without contacting support. The new `PaymentMethods` container lists stored cards with brand name, masked number, and an EXPIRED badge when applicable. Removing a card requires confirmation in a modal that shows a card preview, preventing accidental deletion. The implementation uses the `customerPaymentTokens` query to list tokens and the `deletePaymentToken` mutation to remove them ([#51](https://github.com/adobe-commerce/storefront-account/pull/51), [#57](https://github.com/adobe-commerce/storefront-account/pull/57), [#58](https://github.com/adobe-commerce/storefront-account/pull/58)).

#### Order Comments visible to shoppers

When a store administrator adds a comment to an order in Commerce Admin and marks it as "Visible on Storefront," shoppers now see that comment — with timestamp and message text — in the order details view. The new `OrderComments` container works for both guest orders (via token) and authenticated customer orders. Add the new `commerce-order-comments` boilerplate block to any order details page to render the view ([#68](https://github.com/adobe-commerce/storefront-order/pull/68), [#87](https://github.com/adobe-commerce/storefront-order/pull/87), [#1210](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1210)).

#### Product Recommendations v4 — catalog view support

The [Product Recommendations](/dropins/recommendations/) drop-in has been updated to a new major version that fixes recommendation units not appearing in multi-catalog setups. The drop-in now uses the `getRecommendationsUnitsByIds` GraphQL query, which correctly respects catalog view scoping so that globally configured recommendation units work across all store views. The previous `getRecommendations` query did not honor catalog view context, causing units to appear blank for stores that use non-default catalog views. Update your integration to use the new API when upgrading ([#34](https://github.com/adobe-commerce/storefront-recommendations/pull/34), [#36](https://github.com/adobe-commerce/storefront-recommendations/pull/36), [#1183](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1183)).

#### Requisition List enhancements

B2B users can now move or copy items between requisition lists without leaving the page, replacing a workflow that previously required adding to one list, navigating to another, and deleting from the first. The Add to List button on the product details page also shows an active state — including a customizable icon — when the current product is already saved in the selected list, so users can see at a glance which lists already contain the product ([#116](https://github.com/adobe-commerce/storefront-requisition-list/pull/116), [#127](https://github.com/adobe-commerce/storefront-requisition-list/pull/127)).

#### Checkout vault payment method support

Developers integrating Payment Services vault can now pass the full `additionalData` payload through `setPaymentMethodOnCart` without custom wiring. The `PaymentMethods` container forwards the complete `additionalData` object from the selected payment slot to the GraphQL mutation, so vault tokens, nonces, and any other method-specific fields are included in the request automatically ([#311](https://github.com/adobe-commerce/storefront-checkout/pull/311)).

## March 2026 suite

This suite includes product details page video support, multi-store wishlist, a configurable PLP page size, custom product attributes on the PLP, Quick Order for B2B, checkout updates (custom shipping method rows and extensible shipping estimates), and boilerplate improvements for navigation, layout, and multi-website cart behavior. For per-component version details, see the [changelog](/releases/changelog/).

### Highlights

#### Product details page video support

The [ProductGallery](/dropins/product-details/containers/product-gallery/) container now supports product videos out of the box. Merchants can display video alongside product images in the gallery carousel, improving product presentation and shopper engagement. Videos can be positioned before or after images. See the [ProductGallery configuration](/dropins/product-details/containers/product-gallery/#videos) for setup (<Link href={"https://github.com/hlxsites/aem-boilerplate-commerce/pull/1100"} text={"#1100"} />).

#### Multi-store wishlist

The Wishlist drop-in now supports multi-store deployments. Pass an optional `storeCode` during [initialization](/dropins/wishlist/initialization/) so wishlist data (localStorage, sessionStorage, and cookies) is scoped per store. This keeps guest and authenticated wishlists isolated between store views while remaining backward compatible for single-store or `'default'` store setups (<Link href={"https://github.com/adobe-commerce/storefront-wishlist/pull/73"} text={"#73"} />, <Link href={"https://github.com/hlxsites/aem-boilerplate-commerce/pull/1139"} text={"#1139"} />).

#### Checkout shipping customization and GraphQL extensibility

The [ShippingMethods](/dropins/checkout/containers/shipping-methods/) container adds a `ShippingMethodItem` slot so you can replace the default per-method UI while keeping the selection wired to the API (<Link href={"https://github.com/adobe-commerce/storefront-checkout/pull/300"} text={"#300"} />). You can also extend the `estimateShippingMethods` payload at build time with `ESTIMATE_SHIPPING_METHOD_FRAGMENT` and `EstimateShippingModel` (<Link href={"https://github.com/adobe-commerce/storefront-checkout/pull/307"} text={"#307"} />). See [Extending the checkout drop-in](/dropins/checkout/extending/).

#### Quick Order for B2B bulk ordering

B2B customers can add products to the cart by SKU or product name in bulk. The new [Quick Order](/dropins-b2b/quick-order/) drop-in has feature parity with Luma Quick Order and Grid Ordering for configurable products. It is integrated into the boilerplate and ready for use on B2B storefronts (<Link href={"https://github.com/hlxsites/aem-boilerplate-commerce/pull/1125"} text={"#1125"} />, <Link href={"https://github.com/hlxsites/aem-boilerplate-commerce/pull/1156"} text={"#1156"} />).

#### Configurable product listing page size

Product listing pages now allow merchants to control how many products appear per page. The page size is configurable via the block configuration and defaults to 9, giving store owners flexibility without code changes (<Link href={"https://github.com/hlxsites/aem-boilerplate-commerce/pull/1143"} text={"#1143"} />). Custom product attributes can be added to the product listing (<Link href={"https://github.com/adobe-commerce/storefront-search-dropin/pull/89"} text={"#89"} />).

#### Correct 404 responses for non-existent pages

Non-existent pages now return a proper server-rendered 404 response. Crawlers and tools receive the correct HTTP status, improving SEO and monitoring accuracy (<Link href={"https://github.com/hlxsites/aem-boilerplate-commerce/pull/1134"} text={"#1134"} />).

#### Layout and B2B enhancements

- Full-width sections and padding-based gutters in columns improve layout flexibility (<Link href={"https://github.com/hlxsites/aem-boilerplate-commerce/pull/1133"} text={"#1133"} />).
- B2B: The View wishlist link now includes the store code prefix in PDP and Cart blocks (<Link href={"https://github.com/hlxsites/aem-boilerplate-commerce/pull/1130"} text={"#1130"} />); cart state is cleared when users switch websites to prevent 403 errors (<Link href={"https://github.com/hlxsites/aem-boilerplate-commerce/pull/1137"} text={"#1137"} />).

## Code changes

Every release includes changes to one or more codebases described in the compatibility section of each release suite. The scope of the change determines whether the MAJOR, MINOR, or PATCH number increases in the application's version according to <Link href={"https://semver.org/"} text={"semantic versioning"} />:

> Given a version number MAJOR.MINOR.PATCH, increment the:
> 
> MAJOR version when you make incompatible API changes  
> MINOR version when you add functionality in a backward-compatible manner  
> PATCH version when you make backward-compatible bug fixes  

### Public API

To determine when we increment the MAJOR version we must define a public API. The public API for drop-in components includes the following:

#### Integration APIs

Integration APIs are functions that are exposed to the storefront application to integrate the drop-in components. These functions are defined in the drop-in SDK and are used by the drop-in components.

| File | Function Signatures |
|---|---|
| `@dropins/tools/fetch-graphql.js` | `setEndpoint`<br/>`setFetchGraphQlHeader`<br/>`removeFetchGraphQlHeader`<br/>`setFetchGraphQlHeaders`<br/>`fetchGraphQl`<br/>`getConfig` |
| `@dropins/tools/event-bus.js` | `on`<br/>`emit`<br/>`lastPayload` |
| `@dropins/tools/initializer.js` | `mountImmediately` |
| `@dropins/tools/lib.js` | `debounce`<br/>`getFormValues`<br/>`getFormErrors`<br/>`classes`<br/>`deepmerge`<br/>`merge`<br/>`generateSrcset` |

#### Slots

Slots are built-in extension points in the drop-in components to add your own UI components and functions. The following table lists the default properties and individual drop-in slots that are available:

| Type | Description |
|---|---|
| Default properties available to all slots: | Function signatures of the following functions:<br/>`prependSibling`<br/>`prependChild`<br/>`replaceWith`<br/>`appendChild`<br/>`appendSibling`<br/>`getSlotElement`<br/>`onChange` |
| | Structure of the [`dictionary`](/dropins/all/labeling/) object |
| Individual drop-in slots | Function signatures as defined elsewhere on this site (for example, <Link href={"https://experienceleague.adobe.com/developer/commerce/storefront/dropins/cart/slots/"} text={"cart slots"} />) |

#### Drop-in design tokens

Drop-in [design tokens](/dropins/all/styling/#design-tokens) are defined in the drop-in SDK and are used by the drop-in components to style the storefront application.

This suite introduces seller-assisted buying for B2B and B2C storefronts, company hierarchy management and requisition list sharing for B2B, reactive recommendations on the PDP, and cart item deletion confirmation. The Drop-in SDK was upgraded to 1.9.0 with significant bundle size reductions. Node.js 22 LTS is now required. See the [changelog](/releases/changelog/) for the full list of changes.

<Aside type="caution" title="Breaking changes">
- **User Auth v4.0.0 — enhanced cookie security**: `@dropins/storefront-auth` v4.0.0 introduces strict `SameSite` protection and proper encoding on all authentication cookies as part of the Remote Shopping Assistance feature. If your implementation relies on specific cookie attributes or cross-domain authentication cookie behavior, review and test your auth flows after upgrading.
- **User Account v4.0.0 — major version bump**: `@dropins/storefront-account` was bumped to v4.0.0 for the [seller-assisted buying](/dropins/user-account/containers/seller-assisted-buying/) feature. The new containers ([`SellerAssistedBuyingActivity`](/dropins/user-account/containers/seller-assisted-buying-activity/), [`SellerAssistedBuyingSettings`](/dropins/user-account/containers/seller-assisted-buying-settings/)) and the `getAdminAssistanceActions` API are additive. No existing APIs were removed or changed.
- **Order v4.0.0 — major version bump**: `@dropins/storefront-order` was bumped to v4.0.0 for the seller-assisted buying feature. Orders placed by administrators now display a visible label on the order details page. No existing order APIs were removed or changed.
</Aside>

## Highlights

### Reactive product recommendations on PDP

When a shopper selects a variant on the PDP, recommendation units update immediately. Pass `currentProduct` (`{ sku, price }`) to the [`ProductList`](/dropins/recommendations/containers/product-list/) container — the storefront reads it from the ACDL `productContext.pricing` event. The standalone `currentSku` prop is deprecated; use `currentProduct.sku` instead ([#37](https://github.com/adobe-commerce/storefront-recommendations/pull/37), [#1244](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1244)).

### Cart item deletion with confirmation

Pass `confirmBeforeDelete={true}` to `CartSummaryList` or `MiniCart` to add an inline Remove / Cancel confirmation before deleting a cart item. Use the `ConfirmDeleteBanner` slot to customize the confirmation UI ([#138](https://github.com/adobe-commerce/storefront-cart/pull/138)).

### Company Hierarchy (B2B)

B2B account administrators can browse and manage their company's hierarchical structure from the storefront. The `commerce-b2b-company-hierarchy` boilerplate block uses the [`CompanyHierarchy`](/dropins-b2b/company-management/containers/company-hierarchy/) container. Supports one level of nesting (parent + direct children); deeper hierarchies are not yet supported ([#1240](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1240)).

### Requisition List Sharing (B2B)

B2B users can share requisition lists by email or shareable link using the `commerce-b2b-requisition-list-sharing` boilerplate block. The [`ShareRequisitionListContent`](/dropins-b2b/requisition-list/containers/share-requisition-list-content/) container handles sharing. Recipients use [`SharedRequisitionList`](/dropins-b2b/requisition-list/containers/shared-requisition-list/) to view and import ([#1268](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1268)).

### Seller-assisted buying (B2B and B2C)

Store administrators can place and manage orders on behalf of customers. Two new User Account containers — [`SellerAssistedBuyingActivity`](/dropins/user-account/containers/seller-assisted-buying-activity/) and [`SellerAssistedBuyingSettings`](/dropins/user-account/containers/seller-assisted-buying-settings/) — let customers view their assisted-buying history and control admin access. A header banner appears when a representative is active. See [Seller-assisted buying](/dropins/user-account/containers/seller-assisted-buying/) for setup details ([#1283](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1283)).

### Adobe Commerce 2.4.9 support (Commerce on Cloud or on-premises)

SCP-4.9+ is now supported for Commerce on Cloud or on-premises with Adobe Commerce Optimizer. Adobe Commerce as a Cloud Service is not yet synchronized with SCP-4.9. Those environments remain on Adobe Commerce 2.4.8-p5. See [Adobe Commerce 2.4.9](/setup/configuration/storefront-compatibility/v249/) for Storefront Compatibility Package details.

### Node.js 22 LTS now required

The Drop-in SDK now requires Node.js 22 LTS as the minimum build runtime. Verify your CI/CD pipeline and local development environment before upgrading ([#201](https://github.com/adobe-commerce/StorefrontSDK/pull/201)).

## Updated boilerplate

### Infrastructure

- **Drop-in SDK**: `@dropins/tools` upgraded to 1.9.0. See [Updated Drop-in SDK](#updated-drop-in-sdk) for performance improvements and sub-package versions.
- **Node.js 22 LTS required**: See [Node.js 22 LTS now required](#nodejs-22-lts-now-required) in the Highlights.
- **AEM library**: `scripts/aem.js` updated to 3.1.2 ([#1250](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1250)).

### Fixes and improvements

- **PDP and PLP blocks**: The Add to Cart button is now disabled for out-of-stock products on the PDP and PLP using the `inStock` property exposed by the drop-ins ([#1223](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1223)).
- **Recommendations block**: Add to Cart is disabled for out-of-stock recommended products ([#1235](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1235)). The block also forwards `currentProduct` context from the ACDL data layer to the Recommendations drop-in ([#1244](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1244)).
- **Analytics**: Locale is mapped from `demo-config-aco.json` in the delayed script for correct event processing in Adobe Commerce Optimizer storefronts ([#1238](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1238)).
- **Performance**: `fetchPlaceholders` uses `force-cache` to skip revalidation round-trips after the 2-hour `max-age` expires ([#1273](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1273)).
- **B2B (Authentication)**: Fixed `X-Adobe-Company` header being sent on guest GraphQL requests ([#1248](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1248), B2B).

## Updated Drop-in SDK

<Aside type="note" title="Internal Links">
Links to the StorefrontSDK repository do not resolve unless you have access to that repository.
</Aside>

The Drop-in SDK (`@dropins/tools`) was upgraded to 1.9.0 in this release. The following sub-packages were also updated:

| Package | Version |
|---------|---------|
| `@dropins/build-tools` | 1.2.0 |
| `@adobe-commerce/elsie` | 1.9.0 |
| `@adobe-commerce/event-bus` | 1.1.0 |
| `@adobe-commerce/fetch-graphql` | 1.3.0 |
| `@adobe-commerce/recaptcha` | 1.2.0 |
| `@adobe-commerce/storefront-design` | 1.1.0 |

- **Bundle optimizations**: HTTP requests cut 29-85% per drop-in (tools: 34→24, Auth: 24→6, Cart: 13→2). TTI improved 22%; TBT halved. **Rebuild your drop-ins against this SDK release to get these gains** ([#200](https://github.com/adobe-commerce/StorefrontSDK/pull/200)).
- **Node.js 22 LTS**: All drop-ins updated to the Node.js 22 LTS minimum runtime ([#201](https://github.com/adobe-commerce/StorefrontSDK/pull/201)).
- **GraphQL fragment bundling fix**: GraphQL fragment files are no longer bundled into `chunks/api.js`, so you can override individual GraphQL fragments using the standalone `fragments.js` output again ([#210](https://github.com/adobe-commerce/StorefrontSDK/pull/210)).

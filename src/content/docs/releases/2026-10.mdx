Merchants can share public requisition lists with guests who can add selected products to their carts. Shoppers can pay with saved cards and configure more product options on the product details page. The Storefront Compatibility Packages add invoice data and public-list support across the supported Commerce versions. See the [changelog](/releases/changelog/) for the full list of changes.

<Aside type="caution" title="Breaking changes">
- The Drop-in SDK moves to Elsie 3. Package maintainers who build or extend drop-ins must migrate their development configuration before rebuilding. Published drop-ins continue to work without a rebuild ([#276](https://github.com/adobe-commerce/StorefrontSDK/pull/276), [#345](https://github.com/adobe-commerce/StorefrontSDK/pull/345)).
- The Requisition List drop-in moves to major version 2. Review custom integrations before upgrading to the new public-sharing release ([#169](https://github.com/adobe-commerce/storefront-requisition-list/pull/169), [#170](https://github.com/adobe-commerce/storefront-requisition-list/pull/170)).
- The B2B Storefront Compatibility Package no longer returns `token` from `SharePublicRequisitionList`. Custom integrations that used the previous response should read the token from `RequisitionList.token` instead ([#201](https://github.com/magento-commerce/storefront-compatibility-b2b/pull/201)).
</Aside>

<Aside type="note" title="Consent update released separately">
The analytics consent gate was released and documented separately before this suite. Analytics stays off until consent is granted. The URL parameter is for testing only; merchants and system integrators must connect a production consent management platform. See <Link href={"https://experienceleague.adobe.com/en/tools/commerce-storefront/setup/analytics/consent/"} text={"the consent documentation"} /> ([#1486](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1486), [#1115](https://github.com/commerce-docs/microsite-commerce-storefront/pull/1115)).
</Aside>

## Highlights

### Public requisition lists for guest shoppers

B2B buyers can share a requisition list by email or link, so recipients can review selected products and add them to a cart without signing in. Stores control whether public sharing is available and can set link validity and recipient limits ([#169](https://github.com/adobe-commerce/storefront-requisition-list/pull/169), [#170](https://github.com/adobe-commerce/storefront-requisition-list/pull/170)).

### Checkout with saved cards

Shoppers can save a card for future purchases and select a vaulted card during checkout. The checkout and Payment Services drop-ins now support the saved-card flow, including a way to return to another payment method ([#58](https://github.com/adobe-commerce/storefront-payment-services/pull/58), [#67](https://github.com/adobe-commerce/storefront-payment-services/pull/67), [#69](https://github.com/adobe-commerce/storefront-payment-services/pull/69), [#370](https://github.com/adobe-commerce/storefront-checkout/pull/370)).

### Customizable product options

Shoppers can configure custom product options with dropdowns, radio buttons, and checkboxes on the product details page. Multiple-choice options appear as a checkbox list, which works better with touch and assistive technology than a native multi-select ([#103](https://github.com/adobe-commerce/storefront-pdp/pull/103)).

### Faster sign-in loading

Visitors who do not open a sign-in control no longer download the authentication drop-in with the page header. The B2C and B2B headers load authentication code only when a shopper opens sign-in or chooses an account action ([#1463](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1463), B2C; [#1468](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1468), B2B).

### Recommendation units by label

Implementers can select recommendation units by a label in the block configuration, instead of relying only on a unit ID. The Product Recommendations drop-in can query units by label and unit ID together ([#1451](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1451), [#50](https://github.com/adobe-commerce/storefront-recommendations/pull/50)).

## Updated boilerplate

### Infrastructure

- **Drop-in SDK**: The B2C and B2B storefronts use Drop-in SDK 3.0.0 and `@dropins/build-tools` 1.2.2 ([#1519](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1519), [#1521](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1521)).

### Document Authoring

No Document Authoring changes in this release suite.

### Fixes and improvements

- **Product details page**: Product metadata is now owned by the prerendering layer instead of being generated in the browser. Storefronts need a prerendering solution to provide page titles, Open Graph tags, and structured data to crawlers ([#1458](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1458)).
- **Header**: B2C and B2B storefronts load authentication modules only after a shopper opens a sign-in control ([#1463](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1463), B2C; [#1468](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1468), B2B).
- **Recommendations block**: The block now reads a `label` value from its configuration and requests the matching recommendation unit ([#1451](https://github.com/hlxsites/aem-boilerplate-commerce/pull/1451)).

## Updated Drop-in SDK

<Aside type="note" title="Internal Links">
Links to the StorefrontSDK repository resolve only for readers with access to that private repository.
</Aside>

The Drop-in SDK moves to 3.0.0 and updates its shared packages. Package maintainers who build drop-ins with Elsie must migrate the development toolchain before rebuilding. Existing published drop-ins continue to work without a rebuild ([#276](https://github.com/adobe-commerce/StorefrontSDK/pull/276), [#345](https://github.com/adobe-commerce/StorefrontSDK/pull/345)).

| Package | Version |
|---------|---------|
| `@dropins/tools` | 3.0.0 |
| `@adobe-commerce/elsie` | 3.0.0 |
| `@adobe-commerce/recaptcha` | 1.3.1 |
| `@adobe-commerce/event-bus` | 1.1.2 |
| `@adobe-commerce/fetch-graphql` | 1.3.2 |
| `@adobe-commerce/storefront-design` | 1.1.2 |
| `@dropins/build-tools` | 1.2.2 |

- **New features**: New `sanitizeHtml` and `createSanitizedHtml` helpers use DOMPurify to sanitize untrusted HTML before rendering ([#300](https://github.com/adobe-commerce/StorefrontSDK/pull/300)). Elsie also adds optional library configuration and shared Vite, Cypress, Storybook, and test tooling for package maintainers ([#346](https://github.com/adobe-commerce/StorefrontSDK/pull/346), [#352](https://github.com/adobe-commerce/StorefrontSDK/pull/352), [#356](https://github.com/adobe-commerce/StorefrontSDK/pull/356), [#357](https://github.com/adobe-commerce/StorefrontSDK/pull/357)).
- **Improvements and fixes**: The SDK now uses pnpm instead of Yarn and consolidates shared runtime chunks. In the measured Tools scenario, the change reduced JavaScript requests from 24 to 14 ([#276](https://github.com/adobe-commerce/StorefrontSDK/pull/276), [#345](https://github.com/adobe-commerce/StorefrontSDK/pull/345)). Accessibility fixes give Picker controls names that match visible labels and keep Checkbox descriptions associated with the correct control ([#316](https://github.com/adobe-commerce/StorefrontSDK/pull/316), [#317](https://github.com/adobe-commerce/StorefrontSDK/pull/317)). The Portal component now uses Preact's `createPortal`, preventing intermittent DOM insertion errors ([#337](https://github.com/adobe-commerce/StorefrontSDK/pull/337)).

## Updated storefront tools

- **Site Creator library**: New sites now place the Document Authoring library in `docs/library` instead of the hidden `.da/library` folder. Source sites must include `docs/**` in `full-index.json` so Site Creator can copy the library ([#124](https://github.com/adobe-commerce/storefront-tools/pull/124)).
- **Template access**: Site Creator reads source templates through a worker using a read-only service account, so users can copy templates without receiving write access to the source site ([#126](https://github.com/adobe-commerce/storefront-tools/pull/126)).

Seller-assisted buying lets a store administrator log in as a customer and act on their behalf by browsing products, building a cart, and placing orders. During the session, a banner tells the administrator they are browsing as the customer. Afterward, the customer can review every administrator action in their account activity log.

Seller-assisted buying is not a separate <Term>drop-in</Term> or package. It extends three drop-ins you already have and adds a session banner to the <Term>boilerplate</Term>. This page explains the full flow and points you to the drop-in pages where each part is documented.

<Aside type="note">
The underlying Adobe Commerce <Link href="https://experienceleague.adobe.com/en/docs/commerce-admin/customers/customer-accounts/manage/login-as-customer" text="Login as Customer" /> feature works for both B2B and B2C stores. This page appears under Storefront Features because the feature spans several drop-ins rather than belonging to one.
</Aside>

## How it works

When seller-assisted buying is enabled at the store level, an administrator generates a one-time password (OTP) in the Admin. The administrator uses the OTP to sign in as the customer through the standard storefront sign-in flow. The `storefront-auth` drop-in decodes the returned JSON Web Token (JWT) and checks it for an admin identifier. When the token includes one, the drop-in sets an `auth_dropin_admin_session` cookie.

The boilerplate header block reads that cookie on every page load. When the cookie is present, it renders a banner at the top of the page showing the customer's name and the website name. The banner includes a "Close Session" button that calls `revokeCustomerToken()` and redirects to the home page. The banner also listens to the `authenticated` event and removes itself automatically when the session ends.

## Enable the feature

Enable seller-assisted buying and customize the consent checkbox from the Admin.

<Steps>

1. In the Admin, go to **Stores** > **Settings** > **Configuration** > **Customers** > **Login as Customer**.

1. Set **Enable Extension** to `Yes`.

1. Optionally customize the **Title for Login as Customer opt-in checkbox** and **Login as Customer checkbox tooltip** fields to match your brand voice.

1. Save the configuration.

1. Clear the cache from **System** > **Tools** > **Cache Management**.

</Steps>

<Aside type="note">
All fields on this page are locked by default. Each field has a "Use system value" checkbox on the right that is checked by default. Uncheck it to enable editing for that field.
</Aside>

The fields on this configuration page control the feature:

<TableWrapper>

| Setting | Description |
| ------- | ----------- |
| Enable Extension | Set to `Yes` to activate the feature store-wide. |
| Title for Login as Customer opt-in checkbox | The label shown next to the customer consent checkbox on the sign-up form. |
| Login as Customer checkbox tooltip | Tooltip text that gives the customer more context about the consent option. |

</TableWrapper>

Once the feature is enabled, the consent checkbox and the administrator order labels appear automatically. Those parts need no extra code.

## Add the account blocks

The boilerplate provides two ready-made blocks for the customer-facing <Term>containers</Term>. Place `commerce-seller-assisted-buying-settings` on the account settings page and `commerce-seller-assisted-buying-activity` on the account activity page. Each block checks authentication before rendering and imports the account <Term>initializer</Term> automatically.

```js title="blocks/commerce-seller-assisted-buying-settings/commerce-seller-assisted-buying-settings.js"
import { render as accountRenderer } from '@dropins/storefront-account/render.js';
import { SellerAssistedBuyingSettings } from '@dropins/storefront-account/containers/SellerAssistedBuyingSettings.js';
import { CUSTOMER_LOGIN_PATH, checkIsAuthenticated, rootLink } from '../../scripts/commerce.js';

import '../../scripts/initializers/account.js';

export default async function decorate(block) {
  if (!checkIsAuthenticated()) {
    window.location.href = rootLink(CUSTOMER_LOGIN_PATH);
  } else {
    const container = document.createElement('div');
    await accountRenderer.render(SellerAssistedBuyingSettings, {})(container);
    block.appendChild(container);
  }
}
```

<Aside type="tip">
If you haven't worked with drop-ins before, see [Using drop-ins](/dropins/all/quick-start/) for a step-by-step walkthrough.
</Aside>

## Session banner

The session banner lives in the boilerplate header block, not in a drop-in. The block renders it automatically when an admin session is active. It needs no extra code. The banner CSS and rendering logic ship with the boilerplate header block (`blocks/header/header.css` and `blocks/header/renderSellerAssistedBuyingBanner.js`).

Target these classes to restyle the banner:

```css title="blocks/header/header.css"
/* Adds top padding to page content so the banner does not overlap it */
body:has(.seller-assisted-buying-banner) {}

/* Banner strip — rendered at the top of the page during an assisted session */
.seller-assisted-buying-banner {}
.seller-assisted-buying-banner__message {}
.seller-assisted-buying-banner__close-button {}
```

If you change the banner height, update `body:has(.seller-assisted-buying-banner)` at the same time so the page content shifts down by the same amount.

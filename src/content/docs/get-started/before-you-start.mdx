Gather the accounts, permissions, and Commerce access needed to create a new storefront project, whether you use <Term>Site Creator</Term> or the manual GitHub path. As you prepare, use the table's references for help with unfamiliar tools or access requirements.

For an existing project, go straight to [Run your storefront locally](/get-started/run-locally/), since you do not need to repeat repository creation or backend setup.

You should be comfortable with JavaScript, HTML, CSS, and basic npm workflows, but you do not need prior knowledge of Adobe Commerce, PHP, or React.

## What you need

Your storefront uses <Term>Edge Delivery Services</Term> (EDS), Adobe's hosting and delivery layer, to turn authored documents into fast HTML pages. To build and deploy it, you'll need the accounts, tools, and Commerce access listed below.

## Extra steps for some teams

Your backend and organization policies determine which extra setup applies. If you need to identify your backend, [Backend options](/get-started/backends/) explains the available types and their requirements.

For Adobe Commerce as a Cloud Service, Adobe manages the platform packages and hosted services, but your team still configures the storefront connection. With Adobe Commerce Optimizer, setup also depends on the existing platform that handles cart, checkout, and accounts.

### Commerce PaaS backends

If shopping operations use Adobe Commerce on Cloud or on-premises, complete the Commerce prerequisites even when Adobe Commerce Optimizer supplies the catalog experience. Site Creator or the manual GitHub path creates the storefront project; it does not replace setup on that Commerce deployment.

Finish the [PaaS: required packages and services](/get-started/backends/#paas-required-packages-and-services) checklist for the transactional APIs and catalog path your project uses. The Storefront Compatibility package runs on the Adobe Commerce deployment. For catalog synchronization into Adobe Commerce Optimizer, follow the separate connector requirements in [Backend options](/get-started/backends/).

Until the required Commerce-side setup is complete, catalog or shopping checks can fail even when the storefront content loads. Adobe managing Adobe Commerce Optimizer does not mean that Adobe also configures your existing transactional platform.

Using drop-in components requires a license that covers drop-ins: Adobe Commerce as a Cloud Service, Adobe Commerce Optimizer, or Commerce PaaS with Adobe Commerce Optimizer added. Read [Licensing requirements](/licensing/) for who can use drop-ins and how access works. If your backend type is Commerce PaaS as defined on [Backend options](/get-started/backends/), confirm your situation against both topics before you invest in drop-in work.

### Adobe Commerce Optimizer with a third-party platform

Identify who owns the cart, checkout, and account integration for the existing platform. Adobe Commerce Optimizer provides catalog and product-discovery services, not a replacement for those transactional APIs. Confirm the integration requirements before treating the storefront as a complete shopping experience.

### Site Creator, manual GitHub setup, and enterprise policies

Site Creator walks you through the repository and starter content in the browser. To create the repository separately, start from the <Link href="https://github.com/hlxsites/aem-boilerplate-commerce" text="Commerce boilerplate template" /> on GitHub and install the <Link href="https://github.com/apps/aem-code-sync" text="AEM Code Sync app" /> on that repository. Code Sync redeploys your storefront when you push to `main` and connects Edge Delivery Services to your repo. Follow [Step-by-step setup](/get-started/create-storefront/#step-by-step) for the full GitHub and Code Sync sequence.

The manual path still uses Site Creator's existing-code-repository option to provision starter content. Plan time for repository and GitHub App approvals. If your organization does not allow Site Creator, confirm an approved content-provisioning process with the project owner before starting.

### Sidekick browser extension

Sidekick is the browser extension authors use to preview, publish, and open source documents from a storefront page. You do not need it before creating your first site because Site Creator configures the Sidekick project connection automatically. When authors are ready to use the toolbar, they install the extension from the Chrome Web Store. For installation details, including the Edge browser path, see <Link href="https://www.aem.live/docs/sidekick" text="Sidekick documentation" /> or follow the optional Sidekick step in [Create a storefront](/get-started/create-storefront/#optional-use-sidekick-for-content-editing).

## What you do not need right now

Site Creator and DA.live run in your browser, so you do not need a code editor, a cloned repository, or a local server to create a storefront. For local development, however, you need Node.js, npm, and the project's AEM CLI. To prepare those tools and start a preview, follow [Run your storefront locally](/get-started/run-locally/).

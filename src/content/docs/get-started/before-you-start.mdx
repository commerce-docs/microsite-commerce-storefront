## Extra steps for some teams

The table above is the common baseline. The sections below only matter when that situation applies to you.

If your backend is Adobe Commerce as a Cloud Service or Adobe Commerce Optimizer, you can skip the Commerce PaaS section below. Adobe manages most storefront service requirements for those backends.

### Commerce PaaS backends

If your backend is Commerce PaaS, you can still use Site Creator or the manual GitHub path to create the repository and Document Author starter content. Those tools are not limited to other backend types. What differs is your Commerce instance: complete the [PaaS: required packages and services](/get-started/backends/#paas-required-packages-and-services) checklist there so storefront APIs and drop-ins match what the boilerplate expects. Until that work finishes, Commerce-backed previews and steps that read from Commerce APIs can fail or stay incomplete. That includes the Storefront Compatibility package, Services Connector, Catalog Service, and any other storefront services your rollout needs (for example, Live Search, Product Recommendations, or Data Connection). Install and configure them on your Commerce instance first, or drop-ins will not work. Adobe Commerce as a Cloud Service and Adobe Commerce Optimizer handle these requirements automatically.

Drop-in components require an Adobe Commerce as a Cloud Service or Adobe Commerce Optimizer license. Read [Licensing requirements](/licensing/) for who can use drop-ins and how access works. If your backend type is Commerce PaaS as defined on [Backend options](/get-started/backends/), confirm your situation against both topics before you invest in drop-in work.

### Site Creator, manual GitHub setup, and enterprise policies

Site Creator walks you through the repository and starter content in the browser. If you skip it and start from the <Link href="https://github.com/hlxsites/aem-boilerplate-commerce" text="Commerce boilerplate template" /> on GitHub, install the <Link href="https://github.com/apps/aem-code-sync" text="AEM Code Sync app" /> on that repository. Code Sync redeploys your storefront when you push to `main` and connects Edge Delivery Services to your repo. Follow [Manual setup without Site Creator](/get-started/create-storefront/#manual-setup-without-site-creator) for the full GitHub and Code Sync sequence.

Some organizations block repository creation or GitHub App installs until an administrator approves them. If you use the manual path, plan time for that approval, or use Site Creator when your organization allows it.

### Sidekick after the site is live

When you provision a new storefront with Site Creator, Edge Delivery Services includes automated Sidekick configuration in site config for that site. You do not add Sidekick project wiring by hand on the Site Creator path. That is different from the Sidekick browser extension: each author still installs the extension from the Chrome Web Store (or follows the Edge steps in <Link href="https://www.aem.live/docs/sidekick" text="Sidekick documentation" /> on AEM Docs) before they can use the toolbar to preview, publish, or open source documents from a page. You do not need the extension before you open Site Creator. For a walkthrough that matches this collection, see the optional Sidekick step in [Create a storefront](/get-started/create-storefront/#optional-sidekick-content-editing).

## What you do not need right now

You do not need a code editor, a cloned repository, or a local server to create a storefront. Site Creator and DA.live run entirely in the browser. You do not need Node.js, npm, the AEM CLI, or local Git workflows while you only work in Site Creator and DA.live in the browser. Install and use those tools when you clone the repository and run the boilerplate on your machine. Follow [Create a storefront](/get-started/create-storefront/) for the full sequence (including the <Link href="https://www.aem.live/developer/cli-reference" text="AEM CLI" /> for local preview). Then use [Run it locally](/boilerplate/getting-started/) for day-to-day commands after your site exists.

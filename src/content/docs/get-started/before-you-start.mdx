Gather the accounts, permissions, and Commerce access needed to create a new storefront project, whether you use <Term>Site Creator</Term> or the manual GitHub path. As you prepare, use the table's references for help with unfamiliar tools or access requirements.

For an existing project, go straight to [Run your storefront locally](/get-started/run-locally/), since you do not need to repeat repository creation or backend setup.

You should be comfortable with JavaScript, HTML, CSS, and basic npm workflows, but you do not need prior knowledge of Adobe Commerce, PHP, or React.

## What you need

Your storefront uses <Term>Edge Delivery Services</Term> (EDS), Adobe's hosting and delivery layer, to turn authored documents into fast HTML pages. To build and deploy it, you'll need the accounts, tools, and Commerce access listed below.

## Extra steps for some teams

Your backend and organization policies determine which extra setup applies. If you need to identify your backend, [Backend options](/get-started/backends/) explains the available types and their requirements.

If your backend is Adobe Commerce as a Cloud Service or Adobe Commerce Optimizer, you can skip the Commerce PaaS section below. Adobe manages most storefront service requirements for those backends.

### Commerce PaaS backends

If your backend is Commerce PaaS, you can still use Site Creator or the manual GitHub path to create the repository and starter content in Document Author. The difference is the Commerce-side setup you need to complete first.

On Commerce PaaS, finish the [PaaS: required packages and services](/get-started/backends/#paas-required-packages-and-services) checklist so storefront APIs and drop-ins match what the boilerplate expects. That checklist includes the Storefront Compatibility package, Services Connector, Catalog Service, and any other storefront services your rollout needs (for example, Live Search, Product Recommendations, or Data Connection). [Commerce services at a glance](/get-started/architecture/commerce-services-and-backends/) explains what each service does.

These services let drop-ins request live data when you preview a product page or run the storefront locally. Until the Commerce-side setup is complete, those checks can fail or look incomplete. For Adobe Commerce as a Cloud Service and Adobe Commerce Optimizer, Adobe handles these service requirements instead.

Using drop-in components requires a license that covers drop-ins: Adobe Commerce as a Cloud Service, Adobe Commerce Optimizer, or Commerce PaaS with Adobe Commerce Optimizer added. Read [Licensing requirements](/licensing/) for who can use drop-ins and how access works. If your backend type is Commerce PaaS as defined on [Backend options](/get-started/backends/), confirm your situation against both topics before you invest in drop-in work.

### Site Creator, manual GitHub setup, and enterprise policies

Site Creator walks you through the repository and starter content in the browser. If you skip it and start from the <Link href="https://github.com/hlxsites/aem-boilerplate-commerce" text="Commerce boilerplate template" /> on GitHub, install the <Link href="https://github.com/apps/aem-code-sync" text="AEM Code Sync app" /> on that repository. Code Sync redeploys your storefront when you push to `main` and connects Edge Delivery Services to your repo. Follow [Step-by-step setup](/get-started/create-storefront/#step-by-step) for the full GitHub and Code Sync sequence.

If you use the manual path, plan time for any administrator approval your organization requires before you create repositories or install GitHub Apps. Site Creator is an alternative when your organization allows it.

### Sidekick browser extension

<Term>Sidekick</Term> is the browser extension authors use to preview, publish, and open source documents from a storefront page. You do not need it before creating your first site because Site Creator configures the Sidekick project connection automatically. When authors are ready to use the toolbar, they install the extension from the Chrome Web Store. For installation details, including the Edge browser path, see <Link href="https://www.aem.live/docs/sidekick" text="Sidekick documentation" /> or follow the optional Sidekick step in [Create a storefront](/get-started/create-storefront/#optional-use-sidekick-for-content-editing).

## What you do not need right now

Site Creator and DA.live run in your browser, so you do not need a code editor, a cloned repository, or a local server to create a storefront. For local development, however, you need Node.js, npm, and the project's AEM CLI. Follow [Run your storefront locally](/get-started/run-locally/) to prepare those tools and start a preview.

Use this checklist before you start [Create a storefront](/get-started/create-storefront/).

Confirm Adobe services and Commerce credentials for your backend (PaaS, ACCS, or ACO — the sections below differ by scenario). Optionally read [Storefront configuration](/setup/configuration/commerce-configuration/) so you know where those values land in `config.json`. Then verify your development tools and local environment.

## Required services

Adobe Commerce Storefront supports three backend scenarios. What you need depends on which one applies to your project.

### Commerce PaaS

Adobe Commerce Platform-as-a-Service (self-managed or cloud infrastructure):

- **Adobe Commerce 2.4.7 or later** — your backend catalog, pricing, and order management. See the [compatibility package](/setup/configuration/storefront-compatibility/install/) for version-specific requirements.
- **Edge Delivery Services** — the delivery and rendering layer. Provisioned through your Adobe contract; coordinate with your Adobe account team if you don't have access.
- **Adobe I/O** — required for API Mesh, Commerce eventing, and Experience Platform integrations. Access is provisioned per-organization.
- **Manual service installation** — you must install the following before running the storefront guide: Storefront Compatibility package, Data Connection, Services Connector, Catalog Service, Live Search, and Product Recommendations. See [Compatibility package installation](/setup/configuration/storefront-compatibility/install/).

### Adobe Commerce as a Cloud Service

- **Edge Delivery Services** — provisioned through your Adobe contract.
- All Commerce services (Data Connection, Catalog Service, Live Search, Product Recommendations) are automatically provisioned by Adobe. No manual installation required.

Before starting storefront setup, verify that your organization has the correct Admin Console entitlements and that your Commerce environment is active. See [Pre-onboarding checklist](/setup/pre-onboarding/) and [Adobe Experience Cloud access](/setup/configuration/experience-cloud-access/).

### Adobe Commerce Optimizer

- **Edge Delivery Services** — provisioned through your Adobe contract.
- All services are automatically provisioned. No manual installation required.

Before starting storefront setup, verify that your organization has the correct Admin Console entitlements for Adobe Commerce Optimizer. See [Adobe Experience Cloud access](/setup/configuration/experience-cloud-access/).

<Aside type="tip" title="Licenses">
See [Licensing](/licensing/) for the full list of entitlements required for B2C and B2B storefronts.
</Aside>

## Commerce backend access

You need credentials and endpoint information to configure the storefront. What you need depends on your backend:

<TableWrapper nowrap={[0]}>

| Backend | Credentials and endpoints |
|---------|--------------------------|
| **Commerce PaaS** | Commerce GraphQL endpoint URL, REST API base URL, and an API key or integration token with catalog, cart, checkout, and customer read/write scopes. B2B only: B2B module enabled on the Commerce instance. |
| **Adobe Commerce as a Cloud Service** | Service endpoints are automatically provisioned. Retrieve your API credentials from the Adobe Commerce as a Cloud Service dashboard before starting the setup guide. |
| **Adobe Commerce Optimizer** | Catalog API endpoints are provided by Adobe Commerce Optimizer. Retrieve your credentials from your Adobe Commerce Optimizer configuration before starting the setup guide. |

</TableWrapper>

<Aside type="note" title="Where these values go">
After the [Create a storefront](/get-started/create-storefront/) **Link repo to commerce data** step, your backend URLs, headers, and store context live in storefront configuration (`config.json` in the repo or the Edge Delivery config service). See [Storefront configuration](/setup/configuration/commerce-configuration/) for every field, with tabs for PaaS, ACCS, and ACO.
</Aside>

## Storefront configuration and setup

Your boilerplate connects to Commerce through a JSON configuration: **endpoints** (GraphQL for core Commerce and catalog/read services), **headers** (authentication and store scope), plus analytics, plugins, and multistore settings. Plan time to align endpoints with your CDN and to resolve CORS before you rely on browser-based API calls.

## Development tools

| Tool | Minimum version | Notes |
|------|----------------|-------|
| Node.js | 18.x LTS | 20.x or later recommended |
| npm or pnpm | npm 9 / pnpm 8 | The boilerplate uses pnpm |
| Git | 2.x | Required for the boilerplate workflow |
| GitHub account | — | The boilerplate is a GitHub template; you create your project from it |

## Local environment

- A code editor (VS Code recommended — the boilerplate includes an `.editorconfig`)
- Access to a terminal / shell (bash or zsh)
- The [AEM Sidekick browser extension](https://chromewebstore.google.com/detail/aem-sidekick/ccfggkjabjahcjoljmgmklhpaccedipo) for previewing and publishing Edge Delivery pages

## Next steps

Once you have these in place, read [Core concepts](/get-started/core-concepts/) for a plain-English map of how the pieces fit together, then follow [Create a storefront](/get-started/create-storefront/) — the guide covers both B2C and B2B paths in a single flow.

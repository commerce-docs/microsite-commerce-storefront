Adobe Commerce Storefront is a starter project for building a custom shopping website on Adobe Commerce. It includes product pages, cart, checkout, and account features ready to customize. Storefront code controls how the site looks and behaves, while connected Commerce services supply product and shopping data.

## What the storefront project includes

The <Term term="Commerce boilerplate">Adobe Commerce boilerplate</Term> is a starting point for new storefront projects. Teams can create a new GitHub repository from the template or continue working in an existing storefront repository.

The included shopping features are already connected, so there is no separate cart or checkout package to install. They are built from <Term term="Drop-in components">drop-in components</Term>, reusable packages that supply shopping interfaces and behavior.

The project supplies the website code. Page content and Commerce data come from separate sources.

## How content, code, and Commerce data work together

The shopper's browser combines page content, storefront code, and Commerce data into one website. The numbers identify the parts of that experience, not a sequence of steps.

<Callouts columnCount={1}>

1. Page content: Authors manage text, images, and page settings in an authoring tool such as <Term>DA.live</Term>. This content is separate from your storefront code.

1. Storefront code: The JavaScript and styles in your project control page appearance and behavior. This code connects the shopping features and authored content to the page.

1. Commerce data: Connected Commerce services supply product information and shopping data, such as prices and cart contents. This connected Commerce system is called the [backend](/get-started/backends/).

1. Shopper experience: A product page can show an authored promotion next to a price supplied by Commerce. Storefront code controls how these appear and behave together.

</Callouts>

<Term>Edge Delivery Services</Term> is Adobe's system for delivering the page content and storefront code to the shopper's browser. The code requests shopping data from the backend.

The starter project does not replace the Commerce backend. Each storefront project connects to its own content source and Commerce services. Available shopping features depend on that backend and your [licensing](/licensing/).

## What to customize

Storefront development adapts the starter code to a specific business. Common customizations include:

- Matching brand colors, typography, and spacing.
- Changing how shopping features fit into a page.
- Extending an existing shopping feature or building a custom experience.

These code changes are separate from routine content and catalog updates. Content authors edit page text, images, and layouts in their authoring tool. Product information and prices are managed in the connected Commerce system.

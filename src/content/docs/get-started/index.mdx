With Adobe Commerce Storefront, you start with shopping features such as product discovery, cart, checkout, and accounts. Understanding how these features connect to page content and Commerce services helps you find the code involved in a change.

Available features depend on your [backend](/get-started/backends/) and [licensing](/licensing/). If your team already has a storefront project, you can [go directly to local setup](/get-started/run-locally/).

## Your role as a storefront developer

Your codebase comes from the <Term term="Commerce boilerplate">Adobe Commerce boilerplate</Term>. You customize its code and shopping features, while content authors create and edit pages.

The boilerplate is a GitHub repository template. Your project starts as a copy of that template, and you work in your own repository. Standard shopping features are already included, so you customize their existing code rather than installing a separate cart or checkout package.

## How your storefront reaches shoppers

In the workflow shown below, you keep your code in a GitHub repository, while authors manage page content in <Term>DA.live</Term>.

<Term>Edge Delivery Services</Term> delivers that content and code to shoppers. Your storefront runs in the shopper's browser and combines the content with live shopping data from your Commerce services.

## What your storefront pages are built from

Blocks are named parts of a page. Content blocks add text, images, and layout, while <Term>Commerce blocks</Term> add shopping features.

Commerce blocks can use <Term term="Drop-in components">drop-in components</Term> for ready-made shopping interfaces, such as cart and checkout, that connect to your Commerce services. The Storefront SDK is a software development kit with shared user interface components and tools that Commerce blocks can also use.

<Diagram adaptColors caption="Storefront pages combine shopping features from Commerce blocks with content and layout from content blocks. Commerce blocks can use drop-in components and the Storefront SDK.">
  ![SDK components and drop-ins support Commerce blocks, which combine with content blocks to form storefront pages](images/storefront-page-parts.png)
</Diagram>

Use these names when you explore the project or ask your team for help:

<TableWrapper>

| Name | What it means |
| --- | --- |
| Document | Page content that authors edit in an authoring tool, such as DA.live |
| Edge Delivery Services | Adobe's service for delivering page content and storefront code |
| Content block | A part of a page that displays content, such as a hero or a row of cards |
| Commerce block | A part of a page that connects a shopping experience to the storefront |
| Drop-in component | A package of ready-made shopping interfaces and behavior, such as cart or checkout |
| Container | A part of a drop-in that a block can render, such as a cart item list |
| Storefront SDK | Shared user interface components and development tools |
| Commerce APIs | Application programming interfaces that the storefront calls to read or update shopping data |

</TableWrapper>

## Find your code

Your repository contains the code you change. Page content and Commerce data have their own sources, so cloning the repository is only part of local setup.

<TableWrapper>

| File or directory | What you work on |
| --- | --- |
| `blocks/` | JavaScript and CSS for individual blocks |
| `styles/styles.css` | Shared styles and design tokens, which are named values for colors, spacing, and other design choices |
| `scripts/initializers/` | Setup for drop-ins, including their endpoints and labels |
| `scripts/commerce.js` | Shared Commerce integration code, including loading storefront configuration |
| `config.json` (if present) | Local connection settings for projects that use a local file. See [Storefront configuration](/setup/configuration/commerce-configuration/) before changing them. |

</TableWrapper>

For example, the cart block in `blocks/commerce-cart/commerce-cart.js` imports the cart initializer and renders containers from the cart drop-in. One is `CartSummaryList`, which displays cart items. The block decides where to place those containers, while the drop-in supplies their shopping interface and behavior.

This gives you a starting point for code changes: inspect the block for page integration, its initializer for drop-in setup, or the shared stylesheet for a design change.

For a closer look at a block's responsibilities, see [Blocks and drop-ins](/blocks/blocks-and-dropins/). For a page's loading sequence and communication between shopping features, use [Architecture](/get-started/architecture/) as a reference.

## Content, code, delivery, and commerce

The storefront uses <Term>Edge Delivery Services</Term> to publish and deliver content authored in <Term>DA.live</Term>. Storefront code lives in a GitHub repository based on the <Term term="Commerce boilerplate">Adobe Commerce boilerplate</Term>.

The included <Term term="Drop-in components">drop-in components</Term> use <Term>GraphQL</Term> to communicate with the configured Commerce services.

## How storefront features fit together

<Term>Commerce blocks</Term> implement storefront features on authored pages. A block can render a drop-in container or [build a custom feature](/blocks/build-custom-features/) from drop-in API functions and SDK components. Other blocks display content, such as text and images, without using drop-ins.

<Aside type="note" title="About drop-in licensing">
Drop-in components require an active Adobe Commerce as a Cloud Service or Adobe Commerce Optimizer license. Adobe Commerce on Cloud and on-premises licenses alone do not include drop-ins. Read [Licensing requirements](/licensing/) to confirm your eligibility and [Backend options](/get-started/backends/) for the prerequisites that apply to your project.
</Aside>

## Get your first preview running

If your accounts, tools, and backend prerequisites are ready, go directly to [Create a storefront](/get-started/create-storefront/). Otherwise, follow this path to a local preview:

<Callouts columnCount={1}>
1. [Prerequisites](/get-started/before-you-start/): Gather your tools, accounts, and Commerce access.
1. [Backend options](/get-started/backends/): Confirm the license, services, and [Compatibility Package](/setup/configuration/storefront-compatibility/) requirements for your backend.
1. [Create a storefront](/get-started/create-storefront/): Create your repository and starter content with <Term>Site Creator</Term> in DA.live, or follow the manual setup tasks.
1. [Run your storefront locally](/boilerplate/#running-locally): Start a local preview of your storefront with the standard Commerce blocks already connected.
</Callouts>

Your local preview should now display your Commerce catalog. Use it to test changes before preparing the site for production.

<Aside type="tip" title="When something goes wrong">
Use [Architecture](/get-started/architecture/) to understand which parts of the storefront handle content, page delivery, and Commerce data. This helps you choose where to investigate a problem.
</Aside>

## Reference and how-tos

Use [Developer how-tos](/how-tos/#for-developers) for step-by-step instructions on product pages, cart, checkout, accounts, and search. These topics are in the How-tos section of the sidebar.

Each drop-in reference lists functions, component options (props), slots, and events. For business-to-consumer (B2C) storefronts, use the [B2C drop-in reference](/dropins/). For business-to-business (B2B) storefronts, use the [B2B drop-in reference](/dropins-b2b/). Both are under API Reference in the sidebar.

B2B storefronts use the same preview setup path. After your preview is running, use the B2B drop-in reference for B2B-specific configuration and customization.

Use the [Storefront SDK](/sdk/) when you need shared user interface (UI) components, <Term>design tokens</Term>, or the framework for custom features and new drop-ins. You can use it for small customizations as well as complete drop-in packages.

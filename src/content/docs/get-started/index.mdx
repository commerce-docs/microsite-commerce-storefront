Adobe Commerce Storefront is a starter project for building a custom shopping website on Adobe Commerce. It includes product pages, cart, checkout, and account features ready to customize. Storefront code controls how the site looks and behaves, while connected Commerce services supply product and shopping data.

## What the storefront project includes

For a new project, create your own GitHub repository from the Commerce template. If your team already has a storefront project based on this template, continue working in that repository. You do not need to create another repository.

The included shopping features are already connected for compatible Adobe Commerce backends, so there is no separate cart or checkout package to install. They are built from <Term term="Drop-in components">drop-in components</Term>, reusable packages that supply shopping interfaces and behavior.

## How content, code, and Commerce data work together

The shopper's browser combines page content, storefront code, and Commerce data into one website.

<Diagram type="mermaid" code={`
flowchart LR
  content["Page content"] --> delivery["Edge Delivery Services"]
  code["Storefront code"] --> delivery
  delivery --> browser["Shopper's browser"]
  browser <--> data["Commerce data"]
`} caption="Edge Delivery Services delivers page content and storefront code to the shopper's browser. The storefront code then requests Commerce data." />

- **Page content:** Authors manage text, images, and page settings in an authoring tool such as <Term>DA.live</Term>. This content is separate from your storefront code.
- **Storefront code:** The JavaScript and styles in your project control how pages look and behave. <Term>Edge Delivery Services</Term>, Adobe's delivery system, sends this code and the page content to the shopper's browser.
- **Commerce data:** Connected Commerce services supply product information and shopping data, such as prices and cart contents. These services form the [backend](/get-started/backends/). A project can use one commerce platform or combine services from more than one.

For example, a product page can show an authored promotion next to a price supplied by Commerce. Storefront code controls how they appear together.

## Where Commerce data comes from

The storefront can use different backend services for product discovery and shopping operations.

- <Link href="https://experienceleague.adobe.com/en/docs/commerce/cloud-service/overview" text="Adobe Commerce as a Cloud Service" /> is a fully managed commerce platform. It provides catalog services and handles carts, checkout, customer accounts, and orders.
- <Link href="https://experienceleague.adobe.com/en/docs/commerce/optimizer/overview" text="Adobe Commerce Optimizer" /> provides catalog, search, and product recommendation services alongside an existing commerce platform. That platform continues to handle carts, checkout, customer accounts, and orders.

An existing Adobe Commerce on Cloud or on-premises deployment can work with Adobe Commerce Optimizer. Adobe Commerce on Cloud is a separate product from Adobe Commerce as a Cloud Service.

The included cart and checkout code does not automatically connect to every third-party commerce platform. Those connections require project-specific integration.

For an existing storefront, start with its configured backend. For a new project, review [Backend options](/get-started/backends/) when you are ready to set up the project.

<Aside type="tip" title="Coming from Luma or a classic Commerce theme?">
In the classic model, Commerce builds storefront pages on the server with PHP. In this storefront, Edge Delivery Services delivers the page, and code in the shopper's browser requests Commerce data. Your Commerce Admin, catalog, and order tools stay the same. See [Coming from Luma or a classic Commerce theme](/get-started/architecture/commerce-services-and-backends/#coming-from-luma-or-a-classic-commerce-theme) for details.
</Aside>

## What storefront pages are built from

Each page is made of blocks. A block is a named part of a page, such as a hero banner or a cart. Content blocks add text, images, and layout. <Term>Commerce blocks</Term> add shopping features.

A Commerce block usually imports a drop-in and renders one or more of its containers. A container is a ready-made part of a drop-in's interface, such as the list of items in the cart. Each drop-in also has an initializer, a file that sets up the drop-in's Commerce connection and text labels.

The Storefront SDK (software development kit) supplies shared user interface (UI) components and tools that both blocks and drop-ins use.

## Find your code

Your storefront repository contains the code you change. Use this table to find where a common task starts:

<TableWrapper>

| Task | Start in |
| --- | --- |
| Change brand colors, typography, or spacing | `styles/styles.css`, which defines <Term>design tokens</Term> such as `--color-brand-500` |
| Change how a block looks or where its shopping features appear | The block's folder in `blocks/`, such as `blocks/commerce-cart/` |
| Change how a drop-in connects to Commerce or which labels it loads | The drop-in's initializer in `scripts/initializers/`, such as `cart.js` |
| Point the storefront to a different Commerce environment | Your storefront configuration. See [Storefront configuration](/setup/configuration/commerce-configuration/) before you change it. |

</TableWrapper>

### Example: the cart page

The cart page shows how these files work together:

- The cart block, <Link href="https://github.com/hlxsites/aem-boilerplate-commerce/blob/main/blocks/commerce-cart/commerce-cart.js" text="blocks/commerce-cart/commerce-cart.js" />, imports the cart initializer, <Link href="https://github.com/hlxsites/aem-boilerplate-commerce/blob/main/scripts/initializers/cart.js" text="scripts/initializers/cart.js" />.
- The initializer sets the cart drop-in's Commerce endpoint and loads its text labels.
- The block then renders containers from the cart drop-in. One of them, `CartSummaryList`, displays the items in the cart.

The block decides where each container appears on the page. The drop-in supplies the shopping interface and behavior. To learn more, see [Blocks and drop-ins](/blocks/blocks-and-dropins/) and [Explore your storefront project](/boilerplate/).

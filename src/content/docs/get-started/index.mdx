With Adobe Commerce Storefront, you start with shopping features such as product discovery, cart, checkout, and accounts. To find the code behind a change, follow how these features connect to page content and Commerce services.

Available features depend on your [backend](/get-started/backends/) and [licensing](/licensing/). If your team already has a storefront project, you can [go directly to local setup](/get-started/run-locally/).

## Your role as a storefront developer

You customize the code and shopping features supplied by the <Term term="Commerce boilerplate">Adobe Commerce boilerplate</Term>, while content authors create and edit pages.

The boilerplate is a GitHub repository template, so your project starts as a copy that you develop in your own repository. With standard shopping features already included, you customize their existing code rather than installing a separate cart or checkout package.

## How your storefront reaches shoppers

In the workflow shown below, you keep your code in a GitHub repository, while authors manage page content in <Term>DA.live</Term>.

From these two sources, <Term>Edge Delivery Services</Term> delivers content and code to shoppers. In the shopper's browser, your storefront combines that content with live shopping data from your Commerce services.

## What your storefront pages are built from

Each page is made of blocks, named parts that add content or shopping features. Content blocks add text, images, and layout, while <Term>Commerce blocks</Term> add shopping features.

Commerce blocks can use <Term term="Drop-in components">drop-in components</Term> for ready-made shopping interfaces, such as cart and checkout, that connect to your Commerce services. In addition to drop-ins, these blocks can use the Storefront SDK, a software development kit with shared user interface components and tools.

<Diagram adaptColors caption="Storefront pages combine shopping features from Commerce blocks with content and layout from content blocks. Commerce blocks can use drop-in components and the Storefront SDK.">
  ![SDK components and drop-ins support Commerce blocks, which combine with content blocks to form storefront pages](images/storefront-page-parts.png)
</Diagram>

Use these names when you explore the project or ask your team for help:

<TableWrapper>

| Name | What it means |
| --- | --- |
| Document | Page content that authors edit in an authoring tool, such as DA.live |
| Edge Delivery Services | Adobe's service for delivering page content and storefront code |
| Content block | A part of a page that displays content, such as a hero or a row of cards |
| Commerce block | A part of a page that connects a shopping experience to the storefront |
| Drop-in component | A package of ready-made shopping interfaces and behavior, such as cart or checkout |
| Container | A part of a drop-in that a block can render, such as a cart item list |
| Storefront SDK | Shared user interface components and development tools |
| Commerce APIs | Application programming interfaces that the storefront calls to read or update shopping data |

</TableWrapper>

## Find your code

Your repository holds the code you change, but page content and Commerce data have their own sources. That means cloning the repository is only part of local setup.

<TableWrapper>

| File or directory | What you work on |
| --- | --- |
| `blocks/` | JavaScript and CSS for individual blocks |
| `styles/styles.css` | Shared styles and design tokens, which are named values for colors, spacing, and other design choices |
| `scripts/initializers/` | Setup for drop-ins, including their endpoints and labels |
| `scripts/commerce.js` | Shared Commerce integration code, including loading storefront configuration |
| `config.json` (if present) | Local connection settings for projects that use a local file. See [Storefront configuration](/setup/configuration/commerce-configuration/) before changing them. |

</TableWrapper>

For example, `blocks/commerce-cart/commerce-cart.js` imports the cart initializer and renders containers from the cart drop-in. One of these containers, `CartSummaryList`, displays cart items. The block controls their placement on the page, while the drop-in supplies their shopping interface and behavior.

Use this division of responsibilities to choose where to start: the block for page integration, its initializer for drop-in setup, or the shared stylesheet for a design change.

For a closer look at a block's responsibilities, see [Blocks and drop-ins](/blocks/blocks-and-dropins/). To trace a page's loading sequence or communication between shopping features, use [Architecture](/get-started/architecture/) as a reference.

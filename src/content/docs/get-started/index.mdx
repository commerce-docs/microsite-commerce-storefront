Developing an Adobe Commerce storefront means working with a project that brings together page content, shopping features, and Commerce data. Your first goal is to run that project locally, understand how its parts fit together, and make a small change.

## Where you work

The storefront starter provides the initial code for a new project. Your team maintains its own copy in a storefront repository, a Git project that stores the code.

<Diagram
  adaptColors
  caption="Your storefront combines code from the development team with page content from authors."
>
  ![Developers work in a storefront repository using a code editor. Authors work in DA.live and
  Experience Workspace. Code and page content contribute to the storefront, which starts from a

- **Code changes:** Edit blocks, scripts, and styles in your favorite IDE, then check changes in a local preview. Work in your team's repository, not the starter template.
- **Page content:** Coordinate with content authors, who manage content in Document Authoring (DA.live) and Experience Workspace.

Your code controls how page content and shopping features appear in the storefront.

## How storefront pages are built

A block is a reusable part of a page. Commerce blocks connect shopping features to the page, while content blocks provide other content and layouts.

<Diagram
  adaptColors
  caption="Blocks combine page content and drop-in shopping features in the browser."
>
  ![Commerce blocks import drop-ins and Storefront SDK tools. Drop-ins use SDK tools and fetch
  Commerce data. Commerce blocks, drop-ins, and content blocks render content in the
  browser.](./images/developer-building-blocks.png)
</Diagram>

- **Commerce blocks** load and render drop-ins. For example, the cart block renders the cart interface.
- **Drop-ins** provide shopping features, such as product details, cart, and checkout, and request Commerce data.
- **Storefront SDK** supplies shared tools and UI components used by Commerce blocks and drop-ins.
- **Content blocks** display editorial content as cards, columns, and accordions.

The starter already connects its included drop-ins to Commerce blocks. When customizing the cart, use [Blocks and drop-ins](/blocks/blocks-and-dropins/) to distinguish changes to block settings from changes to the drop-in's internal layout or behavior.

## Create a new storefront

Start with these steps if your team does not already have a storefront project.

<Steps>

1. [Prerequisites](/get-started/before-you-start/): Gather the tools, accounts, and Commerce access you need.

1. [Backend options](/get-started/backends/): Confirm the license and setup requirements for Adobe Commerce as a Cloud Service or Adobe Commerce Optimizer.

1. [Create a storefront](/get-started/create-storefront/): Set up your project repository, Commerce connection, and starter content.

1. [Run your storefront locally](/get-started/run-locally/): Open a local preview with your project's content and Commerce data.

1. [Verify your storefront setup](/get-started/verify-setup/): Test the shopping features your project needs.

</Steps>

Then try [Make your first change](/get-started/first-change/) to change a link color and see the result in your local preview.

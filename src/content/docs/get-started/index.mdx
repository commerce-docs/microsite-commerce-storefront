## Reading order (concepts through reference)

The sections below suggest a reading order for each stage of building an Adobe Commerce storefront on Edge Delivery Services (EDS).

### Before you build

1. [Before you start](/get-started/before-you-start/) — tools, accounts, and backend access to confirm before you open Site Creator.
1. [Backend options](/get-started/backends/) — Commerce PaaS, Adobe Commerce as a Cloud Service, or Adobe Commerce Optimizer. Confirm prerequisites here before anything else.
1. [Storefront Architecture](/get-started/architecture/) — short topics: how a page loads, blocks and repo, drop-ins at a glance, commerce services, and backends. Optional before building, but helpful for mental models.

### Build

1. [Create a storefront](/get-started/create-storefront/) — Site Creator in DA.live; optional Universal Editor; manual GitHub and Code Sync when you need them.
1. [Boilerplate getting started](/boilerplate/getting-started/) — run the Adobe Commerce boilerplate locally.
1. [Boilerplate configuration](/boilerplate/configuration/) — `config.json`, headers, and paths that mirror production.

### Connect Commerce

1. [Storefront setup overview](/setup/) — discovery, configuration, analytics, SEO, and launch in one place.
1. [Storefront configuration](/setup/configuration/commerce-configuration/) — connect the storefront to Commerce and services.
1. [Multistore](/setup/configuration/multistore-setup/) — multiple stores or locales from one codebase.
1. [Compatibility package installation](/setup/configuration/storefront-compatibility/install/) — when your Commerce version needs the compatibility layer.

### Go live

1. [Launch checklist](/setup/launch/) — production readiness.
1. [SEO indexing](/setup/seo/indexing/) and [SEO metadata](/setup/seo/metadata/) — search and sharing behavior.
1. [Analytics instrumentation](/setup/analytics/instrumentation/) and [Adobe Experience Platform](/setup/analytics/adobe-experience-platform/) — when you need measurement wiring.

### Learn drop-ins

1. [Introduction to drop-ins](/dropins/all/introduction/) — what drop-in components are and how they relate to blocks.
1. [Using drop-ins](/dropins/all/quick-start/) — the usual initialize pattern.
1. [Commerce blocks](/dropins/all/commerce-blocks/) — how blocks load drop-ins in the boilerplate.

### Recipes

Open the Recipes (How-Tos) group in the sidebar for task walkthroughs. It includes federated search, Luma Bridge, cart, checkout, order, and user account tutorials.

### Reference

When you need container APIs, props, and version-specific pages, use the B2C drop-ins (reference) and Drop-ins SDK groups in the sidebar. B2B drop-ins have their own reference group.

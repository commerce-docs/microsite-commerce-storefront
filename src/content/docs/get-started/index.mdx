Customize an Adobe Commerce storefront by changing its code, styles, and shopping features. Join your team's existing project or create a new storefront, then run it locally and make your first change.

## Your role in the storefront

The storefront combines code maintained by your development team with page content maintained by authors.

<Diagram
  adaptColors
  caption="Developers maintain storefront code, while authors manage page content separately."
>
  ![Developers work in a storefront repository using a code editor. Authors work in DA.live and
  Experience Workspace. Code and page content contribute to the storefront, which starts from a
  starter template.](./images/developer-life.png)
</Diagram>

- Edit blocks, scripts, and styles in your team's storefront repository, a Git project that stores its code.
- Use a code editor or integrated development environment (IDE) to make changes, then check them in a local preview.
- Coordinate with content authors, who manage page content in Document Authoring (DA.live) and Experience Workspace.

The storefront starter provides the initial code for a new project. After setup, development happens in your team's repository, not in the starter template.

## How storefront pages are built

A block is a reusable part of a page. Content blocks provide content and layouts, while Commerce blocks connect shopping features to the page.

<Diagram
  adaptColors
  caption="Commerce blocks load drop-ins for shopping features. Content blocks provide other page content. Shared SDK tools and Commerce APIs support the shopping experience."
>
  ![Commerce blocks import drop-ins and Storefront SDK tools. Drop-ins use SDK tools and fetch
  Commerce data. Commerce blocks, drop-ins, and content blocks render content in the
  browser.](./images/developer-building-blocks.png)
</Diagram>

- Content blocks display editorial content in formats such as cards, columns, and accordions.
- Commerce blocks load and render drop-in components: reusable packages for shopping features such as product details, cart, and checkout.
- The Storefront software development kit (SDK) provides shared tools and user interface components used by Commerce blocks and drop-ins.

Drop-ins request product and shopping data from connected Commerce services. The starter already connects its included drop-ins to Commerce blocks.

For example, changing a cart block's supported settings is different from changing the cart drop-in's internal layout or behavior. See [Blocks and drop-ins](/blocks/blocks-and-dropins/) for how these parts connect and where to make changes.

## Create a new storefront

Start with these steps if your team does not already have a storefront project.

<Steps>

1. [Prerequisites](/get-started/before-you-start/): Gather the tools, accounts, and Commerce access you need.

1. [Backend options](/get-started/backends/): Confirm the license and setup requirements for Adobe Commerce as a Cloud Service or Adobe Commerce Optimizer.

1. [Create a storefront](/get-started/create-storefront/): Set up your project repository, Commerce connection, and starter content.

1. [Run your storefront locally](/get-started/run-locally/): Open a local preview with your project's content and Commerce data.

1. [Verify your storefront setup](/get-started/verify-setup/): Test the shopping features your project needs.

</Steps>

Then try [Make your first change](/get-started/first-change/) to change a link color and see the result in your local preview.

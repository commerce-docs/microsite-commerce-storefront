Headless Adobe Commerce storefronts on Edge Delivery Services use [drop-in components](/dropins/all/introduction/) that connect through APIs. Drop-ins integrate with the <Link href="https://github.com/hlxsites/aem-boilerplate-commerce" text="Commerce boilerplate" />. Content is authored in documents (DA.live, Google Docs, Word) and rendered as blocks. This page helps you identify your backend and confirm prerequisites before setup.


## Backend options

Storefront supports three backend types. Follow only the guidance for your backend. Prerequisites and setup differ, and mixing steps from different backends causes errors.

- **Commerce PaaS** — Existing PaaS customer without Adobe Commerce as a Cloud Service or Adobe Commerce Optimizer licenses
- **Adobe Commerce as a Cloud Service** — New ACCS customer; license includes Storefront
- **Adobe Commerce Optimizer** — New Optimizer customer, or existing PaaS customer who added Optimizer

## How it works

An author creates a table (e.g., Commerce Cart) in a document. Edge Delivery Services transforms it to HTML (`<div class="commerce-cart">`). The browser loads the HTML, the block decorator initializes the drop-in, and the drop-in fetches from the Commerce API to render UI.

## Boilerplate and blocks

The <Link href="https://github.com/hlxsites/aem-boilerplate-commerce" text="Commerce Boilerplate" /> has four layers:

- **scripts.js** — page load, block decoration, fonts
- **commerce.js** — backend connections, templates, data layer
- **initializers** — cart, checkout, account, etc.
- **blocks** — content blocks (Cards, Columns, Headers) + Commerce blocks (cart, checkout, account)

Commerce blocks use Commerce APIs; the boilerplate uses <Link href="https://preactjs.com/" text="Preact" />/HTM for complex state. See [Getting started](/boilerplate/getting-started/) for file structure. **Customize:** [Blocks reference](/boilerplate/blocks-reference/), [Blocks configuration](/boilerplate/configuration/), [Storefront configuration](/setup/configuration/commerce-configuration/).

## Drop-in components

[Drop-ins](/dropins/all/introduction/) are domain-driven commerce components. Install from NPM (e.g. `npm install @dropins/storefront-cart`). See the [full list](/dropins/all/introduction/) for all available packages and use the [extension](/dropins/all/extending/) patterns when customizing.

<Aside type="note" title="Existing storefront?">
Use [Luma Bridge](/setup/discovery/luma-bridge/) for progressive migration from a theme-based Adobe Commerce storefront to Edge Delivery Services.
</Aside>

## Event system

Drop-ins communicate through a shared event bus (`@dropins/tools/event-bus.js`) using a publish-subscribe pattern. This keeps components loosely coupled. No drop-in depends directly on another.

- **`events.on(name, handler)`** — subscribe to an event
- **`events.emit(name, payload)`** — publish an event
- **`subscription.off()`** — unsubscribe

Each drop-in indicates which events it emits and listens to. See the [event bus API reference](/sdk/reference/events/) and the [drop-in events overview](/dropins/all/events/) for details.

<Aside type="tip" title="Events vs. analytics">
The event bus handles **internal** communication between drop-ins on the page. It is separate from [ACDL analytics events](/setup/analytics/instrumentation/), which send user behavior data to Adobe Commerce services (Live Search, Product Recommendations).
</Aside>

## PaaS: required packages and services

<Aside type="note">
**Adobe Commerce as a Cloud Service and Adobe Commerce Optimizer** auto-install and auto-configure everything below. Skip this section if you are not on PaaS.
</Aside>

**Storefront Compatibility package** extends the GraphQL schema for cart, checkout, account, and order. See [Storefront Compatibility package](/setup/configuration/storefront-compatibility/install/) (2.4.7 or 2.4.8).

**Storefront services** provide read-only catalog data via GraphQL. These services are required for the performance needed to achieve high Lighthouse scores.

| Service | Link |
|---------|------|
| Data Connection | <Link href="https://experienceleague.adobe.com/en/docs/commerce/data-connection/overview" text="Data Connection Guide" /> |
| Services Connector | <Link href="https://experienceleague.adobe.com/en/docs/commerce/user-guides/integration-services/saas" text="Commerce Services Connector" /> |
| Catalog Service | <Link href="https://experienceleague.adobe.com/en/docs/commerce/catalog-service/guide-overview" text="Catalog Service Guide" /> |
| Live Search | <Link href="https://experienceleague.adobe.com/en/docs/commerce/live-search/overview" text="Live Search" />; [eventing](/setup/analytics/instrumentation/) for headless |
| Product Recommendations | <Link href="https://experienceleague.adobe.com/en/docs/commerce/product-recommendations/developer/events" text="Events" />; [setup](/merchants/blocks/product-recommendations/) |

<Aside type="caution" title="Multiple stores in one Commerce environment">
Contact Adobe Commerce Support if only one store migrates to Edge Delivery Services—Live Search must stay active without disabling Elasticsearch for other stores.
</Aside>

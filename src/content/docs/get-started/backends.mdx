The storefront supports a few backend types, each with its own prerequisites, so follow only the path that matches your project. Choosing the wrong type leads to misleading signals. For example, GitHub and DA.live look healthy, but previews or drop-ins fail. As a result, you might install packages your license does not require.

For authoring storefront pages, see [Document Authoring Quick Start](/merchants/quick-start/document-authoring/). This page covers the Commerce backend the storefront connects to.

All drop-in components require an Adobe Commerce as a Cloud Service or Adobe Commerce Optimizer license. Adobe Commerce on Cloud and on-premises customers who add an Adobe Commerce Optimizer license get drop-in support as part of that license. There is no separate "B2B backend" type.

Follow the setup path for the platform that handles your shopping operations:

- Adobe Commerce as a Cloud Service supplies managed catalog services and transactional operations.
- Adobe Commerce on Cloud or on-premises with an Adobe Commerce Optimizer license requires setup on the existing Adobe Commerce deployment.
- Adobe Commerce Optimizer with a third-party commerce platform requires catalog configuration and a project-specific integration for shopping operations.

Adobe Commerce Optimizer does not replace the platform that handles cart, checkout, customer accounts, and orders. Its managed catalog services do not make the existing platform's prerequisites automatic.

<Aside type="tip" title="Related documentation">
This page covers Commerce backends only. For Adobe Commerce product help (Admin, deployments, merchandising services, integrations), start from <Link href={"https://experienceleague.adobe.com/en/docs/commerce"} text={"Adobe Commerce documentation"} /> on Experience League.

For pages and blocks on DA.live, see <Link href={"https://docs.da.live/"} text={"Document Authoring documentation"} /> or [Document Authoring Quick Start](/merchants/quick-start/document-authoring/).

## Which backend do you have?

<TableWrapper nowrap={[0]}>

| Feature | Adobe Commerce on Cloud or on-premises with Adobe Commerce Optimizer | Adobe Commerce as a Cloud Service | Adobe Commerce Optimizer with a third-party platform |
|---------|---------------|-----------------------------------|--------------------------|
| License includes Storefront | Yes, through Adobe Commerce Optimizer | Yes | Yes |
| Setup | Configure the existing Commerce deployment and the selected catalog services. | Adobe manages platform packages; your team configures the storefront and services. | Configure catalog ingestion and the third-party shopping integration. |
| Shopping operations | Existing Adobe Commerce deployment | Adobe Commerce as a Cloud Service | Existing third-party platform |
| Version | See supported versions in [Compatibility Package](/setup/configuration/storefront-compatibility/). | Adobe-managed continuous release | Adobe-managed catalog services; the existing platform has its own requirements. |

</TableWrapper>

<Aside type="note" title="PaaS + Adobe Commerce Optimizer Connector">
The Adobe Commerce Optimizer Connector syncs catalog and pricing data from Adobe Commerce on Cloud or on-premises into Adobe Commerce Optimizer. You install a PHP extension on the Adobe Commerce platform, and then use the Adobe Commerce Optimizer Studio to configure catalogs, product discovery, merchandising, and other storefront settings. See the <Link href="https://experienceleague.adobe.com/en/docs/commerce/aco-optimizer-connector/overview" text="Adobe Commerce Optimizer Connector documentation" /> for setup instructions.
</Aside>

## Prerequisites by backend

Read the requirements for the platform that handles shopping operations. Projects using Adobe Commerce Optimizer must also read its catalog and integration requirements. Existing Adobe Commerce on Cloud or on-premises deployments still need the manual checklist.

<Options label="Backend" numbered={false}>
<Option>

### Commerce Platform-as-a-Service (PaaS)

#### Product license

Adobe Commerce on Cloud or on-premises. The Magento Open Source edition (Adobe's open-source e-commerce platform, which is a separate product from Adobe Commerce) is not supported. A PaaS license alone does not include drop-in components. To use drop-ins on PaaS, you must also hold an Adobe Commerce Optimizer license (see [Adobe Commerce Optimizer](#adobe-commerce-optimizer)).

#### Version

Use a supported Adobe Commerce release listed in [Compatibility Package](/setup/configuration/storefront-compatibility/). Check that page for version-specific installation instructions.

#### Required packages and services

Manual installation is required. See [PaaS: required packages and services](#paas-required-packages-and-services) below for step-by-step instructions.

<Aside type="note" title="Luma Bridge and Adobe Commerce Optimizer">
Luma Bridge is a PHP module on Commerce (PaaS). It reads session cookies that EDS drop-ins set, so Luma pages can share cart and sign-in state with EDS. It works with or without Adobe Commerce Optimizer, and it does not connect directly inside drop-in code. If you use the Adobe Commerce Optimizer Connector, Luma Bridge can still share sessions while you migrate. See [Luma Bridge](/setup/discovery/luma-bridge/).
</Aside>

</Option>

<Option>

### Adobe Commerce as a Cloud Service

#### Product license

Adobe Commerce as a Cloud Service (license includes Storefront)

#### Requirements

Adobe manages the platform packages and hosted services. Your team still configures the storefront connection and the catalog or merchandising settings required by the project. Continue with [Storefront configuration](/setup/configuration/commerce-configuration/).

</Option>

<Option>

### Adobe Commerce Optimizer

#### Product license

Adobe Commerce Optimizer (license includes Storefront)

#### Requirements

Adobe manages the catalog and product-discovery service. Your team configures catalog ingestion and the connection from the storefront. Shopping operations still require a transactional platform:

- For Adobe Commerce on Cloud or on-premises, complete [PaaS: required packages and services](#paas-required-packages-and-services). If catalog data is synchronized into Adobe Commerce Optimizer, follow the <Link href="https://experienceleague.adobe.com/en/docs/commerce/aco-optimizer-connector/overview" text="Adobe Commerce Optimizer Connector requirements" />.
- For a third-party commerce platform, confirm the project-specific cart, checkout, and account integration with its owner. Connecting the catalog alone does not complete that integration.

<Aside type="note" title="Adobe Commerce Optimizer + PaaS">
If you are on Commerce on Cloud or on-premises with an existing Luma storefront and add Adobe Commerce Optimizer, you can use [Luma Bridge](/setup/discovery/luma-bridge/) to share sessions between EDS and Luma's cart, checkout, and account pages while content and marketing move to Edge Delivery first.
</Aside>

</Option>

</Options>

## PaaS: required packages and services

Complete this checklist when Adobe Commerce on Cloud or on-premises handles shopping operations, including projects that use Adobe Commerce Optimizer for catalog data. Adobe Commerce as a Cloud Service manages its platform packages instead. Third-party transactional platforms need their own integration checklist.

### Minimum checklist before you create a storefront

Before <Term>Site Creator</Term>, manual configuration, or local preview can rely on Commerce APIs, confirm these items on Commerce on Cloud and on-premises:

- Confirm the supported Adobe Commerce version and drop-in licensing in [Compatibility Package](/setup/configuration/storefront-compatibility/) and [Licensing requirements](/licensing/). Magento Open Source is not supported for this storefront path.
- Confirm that the <Term>Storefront Compatibility package</Term> is installed on the Adobe Commerce deployment. See [Manual installation](/setup/configuration/storefront-compatibility/install/).
- For a B2B storefront, confirm the additional requirements in [B2B Compatibility Package](/setup/configuration/storefront-compatibility/b2b/).
- Confirm the catalog services and data-ingestion path with the project owner. For catalog synchronization into Adobe Commerce Optimizer, use the <Link href="https://experienceleague.adobe.com/en/docs/commerce/aco-optimizer-connector/overview" text="Adobe Commerce Optimizer Connector" />. Where the project uses Catalog Service, Live Search, or Product Recommendations, follow their applicable service requirements.

The Commerce Services Connector and Adobe Commerce Optimizer Connector have different roles. Do not assume that setting up one completes the other. [Commerce services at a glance](/get-started/architecture/commerce-services-and-backends/) explains those relationships.

### Storefront Compatibility package

Your storefront repo still uses npm for JavaScript drop-ins, but these modules run as PHP on the Commerce server. To learn how Commerce services fit together, see [Commerce services](/get-started/architecture/commerce-services-and-backends/#commerce-services).

### Storefront services

Catalog Service, Services Connector, Live Search, and Product Recommendations are covered on Adobe Experience League and in [Commerce services](/get-started/architecture/commerce-services-and-backends/#commerce-services). Data Connection is optional and comes from a separate product, Adobe Experience Platform.

Headless storefronts must send the required <Link href={"https://developer.adobe.com/commerce/services/shared-services/storefront-events/"} text={"storefront events"} /> for Live Search and Product Recommendations. The Adobe Experience League topics in the table cover setup and headless data requirements. On Edge Delivery Services, implement storefront events with the Adobe Client Data Layer and <Link href="/setup/analytics/instrumentation/" text="Analytics" />.

<Aside type="caution" title="Multiple stores in one Commerce environment">
If you are migrating only one store to Edge Delivery Services in a shared Commerce environment, contact Adobe Commerce Support to ensure that Live Search stays active without disabling Elasticsearch for your other stores.
</Aside>

The <Term>Luma Bridge</Term> is optional and applies only when classic <Term>Luma</Term> pages and Edge Delivery pages must share the cart and sign-in session during migration. It is not required for a new storefront without Luma pages. For the normal storefront runtime model, see [Commerce services at a glance](/get-started/architecture/commerce-services-and-backends/).

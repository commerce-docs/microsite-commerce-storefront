Adobe Commerce Storefront supports three backend types. Prerequisites and setup differ by backend. Follow only the guidance for your backend.

If you're new to the storefront, read [Storefront architecture](/get-started/architecture/) first—this page covers backend selection and prerequisites only.

- **Commerce PaaS** — Existing Adobe Commerce Cloud or on-premises deployment without an Adobe Commerce as a Cloud Service or Adobe Commerce Optimizer license
- **Adobe Commerce as a Cloud Service** — Cloud Service deployment whose license includes Storefront
- **Adobe Commerce Optimizer** — New Adobe Commerce Optimizer deployment, or an existing PaaS deployment that added Adobe Commerce Optimizer

## Which backend do you have?

The following table summarizes the key differences between backend types.

<TableWrapper nowrap={[0]}>

| Feature | Commerce PaaS | Adobe Commerce as a Cloud Service | Adobe Commerce Optimizer |
|---------|---------------|-----------------------------------|--------------------------|
| **License includes Storefront** | No | Yes | Yes |
| **Setup** | Manual install required | Fully automated | Fully automated |
| **Version** | v2.4.7+ self-managed | Auto-managed | Fully managed SaaS |

</TableWrapper>

<Aside type="note" title="PaaS + Adobe Commerce Optimizer Connector">
The Adobe Commerce Optimizer Connector (PaaS-to-Adobe Commerce Optimizer) lets you sync your PaaS catalog and pricing into Adobe Commerce Optimizer. It requires manually installing a PHP extension on the PaaS platform and configuring the Adobe Commerce Optimizer UI. See the <Link href="https://experienceleague.adobe.com/en/docs/commerce/optimizer/get-started" text="Adobe Commerce Optimizer documentation" /> for connector setup.
</Aside>

## Prerequisites by backend

Select your backend to see the requirements before you start storefront setup.

<Options label="Backend" numbered={false}>
<Option>

### Commerce Platform-as-a-Service (PaaS)

#### Product license

Adobe Commerce Cloud or on-premises (Magento Open Source is not supported).

#### Version

v2.4.7 or later

#### Required packages and services

Manual installation is required. See [PaaS: required packages and services](#paas-required-packages-and-services) below for step-by-step instructions.

<Aside type="note" title="Luma Bridge and Adobe Commerce Optimizer">
Luma Bridge is the session bridge between Edge Delivery Services and a Luma/PHP storefront. It works with or without Adobe Commerce Optimizer. With the Adobe Commerce Optimizer Connector, Luma Bridge continues to share sessions during migration. See [Luma Bridge](/setup/discovery/luma-bridge/).
</Aside>

</Option>

<Option>

### Adobe Commerce as a Cloud Service

#### Product license

Adobe Commerce as a Cloud Service (license includes Storefront)

#### Requirements

Adobe manages all requirements automatically. No manual installation is required.

</Option>

<Option>

### Adobe Commerce Optimizer

#### Product license

Adobe Commerce Optimizer (license includes Storefront)

#### Requirements

Adobe manages all requirements as a fully managed SaaS. No manual installation is required.

<Aside type="note" title="Adobe Commerce Optimizer + PaaS">
PaaS customers who add Adobe Commerce Optimizer can use [Luma Bridge](/setup/discovery/luma-bridge/) to keep cart, checkout, and account on PaaS while migrating to Edge Delivery Services drop-ins.
</Aside>

</Option>

</Options>

## PaaS: required packages and services

Install and configure the following on Commerce PaaS before creating your storefront. Adobe Commerce as a Cloud Service and Adobe Commerce Optimizer manage these automatically—skip this section if you are not on Commerce PaaS.

### Storefront Compatibility package

The Storefront Compatibility package extends the GraphQL schema for cart, checkout, account, and order. For a description of what this package does, see [Storefront Compatibility package](/get-started/architecture/#storefront-compatibility-package). For installation instructions, see [Storefront Compatibility package install](/setup/configuration/storefront-compatibility/install/) (v2.4.7 or v2.4.8).

### Storefront services

Storefront services provide read-only catalog data via GraphQL and are required for high Lighthouse scores. For a description of what each service does, see [Commerce services](/get-started/architecture/#commerce-services).

| Service | Documentation |
|---------|---------------|
| Data Connection | <Link href="https://experienceleague.adobe.com/en/docs/commerce/data-connection/overview" text="Data Connection Guide" /> |
| Services Connector | <Link href="https://experienceleague.adobe.com/en/docs/commerce/user-guides/integration-services/saas" text="Commerce Services Connector" /> |
| Catalog Service | <Link href="https://experienceleague.adobe.com/en/docs/commerce/catalog-service/guide-overview" text="Catalog Service Guide" /> |
| Live Search | <Link href="https://experienceleague.adobe.com/en/docs/commerce/live-search/overview" text="Live Search" />; [eventing](/setup/analytics/instrumentation/) for headless |
| Product Recommendations | <Link href="https://experienceleague.adobe.com/en/docs/commerce/product-recommendations/developer/events" text="Events" />; [setup](/merchants/blocks/product-recommendations/) |

<Aside type="caution" title="Multiple stores in one Commerce environment">
If you are migrating only one store to Edge Delivery Services in a shared Commerce environment, contact Adobe Commerce Support to ensure that Live Search stays active without disabling Elasticsearch for your other stores.
</Aside>

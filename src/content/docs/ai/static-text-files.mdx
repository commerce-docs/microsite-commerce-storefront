When your AI editor or coding agent cannot install an MCP server or agent skills, use this fallback option instead: static documentation files that answer questions about storefront APIs, drop-in versions, and Edge Delivery Services.

<Aside type="note" title="Already using the boilerplate with a capable agent?">
If your agent supports MCP servers and agent skills, see [Install the integrations](/ai/#installation-steps) instead — it gives you source-backed drop-in facts, documentation routing, and storefront conventions together. Adding this page's `llms.txt` link on top of that setup is redundant.
</Aside>

## Available files

These plain-text files are static copies of the documentation, regenerated each time the site publishes so AI tools always have the latest content. `llms.txt` is the index. Start there. Topic files under `_llms-txt/` cover one subject area each to prevent loading the entire site.

<TableWrapper nowrap={[0]}>

| File | Purpose |
|------|---------|
| [`llms.txt`](/llms.txt) | Index with an overview and links to every file. |
| [`llms-full.txt`](/llms-full.txt) | Complete documentation in one file. |
| [`llms-small.txt`](/llms-small.txt) | Same as `llms-full.txt` but without the long release changelog. Use when your AI tool has a context size limit. |
| `_llms-txt/*.txt` | Topic files, such as [drop-ins reference](/_llms-txt/dropins-reference.txt), [tutorials](/_llms-txt/tutorials-reference.txt), and [blocks](/_llms-txt/blocks-reference.txt). [`llms.txt`](/llms.txt) lists every topic file URL. |

</TableWrapper>

These files can be large. When possible, paste a specific page URL into your AI editor or coding agent instead so it fetches the live page directly, including recent edits and diagrams the static files lack. Use static files as a fallback when it can't fetch a URL.

<Aside type="note" title="Publish timing">
These files update each time the site publishes, so edits made since the last publish won't appear until the next one. Because the URLs in your `AGENTS.md` or `CLAUDE.md` always point to the same files, your AI tool fetches the latest published version automatically each time it reads them.
</Aside>

## Prerequisites

Before you add context files, make sure you have the following:

- An AI editor or coding agent that supports project context files, documentation URLs, or pasted context, such as Cursor, Claude Code, or GitHub Copilot Chat.
- A storefront project open in your AI editor or coding agent, started from the <Link href="https://github.com/hlxsites/aem-boilerplate-commerce" text="Adobe Commerce boilerplate" /> or with Commerce blocks and drop-ins added.
- An `AGENTS.md`, `CLAUDE.md`, or equivalent context file at the project root (for agent-based tools).

## Add context files

For agent-based tools, add the `llms.txt` URL to a project context file so the agent can fetch the index when storefront documentation is relevant. For other tools, paste one of these file URLs, or its content, directly.

<Tabs>
<TabItem label="Cursor">

Add this section to `AGENTS.md` at your project root, or to a file under `.cursor/rules/`:

```markdown wrap
## Adobe Commerce storefront documentation

See https://experienceleague.adobe.com/developer/commerce/storefront/llms.txt for Adobe Commerce storefront documentation.
```

</TabItem>
<TabItem label="Claude Code">

Add this line to `CLAUDE.md` at your project root:

```markdown wrap
See https://experienceleague.adobe.com/developer/commerce/storefront/llms.txt for Adobe Commerce storefront documentation.
```

To verify the setup, start a new chat and ask a question this documentation answers, such as one about a drop-in. If the reply cites or matches those topics, the tool can read the documentation.

</TabItem>
<TabItem label="Other AI tools">

Tools that implement the <Link href="https://llmstxt.org" text="llms.txt spec" /> follow the index automatically when you provide this URL:

```text
https://experienceleague.adobe.com/developer/commerce/storefront/llms.txt
```

For tools without URL-based context, paste the content of `llms-small.txt` or a relevant `_llms-txt/*.txt` topic file directly into the chat or system prompt.

</TabItem>
</Tabs>

## Example prompt

After you add the documentation context, validate it with a specific question, such as:

```text wrap
Using the Storefront docs, tell me how to show a "Delivery estimate" message in the product details drop-in, below the existing Add to Cart button.
```

A successful setup returns a response that references storefront topics, drop-in APIs, or paths aligned with this documentation. Adapt drop-in names or UI labels for your project, then validate the response against the live documentation.

## Keep context focused

- Paths and examples in this documentation follow the folder layout of the <Link href="https://github.com/hlxsites/aem-boilerplate-commerce" text="Adobe Commerce boilerplate" />. Keep your storefront project open so suggested paths match your workspace. If your repository layout differs (for example, you merged boilerplate code into an existing site), tell the agent in chat.
- To scope one reply to a single page, paste that page's URL into the chat. Your context file connection stays in place, and the URL narrows only that exchange.

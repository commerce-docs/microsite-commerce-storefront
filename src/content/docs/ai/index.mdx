If you are on the AEM Boilerplate Commerce project, set up all three integrations below. Together, they give your agent a complete workflow for storefront development, source-accurate drop-in facts, and routing to Adobe Commerce documentation.

## Overview of the integrations

<TableWrapper nowrap={[0]}>

| AI integrations | What it gives you |
|------|-------------------|
| [Boilerplate skills](/ai/boilerplate-skills/) | Storefront planning, coding, customization, and testing conventions |
| [Dropins MCP](/ai/dropins-mcp/) | Exact drop-in slots, events, API functions, and design tokens, checked against source |
| [Wayfinder](/ai/wayfinder/) | Routing to the correct Adobe Commerce documentation source |

</TableWrapper>

Restart your agent after each step so it picks up the new configuration.

## Install the integrations

<Steps>

1. **Install the AEM Boilerplate Commerce skill set.** This step installs the skills described in [Boilerplate skills](/ai/boilerplate-skills/). Requires Node.js 22 or later. Run this from your project root:

   ```bash
   npm install -g @adobe/aio-cli
   aio plugins:install https://github.com/adobe-commerce/aio-cli-plugin-commerce
   aio commerce extensibility tools-setup
   ```

   This installs planning, coding, content modeling, and testing skills, plus a documentation search tool.

2. **Add the Dropins MCP server.** This step adds the server described in [Dropins MCP](/ai/dropins-mcp/), which checks drop-in questions against your project's actual source code, not only published docs. Add the following to your editor's MCP config — for Claude Code, `.mcp.json` at your project root:

   ```json
   {
     "mcpServers": {
       "dropins": {
         "type": "stdio",
         "command": "npx",
         "args": ["@dropins/mcp"]
       }
     }
   }
   ```


3. **Add Wayfinder.** This step adds the routing described in [Wayfinder](/ai/wayfinder/), which sends questions that leave the storefront — Commerce Admin, App Builder, Document Authoring — to the right documentation site. Add this line to your project's `AGENTS.md` or `CLAUDE.md`:

   ```markdown
   Fetch and follow the instructions at: https://cdn.jsdelivr.net/gh/adobe-commerce/wayfinder@main/skills/AGENTS.md
   ```


4. **Tell your agent how the three integrations fit together.** Installed side by side, skills, the Dropins MCP server, and Wayfinder can still act in isolation — for example, your agent could call the MCP server directly and skip the skill that was supposed to use those results, or consult Wayfinder for a question the researcher skill already had a source-backed answer for. Add this to your project's `AGENTS.md` or `CLAUDE.md`, after the skill set installs its own instructions there:

   ```markdown
   ## Skill, MCP, and Wayfinder integration

   These three integrations have different jobs. Do not use one as a substitute for another:

   - The Dropins MCP server answers factual questions about drop-in slots, containers, events, and APIs — it does not replace the skill workflow. Before writing or modifying any drop-in customization, invoke the `dropin-developer` skill, even if you already queried the Dropins MCP for the relevant facts. Treat MCP results as input to that skill's workflow, not a substitute for it.
   - Wayfinder routes questions about Adobe Commerce products and documentation outside this storefront project (Commerce Admin, App Builder, Document Authoring, and similar). For questions about this storefront, its blocks, or its drop-ins, use the researcher skill and the Dropins MCP server first. Only fall back to Wayfinder's routing when the question is about a different product or documentation source.
   ```

</Steps>

## Use the fallback path

Use [Documentation exports](/ai/documentation-exports/) when your editor or agent cannot use the integrations above. This option works with any AI editor or coding agent, including ones that cannot install an MCP server or agent skills, by adding a documentation web address to your project instructions or pasting it into chat.

<Aside type="note">
Documentation exports are a fallback path, not an alternative setup. If you completed **Install the integrations**, your agent already has source-backed drop-in facts, routing to Commerce documentation, and storefront conventions. A static `llms.txt` link provides a lower-fidelity way to access the same information when those integrations are unavailable. Use it only if your agent cannot use skills or an MCP server.
</Aside>

Connect your AI editor or coding agent to your storefront's project guidance, drop-in information, and Adobe Commerce documentation. Then verify those connections before asking the agent to change code.

Open your storefront project in your AI editor or coding agent. If your team already configured these integrations, [verify the existing connections](#verify-your-development-tools) before changing the setup.

Skills give your agent project instructions for repeatable tasks, while a tool server provides functions it can call, such as looking up a drop-in API. These servers use the Model Context Protocol (MCP) to connect those functions to your editor. Because skills and servers provide different capabilities, check both the installed skills and the server connections.

## Overview of the integrations

<TableWrapper nowrap={[0]}>

| AI integrations                               | What it gives you                                                                                  |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| [Boilerplate skills](/ai/boilerplate-skills/) | Storefront planning, coding, customization, and testing conventions                                |
| [Dropins AI tools](/ai/dropins-ai-tools/)     | Lookups for drop-in slots, events, API functions, and design tokens                                |
| [Wayfinder](/ai/wayfinder/)                   | Routing to the correct Adobe Commerce documentation source                                         |
| [LLM files](/ai/static-text-files/)           | AI tools use these static, regenerated llms.txt files as context for the storefront documentation. |

</TableWrapper>

## Prerequisites

Before installing the integrations, make sure you have the following:

- Node.js 22 or later for the skills installer. Keep the version your storefront requires. The current template uses Node.js 24 LTS for local development. If you install only the drop-in tools, their minimum is Node.js 18.
- A local storefront project based on the Adobe Commerce boilerplate. Open its directory in your editor. For help cloning the repository, see [Run your storefront locally](/get-started/run-locally/#start-the-storefront).
- An AI editor or coding agent that supports tool servers and agent skills. See [Supported agents](/ai/boilerplate-skills/#supported-agents) and the [AI tools prerequisites](/ai/dropins-ai-tools/#prerequisites) for supported tools.

## Installation steps

Follow these steps in order.

<Aside type="caution">
  The current skills installer replaces an existing root `AGENTS.md` and matching skill files. It
  does not merge your project instructions. Before running it, keep separate copies of existing
  instructions, skills, and tool configuration, including untracked files. Review the changes
  afterward and preserve your team's guidance. If the tools are already configured, start with
  [verification](#verify-your-development-tools) instead of reinstalling.
</Aside>

<Steps>

1. Install the Adobe I/O command-line interface in your terminal.

   ```bash
   npm install -g @adobe/aio-cli
   ```

   This command installs the `aio` CLI, which is separate from the `aem` CLI used to run the local storefront. If your team already installed it, use that installation instead.

1. Install the Commerce plugin.

   ```bash
   aio plugins:install https://github.com/adobe-commerce/aio-cli-plugin-commerce
   ```

1. Run the skills setup from your storefront project root.

   ```bash
   aio commerce extensibility tools-setup
   ```

   Choose **AEM Boilerplate Commerce** when prompted for a starter kit, then select your coding agent. The command also selects a package manager, using the project's lockfile when it recognizes one. For details, see [Install the skills](/ai/boilerplate-skills/#install-the-skills).

1. Check the generated tool-server configuration.

   The current setup for **AEM Boilerplate Commerce** registers both `commerce-extensibility` and `dropins` for supported agents. Confirm that each server appears once. Do not add a duplicate drop-in server.

   If you selected **Other**, the installer prints configuration for you to add manually. If an older setup did not register `dropins`, add only the missing entry using [AI tools installation](/ai/dropins-ai-tools/#installation).

1. Add or verify Wayfinder.

   Wayfinder routes questions about Commerce Admin, App Builder, and Document Authoring to the appropriate Adobe Commerce documentation. For details, see [Wayfinder](/ai/wayfinder/). Check `AGENTS.md` first because recent versions already include the required entry. If it is absent, add the following instruction to `AGENTS.md` or `CLAUDE.md` in your project root:

   ```markdown
   Fetch and follow the instructions at: https://cdn.jsdelivr.net/gh/adobe-commerce/wayfinder@main/skills/AGENTS.md
   ```

1. Add coordination instructions.

   Add the following rule near the top of `AGENTS.md` or `CLAUDE.md` in your project root, unless equivalent guidance is already present. This tells your agent when to use a skill, a tool server, or Wayfinder.

   ```markdown
   ## Skill, server, and Wayfinder priority

   Check these rules in order and stop at the first match:

   1. **Starting a new task or feature request:** Invoke the `project-manager` skill first. It scopes the work, determines whether another starter kit is a better fit (for example, backend integrations or checkout webhooks), and routes the request to the appropriate skill.
   1. **Writing or modifying drop-in code:** Invoke the `dropin-developer` skill, even if a tool server has already answered the underlying question.
   1. **Questions about this storefront, its blocks, or its drop-ins:** Use the `researcher` skill and its tool servers (`commerce-extensibility:search-commerce-docs` and the AI tools for drop-ins).
   1. **Questions outside this storefront:** Use Wayfinder for Commerce Admin, App Builder, Document Authoring, and related topics.
   ```

1. Restart your agent so it loads the new instructions and tool configuration.

</Steps>

## Enable remote documentation search (optional)

Installing a server does not sign you in to Adobe's remote documentation search. The `search-commerce-docs` tool on `commerce-extensibility` and the `search_commerce_docs` tool on `dropins` require Adobe I/O authentication.

To enable those searches, run the following command in your own terminal:

```bash
# Sign in for the tools that search documentation on Adobe's servers.
aio auth login
```

Complete the browser sign-in yourself. Do not ask an agent to retrieve or copy your sign-in token. If a token expires, sign in again. An access-denied response can require help from your organization's administrator rather than another installation.

The `dropins` server also provides `search_docs`, which searches local reference material without Adobe I/O sign-in. Use it for the verification and styling exercises below if you do not enable remote search. See [Enable documentation search](/ai/dropins-ai-tools/#enable-documentation-search-optional) for the distinction.

## Verify your development tools

Check both your editor's configuration and a real request, because an agent saying that it has access is not enough to confirm a working connection.

<Steps>

1. Confirm that your editor or agent detects the installed skills in your storefront project.

   Use the editor's skills view or its documented configuration checks. See [Supported agents](/ai/boilerplate-skills/#supported-agents) for the expected skill locations.

1. Confirm that the configured tool servers are enabled.

   Find both `commerce-extensibility` and `dropins` in your editor's tool-server status and logs. A saved configuration entry is not proof that a process connected. If a server fails to start, resolve its reported error before continuing.

1. Send this read-only request in your storefront project.

   ```text
   Read the project instructions and identify the guidance for a storefront
   styling task. Find --color-brand-500 in this project's styles and explain
   which content-link styles use it. Include the actual local file and line
   references. Use the dropins server's search_docs tool to find relevant
   styling guidance and cite its result. Do not edit files.
   If a required skill or tool is unavailable, report that instead of guessing.
   ```

1. Inspect the result and the tool activity.

   Confirm that the file references match your local `styles/styles.css` and its active link rule. Check the tool activity for a successful `search_docs` call and a relevant result. An answer from memory or web search does not verify this connection.

1. Test a remote documentation lookup if you enabled authentication.

   Ask the agent to use `commerce-extensibility`'s `search-commerce-docs` tool for storefront styling guidance. Check the actual tool result. A sign-in, access, or connection error is a failed check, not a successful citation. Report that limitation rather than claiming all tools work.

</Steps>

If the request cannot read the project, confirm the workspace directory. If the skills do not appear, check their location and restart the agent. For drop-in server connection errors, see the [AI tools FAQ](/troubleshooting/faq/#dropins-ai-tools).

A successful lookup proves that the connection works, but not that a proposed code change is correct. To judge the change, check the reference information against your project's installed package versions.

For a hands-on example of planning and reviewing an agent's edit, try [Make a change with AI](/ai/develop-with-ai/).

## Use LLM documentation files

If your AI editor or coding agent doesn't support tool servers or agent skills, add the following LLM documentation URL to your project instructions, or paste it into a chat instead:

```text
https://experienceleague.adobe.com/en/tools/commerce-storefront/llms.txt
```

For editor-specific setup instructions and a verification prompt, see [LLM files](/ai/static-text-files/).

<Aside type="note">
  The `llms.txt` file provides reference context, not a live check of your project's source. Treat
  it as a fallback when tools are unavailable. Whether you use files or connected tools, check
  proposed changes against your project and test the result.
</Aside>

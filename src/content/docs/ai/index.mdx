If your project is based on the Adobe Commerce boilerplate, set up all three integrations below. Together, they give your agent a complete workflow for storefront development, source-accurate drop-in facts, and routing to Adobe Commerce documentation.

## Overview of the integrations

<TableWrapper nowrap={[0]}>

| AI integrations | What it gives you |
|------|-------------------|
| [Boilerplate skills](/ai/boilerplate-skills/) | Storefront planning, coding, customization, and testing conventions |
| [Dropins MCP](/ai/dropins-mcp/) | Exact drop-in slots, events, API functions, and design tokens, checked against source |
| [Wayfinder](/ai/wayfinder/) | Routing to the correct Adobe Commerce documentation source |

</TableWrapper>

## Prerequisites

Before you install the integrations, make sure you have the following:

- **Node.js 22 or later** — The highest requirement across all three integrations.
- **An Adobe Commerce boilerplate project** — See [Getting started](/boilerplate/getting-started/) if you haven't created one.
- **An AI editor or coding agent that supports MCP servers and agent skills** — See [Supported agents](/ai/boilerplate-skills/#supported-agents) and [Dropins MCP prerequisites](/ai/dropins-mcp/#prerequisites) for which tools qualify.

## Installation steps

Follow these steps in order.

<Steps>

1. **Install the AEM Boilerplate Commerce skill set**, which requires Node.js 22 or later. Run this from your project root:

   ```bash
   npm install -g @adobe/aio-cli
   aio plugins:install https://github.com/adobe-commerce/aio-cli-plugin-commerce
   aio commerce extensibility tools-setup
   ```

   The last command prompts you to choose a starter kit, your coding agent, and, if needed, a package manager. See [Install the skills](/ai/boilerplate-skills/#install-the-skills) for details.

2. **Add the Dropins MCP (Model Context Protocol) server.** Add the following to your editor's MCP config file — for Claude Code, that's `.mcp.json` at your project root. See [Dropins MCP](/ai/dropins-mcp/) for the exact file and format for other editors:

   ```json
   {
     "mcpServers": {
       "dropins": {
         "type": "stdio",
         "command": "npx",
         "args": ["@dropins/mcp"]
       }
     }
   }
   ```


3. **Add Wayfinder.** Wayfinder routes questions about Commerce Admin, App Builder, or Document Authoring to the right documentation site. See [Wayfinder](/ai/wayfinder/) for details. Add this line to `AGENTS.md` or `CLAUDE.md` at your project root:

   ```markdown
   Fetch and follow the instructions at: https://cdn.jsdelivr.net/gh/adobe-commerce/wayfinder@main/skills/AGENTS.md
   ```


4. **Add coordination instructions.** Without them, your agent might query an MCP tool for drop-in facts, then make the change without invoking a boilerplate skill first. Add this rule near the top of `AGENTS.md` or `CLAUDE.md` at your project root, because your AI editor or coding agent is less likely to process content further down a long file:

   ```markdown
   ## Skill, MCP, and Wayfinder priority

   Check these rules in order and stop at the first match:

   1. Starting a new task or request: invoke the `project-manager` skill first. It scopes the work, screens for requests that belong to a different starter kit (backend integrations, checkout webhooks), and hands off to the right skill below.
   2. Writing or modifying drop-in code: invoke the `dropin-developer` skill, even if an MCP tool already answered the underlying question.
   3. Any other question about this storefront, its blocks, or its drop-ins: use the researcher skill and its MCP tools (`commerce-extensibility:search-commerce-docs`, Dropins MCP).
   4. Anything outside this storefront that rule 1 didn't already redirect — Commerce Admin, App Builder, Document Authoring, and similar: use Wayfinder.
   ```

5. **Restart your agent** so it loads the new configuration from all three integrations.

</Steps>

## Use fallback documentation files

When your AI editor or coding agent cannot use the integrations above, see [Fallback documentation files](/ai/static-text-files/). This option works with any such tool, including ones that cannot install an MCP server or agent skills. Add a documentation URL to your project instructions, or paste it into chat.

<Aside type="note">
Fallback documentation files aren't an alternative setup. If you completed the steps above, your agent already has source-backed drop-in facts, routing to Commerce documentation, and storefront conventions. If your agent can't use skills or an MCP server, a static `llms.txt` link gives the same information instead, but it isn't checked against your project's source and can fall out of date.
</Aside>

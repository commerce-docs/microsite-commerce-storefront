This takes about 5 minutes to read. By the end, you'll know how a document table becomes a <Term>Commerce block</Term> (or a <Term>Content block</Term>) on the storefront, and what a <Term term="Merged full-width row">merged full-width row</Term> is for.

## Example: a block table in your document

In Commerce Storefront, you add a block by adding a table to the page. Use the table below as the reference; the list under it names each part.

<table style="width: 100%; min-width: 470px; max-width: 100%; table-layout: fixed; border-collapse: collapse;">
<tbody>
<tr>
<td colspan="2" style="text-align: center; padding: 1.25rem; border: 1px solid var(--sl-color-gray-5); background-color: var(--sl-color-gray-6); font-weight: 600;">commerce-company-credit</td>
</tr>
<tr>
<td style="width: 50%; padding: 1.25rem; border: 1px solid var(--sl-color-gray-5);">showHistory</td>
<td style="width: 50%; padding: 1.25rem; border: 1px solid var(--sl-color-gray-5);">true</td>
</tr>
<tr>
<td colspan="2" style="padding: 1.25rem; border: 1px solid var(--sl-color-gray-5); color: var(--sl-color-gray-3); font-style: italic;">Optional: in some blocks, a merged full-width row is where the visible page content goes when it does not fit in a small value cell. Not every block uses this row.</td>
</tr>
</tbody>
</table>

Read the table from top to bottom:

- The first row (full width, shaded) is the <Term term="Block name row">block name</Term> row. It is usually a single `kebab-case` name such as `commerce-cart` or `targeted-block`. The storefront uses that name to choose the right block implementation. In some editors, the <Term term="Block name row">name</Term> may appear in the first cell with the second cell left empty, but the rule is the same: one clear block identifier.
- Rows with two cells are <Term term="Key-value row">key-value</Term> settings: a property name in the first column and a value in the second. Many options are optional and use safe defaults if you leave them out. Each block's documentation lists the valid keys, allowed values, and which keys (if any) are required.
- A row with one cell spanning the full width is a <Term term="Merged full-width row">merged full-width row</Term> when the cell holds block content, not a second <Term term="Key-value row">key-value</Term> line. The italic row in the example shows that option. For some blocks you can point to another document with a <Term term="Fragment path">fragment path</Term> in settings instead of inlining the content; see the next section and [Personalization setup](/merchants/blocks/personalization/).

<Aside type="caution" title="Where is my block?">
If a block does not appear on the page when previewed, the most common problem is a <Term term="Block name row">block name</Term> that does not match the spelling in the block reference. If a block is wrong or empty, check the <Term term="Merged full-width row">full-width</Term> and <Term term="Fragment path">fragment</Term> content rules for that block in the reference, or use [Personalization setup](/merchants/blocks/personalization/) for `targeted-block`.
</Aside>

## What is a fragment?

In a `targeted-block` table, `fragment` refers to a <Term term="Fragment path">fragment path</Term>: a separate document path the storefront can load to supply the content for the block, instead of writing that content in the same table.

For `targeted-block` authoring, see [Personalization setup](/merchants/blocks/personalization/).

## Start authoring a block in your document

<Steps>

1. In Document Authoring, add a new table, set the <Term term="Block name row">name row</Term> to the block you want in `kebab-case`, and add the <Term term="Key-value row">key-value rows</Term> the block's documentation requires or recommends.

1. Preview the page, then publish when it looks right. For a full end-to-end example (metadata, cart block, section styling), work through [Your first page](/merchants/quick-start/your-first-page/).

</Steps>

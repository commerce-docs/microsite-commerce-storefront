Publish agreement documents and link them from the checkbox labels shoppers see at checkout. Work with your administrator and developer to confirm how your storefront defines its agreements before changing their configuration.

## Before you begin

- Obtain approved agreement text and the languages or store views that need it.
- Check that you can author and publish documents and update the storefront's placeholders sheet.
- Ask your developer whether the storefront uses its default agreement, custom agreements, or Admin-managed Commerce agreements, and which Admin settings apply.

<Aside type="note">
The default storefront defines a manually accepted agreement with the label key `Checkout.TermsAndConditions.label`. Adding agreement records in Admin does not automatically replace that code-defined agreement. Additional agreements or a different agreement source require developer configuration; see the [TermsAndConditions reference](/dropins/checkout/containers/terms-and-conditions/).
</Aside>

<Aside type="tip" title="TermsAndConditions configurable on a per store-view basis">
  For a storefront configured to use store-view-specific agreements, prepare the corresponding documents and labels for each language. Ask your developer to confirm that checkout uses the intended agreement source for each store view.

  Visit the [Multi-store setup](/setup/configuration/multistore-setup/) documentation for more information on how to build blocks and configure the storefront structure based on **Edge Delivery Services (EDS)**.
</Aside>

## How to enable and configure the Terms and Conditions

Confirm the applicable Admin configuration with your developer, publish the agreement documents, and update the labels for the agreement source your storefront uses.

<Tasks>

<Task>

### Enable the component

If your developer confirms that your checkout requires the Commerce Admin setting, ask an administrator to enable it as follows:

<Steps>

1. Log in to the Admin Panel.

1. On the Admin sidebar, go to **Stores** > _Settings_ > **Configuration**.

1. In the left panel, expand **Sales** and choose **Checkout**.

1. Expand the **Checkout Options** section.

1. Set **Enable Terms and Conditions** to "Yes".

1. Click **Save Config**.

</Steps>

See <Link href={"https://experienceleague.adobe.com/en/docs/commerce-admin/stores-sales/point-of-purchase/checkout/terms-and-conditions"} text={"Terms and conditions for checkout"} /> documentation for more information on how to enable the terms and conditions using the Admin Panel.

</Task>

<Task>

### Create the agreement document

For agreement labels that link to storefront documents, create the content in Document Authoring:

<Steps>

1. Create an agreement document at the intended path, such as `/terms-and-conditions` or a locale-specific path.
1. Add the approved agreement text and any required links.
1. Preview and publish the document.
1. Open its published URL and confirm that shoppers can read it without an authoring login. Keep this URL for the checkbox label.

</Steps>

</Task>

<Task>

### Configure the agreement checkbox label

Use the **EDS placeholders** or the **Admin Panel** instructions in the following tabs to configure the agreement checkbox label.

<Tabs>
  <TabItem label="Using EDS placeholders" default>
    For the default storefront agreement, update the **`placeholders`** sheet using the existing label key and the following information. For additional agreements, ask your developer which label keys their configuration uses.

    - An **_identifier_**:
      It's the reference that identifies the label translated
    - A **_label_**:
      The text displayed next to the checkbox comes from the storefront placeholders for the shopper's language. It accepts HTML links to your published agreement documents.

    Similarly, the merchant can configure the translation for the validation error that appears when the user clicks the `Place Order` button and an agreement is not checked, using the **"Checkout.TermsAndConditions.error"** identifier.

    Sample of **placeholders** sheet:
    ```txt
    "Checkout.TermsAndConditions.label", "I have read, understand, and accept the <a href='/en/privacy-policy' target='_blank'>Terms of Use, Terms of Sales, Privacy Policy, and Return Policy</a>."
    "Checkout.TermsAndConditions.error", "Please accept the Terms and Conditions to continue."
    ```

    Replace the example wording with approved text and the example link with the published URL of your agreement document. Follow [Change labels and placeholders](/how-tos/change-labels-and-placeholders/) to preview and publish the updated sheet.

    These labels are used to render the `TermsAndConditions` container in the **commerce-checkout.js** block file.

    Refer to the Adobe Commerce documentation for examples on how to use these labels.
  </TabItem>
  <TabItem label="Using the Admin Panel">
  Use this option only when your developer has configured checkout to use Admin-managed Commerce agreements. It does not automatically change the default code-defined agreement.

  The merchant has to configure the checkbox label for each agreement using the Admin Panel. As mentioned before, the Admin Panel allows merchants to create configurations per store-view level as follows:

  <Steps>

  1. Log in to the Admin Panel.

  1. On the Admin sidebar, go to **Stores** > _Settings_ > **Terms and Conditions**.

  1. In the upper-right corner, click the **Add New Condition** button.

  1. Enter the following **Terms and Conditions** information:
      - **`Condition Name`**
        The agreement identifier
      - **`Status`**
        Attribute to indicate if it's available or not:
        - 'Enabled'; the agreement will be retrieved by the GraphQL API query
        - 'Disabled'; the agreement won't be retrieved by the GraphQL API query
      - **`Applied`**
        Specifies how the checkbox should appear:
        - 'Manually': the user is required to manually check and accept the conditions to place an order
        - 'Automatically': the checkbox will appear checked by default, conditions are automatically accepted upon checkout
      - **`Store View`**
        Defines the scope at store view level for this agreement where you want these Terms and Conditions to be used
      - **`Checkbox Text`**
        It contains directly the text to show; it accepts HTML with links to a specific page in EDS

      <Aside type="note" title="Some attributes are not used">
        Although the following attributes are provided by the Admin Panel, they are not going to be utilized in the current solution because they will be handled in EDS. Merchants are able to work on their own solution if they want to use them:
        - **`Content`**
          As described above, the content for the agreements pages will be created **ONLY** using EDS
        - **`Show Content as`** (Text, HTML)
          Not really needed because EDS pages accept HTML code
        - **`Content Height (css)`**
      </Aside>

  1. Click **Save Condition**.

  </Steps>

      These entries are used to render the `TermsAndConditions` container in the **commerce-checkout.js** block file.

    Refer to the Adobe Commerce documentation for examples of this feature.

    See the <Link href={"https://experienceleague.adobe.com/en/docs/commerce-admin/stores-sales/point-of-purchase/checkout/terms-and-conditions"} text={"Terms and conditions for checkout"} /> documentation to learn how to configure the terms and conditions using the Admin Panel.
  </TabItem>
</Tabs>

<Aside type="note">
For storefront-authored agreement documents, the checkbox label must link to the relevant published document for the shopper's language or store view.
</Aside>

</Task>
</Tasks>

## Check the result

Preview checkout for each affected store view. Confirm that the intended agreement appears, its links open the published documents, and any required manual acceptance is enforced before an order can be placed. Use your team's test-order process rather than placing an unintended live order.

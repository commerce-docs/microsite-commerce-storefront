Add a recommendation unit to a storefront page using a `product-recommendations` block. The unit you choose determines which products are recommended and whether the block needs product context.

## Before you begin

Ask your administrator to confirm that Product Recommendations is available for your Commerce backend and that you can create or use a recommendation unit. Your storefront must already support the recommendations block. Follow [the authoring steps](#how-to-enable-and-configure-product-recommendations), using the configuration examples below.

- **recId**: Recommendation unit ID to render. One of `recId` or `referenceKey` must be set. Identifies which recommendation unit to fetch; ignored if `referenceKey` is also set.

- **referenceKey**: Label identifying the recommendation unit, passed to the drop-in as `label`. One of `recId` or `referenceKey` must be set. Takes precedence over `recId` when both are set.

- **currentsku**: Seed product SKU. Required on non-PDP pages for **anchor-based** recommendation unit types (for example, more-like-this, visual similarity, viewed-viewed, viewed-bought, bought-bought). On PDP pages, the boilerplate reads the seed SKU automatically from the Adobe Client Data Layer (ACDL).

- **currentprice**: Anchor product price (numeric). Required on non-PDP pages when the unit uses **dynamic or relative** price filter operators (Adobe Commerce Optimizer and Adobe Commerce as a Cloud Service only). Not required for static price filters—a fixed price range in the filter rule does not remove the need for a seed SKU on anchor-based types. On PDP pages, the boilerplate reads anchor price automatically from ACDL when needed.

### When product context is required

Whether a seed SKU or anchor price is required depends on the **recommendation unit type** and the **price filter operator**, not on each other:

| Unit type | Seed SKU | Anchor price |
| --- | --- | --- |
| **Anchor-based** (more-like-this, visual similarity, viewed-viewed, viewed-bought, bought-bought) | Required | Only for dynamic or relative price filter operators |
| **Context-free** (most-viewed, most-purchased, and similar popularity or behavioral types) | Not required | Not applicable |

A **static** price filter defines a fixed price range in the filter rule. It does not mean the unit can run without an anchor product. For example, a more-like-this unit with a static price filter returns no products when the seed SKU is missing, but returns results with the seed SKU alone—`currentprice` is not required.

### Storefront block configuration

How you configure the block depends on the page type and unit type:

- **PDP pages**: Set only `recId`. The boilerplate supplies the seed SKU from ACDL product context. On Adobe Commerce Optimizer and Adobe Commerce as a Cloud Service it also sends the ACDL anchor price automatically; the backend applies it only when the unit's filter uses a dynamic or relative operator.
- **Non-PDP pages (PLP, cart, home, and so on)**: There is no product context on these pages. For **anchor-based** unit types, you must set `currentsku` in block config. Add `currentprice` only when the unit uses dynamic or relative price filter operators (Adobe Commerce Optimizer and Adobe Commerce as a Cloud Service only).
- **Context-free unit types on any page**: Set only `recId`. These popularity and behavioral units do not use a seed product.

<Aside type="caution" title="Important">

  - You must set `recId` or `referenceKey`. If both are set, `referenceKey` takes precedence and `recId` is ignored.
  - **PDP pages** require only `recId` or `referenceKey` to be set.
  - **Other pages** require `currentSku`, plus either `recId` or `referenceKey`.

</Aside>

## How to enable and configure Product Recommendations

The Product Recommendations block can be configured on each page through Document Authoring. Follow the step-by-step guide below to enable and configure Product Recommendations:

<Tasks>

<Task>

### Create a recommendation unit

Create the recommendation unit in the Admin for your backend. Use the matching navigation below.

#### Catalog Views and Policies context

For Adobe Commerce as a Cloud Service with Merchandising Services, create a recommendation unit for the catalog view that supplies products to your storefront. Use <Link href="https://experienceleague.adobe.com/en/docs/commerce-admin/start/admin/admin-unified-experience" text="Commerce Admin in Adobe Unified Experience" /> for the instance provisioned with CCDM.

The **Merchandising** > **Recommendations** menu is available when Catalog Views and Policies is enabled and your Admin role has permission to use it. If you do not have the required permission, ask your administrator to complete this task.

<Steps>

1. In the Commerce Admin, go to **Merchandising** > **Recommendations**.
1. In **Catalog view**, select the catalog view for your storefront.
1. Follow <Link href="https://experienceleague.adobe.com/en/docs/commerce-admin/merchandising-with-ccdm/merchandising/recommendations/create" text="Create and manage recommendations" /> to create the recommendation unit.

</Steps>

The storefront connection must use the matching [Merchandising Services configuration](/setup/configuration/commerce-configuration/#catalog-views-and-policies-context).

#### Adobe Commerce Optimizer

Create a recommendation unit for the catalog view that supplies products to your storefront.

  <Steps>

    1. Log in to the Adobe Commerce Optimizer Admin.
    
    1. On the Admin sidebar, go to **Merchandising** > **Recommendations**.

    1. Follow <Link href="https://experienceleague.adobe.com/en/docs/commerce/optimizer/merchandising/recommendations/create" text="Create and manage recommendations" /> to create a recommendation unit.

  </Steps>

#### Storefront services context

For an Adobe Commerce environment using the Product Recommendations service, follow <Link href="https://experienceleague.adobe.com/en/docs/commerce/product-recommendations/admin/create" text="Create a recommendation" />. This uses a different configuration from Merchandising Services.
   
   </Task>
   <Task>

### Get the storefront reference key

After the unit is created, copy its storefront reference key. You will use this key to choose which recommendation unit appears on each storefront page.

For Adobe Commerce as a Cloud Service with Merchandising Services or Adobe Commerce Optimizer, the Recommendations workspace is under **Merchandising** > **Recommendations**.

<Steps>

1. Open the Recommendations workspace for your backend.

1. Open the recommendation unit's details.

1. Copy the storefront reference key.

</Steps>

For backend-specific details, see:

- <Link href="https://experienceleague.adobe.com/en/docs/commerce-admin/merchandising-with-ccdm/merchandising/recommendations/create#get-the-storefront-reference-key" text="Get the storefront reference key for Merchandising Services" />.
- <Link href="https://experienceleague.adobe.com/en/docs/commerce/optimizer/merchandising/recommendations/create#get-the-storefront-reference-key" text="Get the storefront reference key for Adobe Commerce Optimizer" />.
- <Link href="https://experienceleague.adobe.com/en/docs/commerce/product-recommendations/admin/create#get-the-storefront-reference-key" text="Get the storefront reference key for Product Recommendations" />.

You will use this reference key in the next step to configure the recommendations block.

</Task>

Preview the page and confirm that the selected recommendation unit appears. For a unit that needs a seed product, check the product context required by the examples above.

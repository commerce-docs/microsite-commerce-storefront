## Editing Permissions

Editing permissions control who can create and edit content in Document Authoring. These are configured through the DA permissions sheet, which uses a simple `read`, `write`, or `[ ]` (none) model to control access at the organization, group, or individual email level.

For setup instructions, see the <Link href="https://docs.da.live/administrators/guides/permissions" text="Permissions and Security Guide" /> on da.live.

## Preview and Publish Permissions

Preview and publish permissions control who can preview, publish, and delete content. These are managed through the AEM Permissions App, which provides a simple workflow for requesting and approving access. For advanced configuration using the Admin API, see <Link href="https://www.aem.live/docs/authentication-setup-authoring" text="Configuring Authentication for Authors" /> on aem.live.

#### Permission Roles

| Role | What You Can Do |
|------|-----------------|
| **Basic Author** | Preview content only. |
| **Basic Publish** | Preview and publish content. Includes basic author permissions. |

#### Requesting Access

When you try to preview or publish content without the required permissions:

1. If you see "Not Authorized," click the **Request Access** link in the notification message.
2. An administrator receives a notification to approve it.
3. Once approved, you can preview or publish content.

Watch the video above to see the complete workflow.

#### Troubleshooting

| Problem | Solution |
|---------|----------|
| "Not Authorized" when previewing | Request basic author access from the link in the error message. |
| "Not Authorized" when publishing | Request publish access from the link in the error message. Publish access includes basic author, so you only need one role. |
| Wrong organization | If you belong to multiple Adobe organizations, select the correct one in your profile menu. |

#### Approving Access Requests

When authors request preview or publish access through the AEM Permissions App:

1. Open the Permissions App to view pending requests.
2. Review the requested role (basic author or publish).
3. Click **Approve** to grant access. The app automatically updates the permissions configuration.
4. If a user already has basic author and requests publish, remove the basic author role since publish includes those permissions.

#### Manual Configuration

The AEM Permissions App handles most permission workflows automatically. For advanced configuration using the Admin API (such as bulk user management or scripted setups), see [Configuring Authentication for Authors](https://www.aem.live/docs/authentication-setup-authoring).

#### Related: Editing Permissions

This page covers preview and publish permissions only. To configure who can create and edit content in Document Authoring, see the [Permissions and Security Guide](https://docs.da.live/administrators/guides/permissions) on da.live.

#### Site Authentication

To protect your preview (`aem.page`) and live (`aem.live`) sites from unauthorized visitors, configure token-based site authentication. This restricts access to your entire site, requiring visitors to authenticate before viewing content.

Site authentication is useful for:

- **Intranet sites**: Restrict access to internal users only.
- **Staging environments**: Protect preview sites during development.
- **Gated content**: Require authentication for all site visitors.

For implementation details, including API configuration and CDN setup, see the [Configuring Site Authentication Guide](https://main--helix-website--adobe.aem.page/docs/authentication-setup-site).

Page metadata controls page-level settings like SEO, caching, social sharing, and structured data. When you create a page using document authoring, you can include a metadata table to configure how the page appears in search engines, social media, and browsers.

## What is page metadata?

Page metadata is a special table you add to your document that controls page-level properties. Unlike [section metadata](/merchants/storefront-builder/section-metadata/) which styles sections, page metadata affects the entire page's SEO, caching behavior, and social sharing appearance.

### Page vs. Section metadata

- **Page metadata** — Controls SEO, caching, and page structure (added to the `metadata` table)
- **Section metadata** — Controls section styling and visual presentation (added to the `Section Metadata` table)

Both can be used on the same page but serve different purposes.

## Complete list of page metadata options

### Standard page metadata

These properties control basic page settings, SEO, and caching:

| Metadata Property | Purpose | Example Values |
|-------------------|---------|----------------|
| `Title` | Page title (SEO and browser tab) | `Cart`, `Checkout`, `Product Name` |
| `Description` | Meta description for SEO | Product or page description (max 160 chars) |
| `Keywords` | SEO keywords (optional, legacy) | `shoes, running, athletic` |
| `Robots` | Search engine indexing directives | `noindex, nofollow`, `index, follow` |
| `Cache-Control` | HTTP caching behavior | `no-store`, `max-age=3600` |
| `Template` | Page layout template | `Columns`, `Addresses, Columns` |
| `Theme` | Visual theme variant | `dark`, `light`, custom theme name |

:::tip[SEO best practices]
- Keep titles under 60 characters
- Keep descriptions between 150-160 characters
- Use `noindex, nofollow` for checkout, cart, and account pages
- Use `no-store` for pages with sensitive or personalized content
:::

### Open Graph metadata

Open Graph properties control how your page appears when shared on social media platforms (Facebook, LinkedIn, etc.):

| Metadata Property | Purpose | Example Value |
|-------------------|---------|---------------|
| `og:type` | Content type | `product`, `website` |
| `og:title` | Social sharing title | Product or page name |
| `og:description` | Social sharing description | Product or page description |
| `og:url` | Canonical URL | `https://example.com/products/...` |
| `og:image` | Social sharing image | Full URL to product or page image |
| `og:image:secure_url` | HTTPS image URL | Full HTTPS URL to image |

:::note[Social sharing]
Open Graph tags are primarily used by Facebook, LinkedIn, and other social platforms. Twitter has its own set of meta tags (`twitter:card`, `twitter:title`, etc.) that can also be added using the same metadata table format.
:::

### Structured data

Structured data helps search engines understand your content and enables rich snippets in search results:

| Metadata Property | Purpose | Example Value |
|-------------------|---------|---------------|
| `json-ld` | Schema.org structured data | JSON-LD string for products, breadcrumbs, etc. |

**Common schema types:**
- `Product` — Product details, price, availability, reviews
- `BreadcrumbList` — Navigation breadcrumbs
- `Organization` — Business information
- `WebSite` — Site-level information

:::tip[Automated product metadata]
For product detail pages, use the [PDP metadata generator tool](https://github.com/hlxsites/aem-boilerplate-commerce/tree/main/tools/pdp-metadata) to automatically generate metadata including Open Graph tags and JSON-LD structured data from your product catalog.
:::

## How to use page metadata

<Steps>

1. **Create or open your document**

   Open the document in the Universal Editor or document authoring interface.

2. **Add the metadata table**

   At the top of your document (typically before any content blocks), add a new table with exactly two columns.

3. **Set the table header**

   In the first row, merge both cells and enter: `metadata`

4. **Add metadata properties**

   In subsequent rows, add your desired properties:
   - First column: Property name (e.g., `Title`)
   - Second column: Property value (e.g., `My Product Name`)

5. **Save and publish**

   Save your document. The metadata will be applied when the page is published.

</Steps>

## Best practices

### SEO optimization

- **Unique titles and descriptions** — Each page should have unique, descriptive metadata
- **Keyword placement** — Include primary keywords naturally in titles and descriptions
- **Length limits** — Keep titles under 60 characters, descriptions between 150-160 characters
- **Avoid duplication** — Don't duplicate content between Title and Description

### Caching strategy

- **Sensitive pages** — Use `Cache-Control: no-store` for cart, checkout, and account pages
- **Public pages** — Use `max-age` with appropriate duration for cacheable content
- **Dynamic content** — Consider page personalization when setting cache directives

### Social media

- **High-quality images** — Use images at least 1200x630 pixels for og:image
- **Test sharing** — Use Facebook's Sharing Debugger and Twitter Card Validator
- **Complete metadata** — Always provide og:title, og:description, and og:image together

### Indexing control

Use the `Robots` metadata to control search engine behavior:
- `index, follow` — Default; allow indexing and following links
- `noindex, follow` — Don't index this page, but follow links
- `noindex, nofollow` — Don't index or follow links (use for private pages)
- `none` — Equivalent to `noindex, nofollow`

## Developer reference

### Technical implementation

Page metadata is processed when the page loads and converted to HTML `<meta>` tags in the document `<head>`:

```html
<!-- Standard metadata -->
<title>Shopping Cart</title>
<meta name="description" content="View and manage items in your cart">
<meta name="robots" content="noindex, nofollow">

<!-- Open Graph metadata -->
<meta property="og:type" content="product">
<meta property="og:title" content="Premium Running Shoes">
<meta property="og:image" content="https://example.com/image.jpg">
```

### Metadata processing

The `getMetadata()` function in `scripts/aem.js` retrieves metadata values:

```javascript
function getMetadata(name, doc = document) {
  const attr = name && name.includes(':') ? 'property' : 'name';
  const meta = [...doc.head.querySelectorAll(`meta[${attr}="${name}"]`)]
    .map((m) => m.content)
    .join(', ');
  return meta || '';
}
```

### Template and theme

The `Template` and `Theme` metadata properties add CSS classes to the `<body>` element:

```javascript
const template = getMetadata('template');
if (template) addClasses(document.body, template);
const theme = getMetadata('theme');
if (theme) addClasses(document.body, theme);
```

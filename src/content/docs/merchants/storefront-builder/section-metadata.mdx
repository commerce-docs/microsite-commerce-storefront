Section metadata allows you to control the styling and layout of sections that contain your commerce blocks. When you add a commerce block to a page using document authoring, you can include a Section Metadata table to apply visual styling to the entire section.

## What is section metadata?

Section metadata is a special table you add to your document that controls how the section wrapping your content is styled. While block configuration controls the behavior of individual blocks, section metadata controls the visual presentation of the section container.

### Section vs. Block

- **Section** — The container that wraps one or more blocks on your page
- **Block** — The individual commerce functionality (cart, checkout, product details, etc.)
- **Section Metadata** — Styling applied to the section container
- **Block Configuration** — Settings specific to the block's functionality

## Complete list of section metadata options

Section metadata supports two types of properties: built-in Style classes and custom data attributes.

### Built-in section styles

The `Style` property applies predefined CSS classes from `styles/styles.css`:

| Style Value | CSS Class | Effect | Use Case |
|-------------|-----------|--------|----------|
| `light` | `.section.light` | Light gray background (`var(--color-neutral-100)`) with top/bottom padding | Highlight content sections with subtle differentiation |
| `highlight` | `.section.highlight` | Light gray background (`var(--color-neutral-100)`) with top/bottom padding | Emphasize important content or calls-to-action |

:::note[Customization]
The `light` and `highlight` styles are visually identical in the default boilerplate (background: `#fafafa`, padding: `40px 0`). Developers can customize these in `styles/styles.css` to create different visual effects.
:::

### Custom data attributes

Beyond the `Style` property, section metadata supports any custom key-value pairs. These are automatically converted to data attributes on the section element (kebab-case keys become camelCase data attributes):

```html
<!-- Section with custom metadata -->
<section class="section" data-backgroundColorblue" data-theme="dark">
  <!-- Your commerce block -->
</section>
```

**Common custom properties:**

| Property | Data Attribute | Purpose | Example Value |
|----------|----------------|---------|---------------|
| `Background-Color` | `data-backgroundColor` | Custom background color identifier | `light-blue`, `brand-primary` |
| `Theme` | `data-theme` | Theme variant | `dark`, `light`, `branded` |
| `Analytics-Section` | `data-analyticsSection` | Section identifier for analytics | `hero`, `featured-products` |
| `Content-Type` | `data-contentType` | Content classification | `promotional`, `informational` |

:::tip[Naming convention]
Use kebab-case in your metadata table (`Background-Color`). The system converts it to camelCase for data attributes (`data-backgroundColor`).
:::

## How to use section metadata

<Steps>

1. **Create or open your document**

   Open the document containing your commerce block in the Universal Editor or document authoring interface.

2. **Add the Section Metadata table**

   Below your commerce block, add a new table with exactly two columns.

3. **Set the table header**

   In the first row, merge both cells and enter: `Section Metadata`

4. **Add style properties**

   In subsequent rows, add your desired properties:
   - First column: Property name (e.g., `Style`)
   - Second column: Property value (e.g., `highlight`)

5. **Save and publish**

   Save your document. The section metadata will be applied when the page loads.

</Steps>

## Best practices

### Use section metadata sparingly

Section metadata is best used for:
- Highlighting key content sections
- Creating visual separation between page areas
- Adding custom styling hooks for developers

Avoid overusing section styles, as too many styled sections can make pages visually cluttered.

### Consistent naming

When using custom properties:
- Use lowercase with hyphens (kebab-case): `custom-theme`, not `customTheme`
- Choose descriptive names: `promotion-banner`, not `promo`
- Document custom properties in your project's style guide

### Test across devices

Always preview your pages on different screen sizes to ensure section styling works well on mobile, tablet, and desktop.

## Developer reference

### Technical implementation

Section metadata is processed by the `decorateSections` function in `scripts/aem.js`:

```javascript
// Process section metadata
const sectionMeta = section.querySelector('div.section-metadata');
if (sectionMeta) {
  const meta = readBlockConfig(sectionMeta);
  Object.keys(meta).forEach((key) => {
    if (key === 'style') {
      const styles = meta.style
        .split(',')
        .filter((style) => style)
        .map((style) => toClassName(style.trim()));
      styles.forEach((style) => section.classList.add(style));
    } else {
      section.dataset[toCamelCase(key)] = meta[key];
    }
  });
  sectionMeta.parentNode.remove();
}
```

### Adding custom section styles

To add custom section styles, update `styles/styles.css`:

```css
/* Custom section style example */
main .section.branded {
  background: linear-gradient(135deg, #667eea 0%, #764ba2 100%);
  color: white;
  padding: var(--spacing-xxbig) 0;
}

main .section.compact {
  padding: var(--spacing-small) 0;
}
```

## Page vs. Section metadata

Section metadata and page metadata serve different purposes:

- **Section metadata** — Controls section styling and custom data attributes (covered on this page)
- **Page metadata** — Controls SEO, caching, social sharing, and page structure

For complete information about page-level metadata including SEO, Open Graph, and structured data options, see the [Page metadata guide](/merchants/storefront-builder/page-metadata/).

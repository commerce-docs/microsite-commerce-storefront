A <Term>block table</Term> in your document is how you add any <Term>Commerce block</Term> or <Term>Content block</Term> to a page. You create it in Document Authoring as a simple table: the block name goes in the first row, and settings go in the rows below it.

## Example: a block table in your document

This example uses the `commerce-cart` block and includes all three row types.

<table style="width: 100%; min-width: 470px; max-width: 100%; table-layout: fixed; border-collapse: collapse;">
<tbody>
<tr>
<td colspan="2" style="text-align: center; padding: 0.4rem 0.75rem; border: 1px solid var(--sl-color-gray-5); background-color: var(--sl-color-gray-6); font-weight: 600;">commerce-cart</td>
</tr>
<tr>
<td style="width: 50%; padding: 0.4rem 0.75rem; border: 1px solid var(--sl-color-gray-5);">Enable Item Quantity Update</td>
<td style="width: 50%; padding: 0.4rem 0.75rem; border: 1px solid var(--sl-color-gray-5);">true</td>
</tr>
<tr>
<td style="width: 50%; padding: 0.4rem 0.75rem; border: 1px solid var(--sl-color-gray-5);">Hide Heading</td>
<td style="width: 50%; padding: 0.4rem 0.75rem; border: 1px solid var(--sl-color-gray-5);">false</td>
</tr>
<tr>
<td style="width: 50%; padding: 0.4rem 0.75rem; border: 1px solid var(--sl-color-gray-5);">Checkout URL</td>
<td style="width: 50%; padding: 0.4rem 0.75rem; border: 1px solid var(--sl-color-gray-5);">/checkout</td>
</tr>
<tr>
<td colspan="2" style="padding: 0.4rem 0.75rem; border: 1px solid var(--sl-color-gray-5); color: var(--sl-color-gray-3); font-style: italic;">Optional: in some blocks, a merged full-width row is where the visible page content goes when it does not fit in a small value cell. Not every block uses this row.</td>
</tr>
</tbody>
</table>

Read the table from top to bottom:

- The first row (full width, shaded) is the <Term term="Block name row">block name</Term> row. It contains a single `kebab-case` name such as `commerce-cart`. The storefront uses this name to find and load the right block.
- Rows with two cells are <Term term="Key-value row">key-value</Term> settings: a setting name in the left column and its value in the right. Most settings are optional and fall back to safe defaults. Each block's [reference page](/merchants/blocks/) lists the available keys and which are required.
- A row with one cell spanning the full width is a <Term term="Merged full-width row">merged full-width row</Term>. Some blocks use it to hold page content that doesn't fit in a setting value. The italic row in the example shows this option.

<Aside type="caution" title="Where is my block?">
If a block does not appear on the page when previewed, the most common cause is a block name that does not match the spelling on that block's [reference page](/merchants/blocks/). If the block appears but looks wrong or empty, check the content rules on that block's [reference page](/merchants/blocks/), or use [Personalization setup](/merchants/content-customizations/personalization/) for `targeted-block`.
</Aside>

## Add a block to your document

To add any Commerce block to a page, create a block table in Document Authoring (the web-based editor where you create and update storefront pages).

<Steps>

1. Add a new table to the page.

1. Set the first row to the block name in `kebab-case`, for example, `commerce-cart`.

1. Add the key-value rows that the block's [reference page](/merchants/blocks/) requires or recommends.

1. Preview the page. The block should appear in the section where you placed the table.

1. Publish when the page looks right.

</Steps>

</TaskSection>

For an end-to-end example that covers metadata, a commerce block, and section styling, work through [Create your first commerce page](/merchants/quick-start/your-first-page/).

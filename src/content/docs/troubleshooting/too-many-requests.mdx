A `429` error means Edge Delivery Services throttled your storefront for sending too many requests too fast. This page helps you find the cause and fix it.

## Status code 429

### If you see this

You see repeated `429` status codes in your browser's network tab, or a PageSpeed Insights or Lighthouse audit flags an unusually high number of requests on page load.

### Why this happens

Edge Delivery Services caps requests from one visitor to 200 per second for each `aem.page` or `aem.live` host name. See [Delivery rate limits](/setup/seo/platform-limits/#delivery-rate-limits). Custom code that fetches more than shoppers need, before they ask for it, pushes a storefront toward that cap.

The most common cause is hidden UI, such as a Mini Cart panel or drop-in container, that fetches its scripts, fragments, or styles on every page load instead of on the interaction that reveals it.

Other causes include:

- Local-development-only scripts that ship to production without a hostname guard
- Many small utility or component files loaded as separate requests instead of a shared module

### What to do

<Steps>

1. Open your browser's network tab, or run a Lighthouse audit, and count the requests in the first second of page load.

   Lighthouse lists them under its Network requests diagnostic. For how to run the audit, see [Run Lighthouse audits](/get-started/performance/#run-lighthouse-audits).

1. Find hidden UI, such as a Mini Cart panel, that fetches its scripts, fragments, or styles on every page load, and move that fetch to the interaction that reveals it, such as a click or tap.

   For more information, see [Load hidden UI on demand](/get-started/performance/#load-hidden-ui-on-demand).

1. Guard local-development-only scripts behind a hostname check so they never ship to production.

1. Consolidate small utility files into a shared module instead of sending one request per file.

1. Re-run the audit to confirm the request count dropped.

</Steps>

For load-order and LCP guidance beyond request count, see [How can I improve the performance of my catalog pages?](/troubleshooting/faq/#how-can-i-improve-the-performance-of-my-catalog-pages) in the FAQ.
